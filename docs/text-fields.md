# Text Fields

## Scope and Interaction

Text is a normal content-band element, not note content or a separate drawing layer. The Text tool creates a rectangular field. A short click or tap on an already singly selected field opens its source editor for mouse, touch, and pen, including after Lasso selection. A double-click also opens that selected field and retains the same editor. Without selection, the first click selects the field and a double-click selects and opens it. During entry initiated by a pointer, another primary contact inside the same field belongs to that pending entry; it must not close or restart the editor. Once ready, ordinary editor clicks retain native caret and word-selection behavior. Existing first-click selection stays unchanged, with no delay to await a possible double-click. Dragging moves the field, handles retain resize and rotation ownership, and long press, pinch, cancellation, modifier selection, and pen eraser buttons do not activate source editing. Enter or the adaptive context menu's **Edit text** (**Text bearbeiten**) action also opens a selected field. Shift+Enter enters keyboard geometry editing for a text selection, and Escape finishes source editing. These fixed bindings follow [Keyboard Shortcuts](keyboard-shortcuts.md#canvas-object-navigation-and-geometry-editing). Selection, movement, rotation, arrangement, duplicate, clipboard, undo, and redo use the existing element pipelines. The field exposes the eight rectangular connection anchors. Lasso and rectangular selection use its rectangle; erasing an intersected field removes the whole element.

An unfilled new field is provisional. Leaving it through Escape, an outside action, locking, or export discards it without an empty element or creation-history entry; existing redo remains available. Whitespace and formatting controls alone do not accept a new field. Actual user text, including deliberately typed Markdown or LaTeX delimiters, does. Editing an existing field does not apply this creation-only discard policy.

Pointer entry places the caret at the source end and requests visibility through the native scroll owner. Subsequent clicks position the caret normally. The purple selection outline and resize handles remain visible during source editing; selection traces remain hidden. Shared inner padding separates the native caret from the frame. Resize handles remain usable, and completing or cancelling a resize restores the retained text selection and input focus. While revealed source is taller than the prepared text, the selection outline and handle hit targets use the same temporary height as the editing surface and background, including rotated fields and camera changes. Returning to rendered content restores the prepared height. Geometry gestures keep the same native editor, caret, revealed Markdown, and empty tail lines visible while the existing handle pipeline owns the pointer. Published resize geometry updates the live editor without committing intermediate text changes, and its temporary source frame follows the reflowed editor height. Handle hover uses the same rotation-aware resize cursor as the canvas and returns to the text caret away from handles. Source reveal never changes stored geometry or history. Closing restores the normal selection presentation. The text retains its prepared position, font face, and baseline.

Inside the padded content rectangle of a single selected field, handle hits use a 6 CSS-pixel radius around the visible grips. The existing expanded targets remain available outside the content. The same visible-grip limit applies to owned source-editor content, including revealed source beyond the saved rectangle. This keeps text taps and text selection usable in small phone fields while preserving actual grip interaction.

Text fields use equal padding on all four sides: one base font size with a minimum of 28 document units, capped at one quarter of the outer field width and rounded to canonical geometry precision. Width and height describe the outer rectangle; wrapping and alignment use its inner width, and field height includes both vertical insets. The prepared layout stores its padding so SVG, math, backgrounds, and the native editor share the same coordinates. Source-only reflow retains stored and proportionally scaled padding; explicit font-size changes recompute it, and width changes cap it at one quarter of the new outer width. Existing layouts with missing or smaller padding remain valid. The padding upgrade on entering editing expands only the outer rectangle without moving glyphs, changing wrapping, or replacing its font resources. Existing larger insets remain intact. Missing table-following gaps are repaired through the normal layout pipeline before source editing, moving following blocks down to reserve the rail. These one-time geometry changes use normal undo history; history replay preserves its recorded layout instead of reapplying the upgrade.

Dragging a horizontal side handle changes width and recomputes line wrapping without changing font size, including while Shift is held. Corner resizing scales the field and its font sizes uniformly. A multi-selection containing text always scales uniformly, including side-handle gestures; uniform text scaling keeps the smallest base or explicit range font size at least 0.001 page units. Side-width reflow retains one running operation and the latest requested width. Retargeting lets admitted work finish without publishing an obsolete width; returning to the initial width or disposing the gesture cancels it immediately. Automatic height changes on rotated fields preserve the world-space top-left origin: the shared domain reflow helper compensates `x` and `y` while retaining a centered pivot and the field rotation. Side-width reflow uses the same helper. Geometry, anchors, connected endpoints, and undo remain committed through the existing validated command boundary.

Single-text resize outlines and their six scale handles use the same displayed preview frame as the scene, including the frame used when acquiring a grip. Corner dragging reflows at the requested font size through the existing preparation port and stabilizes the opposite gesture anchor. Its reflow draft scales styles, ranges, geometry, and stored padding while retaining font bindings; it does not transform old glyphs, formula paths, or table rows that native layout replaces. Every pointer frame applies a uniform residual transform to the last complete native layout, including the retained source editor, formulas, table, and backgrounds. The scene rebases this feedback against the actually displayed element while a replacement SVG is still staged. The outline and connected endpoints use the same feedback basis. Native source height retains its associated element basis, so revealed source remains enclosed without another height read per residual frame. Floating table controls are hidden and inert during the gesture, then resume after fresh placement. The queue retains one running operation and only the latest request; obsolete results cannot replace the current complete layout. A ready result is reused at commit, avoiding a different final layout on release. Native line metrics are measured at that size rather than assuming that browser baseline rounding scales linearly. Geometry preparation stages the matching native Markdown decorations and visible formula and table paint before adoption. Existing widgets retain their complete paint until their replacements are ready. Native text, rendered widgets, field bounds, and measured backgrounds publish through the same geometry update. Pure geometry changes preserve the native source document and selection, including normalized CRLF input. Returning a side handle to its starting width reuses the original prepared layout immediately and cancels obsolete reflow.

Native line measurement batches the actually used font variants, including retained font-resource boundaries, before shaping. Probe writes precede native rectangle reads; the shared scheduler admits both phases, and cancellation releases temporary probes. Formula geometry that naturally fits a changed width reuses the existing bounded cache at the same font size, display mode, and mathematical weight. Narrower containers still use width-aware formula layout; absolute LaTeX dimensions are never approximated by scaling a different font size.

When typing, pasting, formatting, or width reflow increases a field's bottom, the embed grows through the existing automatic downward page-expansion policy, including repeated growth during the same editing session. Committed text geometry remains part of the page extent after editing finishes and when saving, locking, or exporting. Temporary source-reveal height follows the separate lifecycle below; Obsidian remains the sole vertical scroll owner. Native scroll callbacks request a public CodeMirror measurement rather than reading layout during editor updates. That measurement captures the caret's page bounds before height publication or source-extent changes can move its clipped input window; the write phase updates the extent and reveals those captured bounds. A single native caret-reveal intent retains its source document and selection across successive corrections to estimated long-source height. Each intent tracks its own measured and pending height, independently of height publication. A changed native height can renew measurement; unchanged viewport updates perform no caret reads. When the actual host block size changes, the existing host CodeMirror layout-reconciliation barrier resumes the retained page reveal after the native scroll range becomes available. This continuation reuses captured page bounds without another caret or source-height read. Pointer, wheel, keyboard, source or selection changes, geometry suspension, and disposal cancel stale intent.

## Source, Formatting, and Mathematics

Unmodified arrow keys enter rendered tables from the surrounding text and leave the first or last cell for the immediately adjacent outer line, preserving blank lines. Right enters the first cell at its start; Left enters the last cell at its end. Up and Down choose the boundary row's column from the caret's horizontal position. Horizontal cell transitions place the caret at the corresponding start or end. Arrow keys never append rows; Tab and Enter retain their explicit row-insertion behavior. Ordinary movement within text and wrapped cells uses the native CodeMirror cursor APIs. Explicit table-source mode remains normal source editing.

An outer-editor text selection that intersects a table reveals its Markdown source, like a selected formula. Mouse dragging, Shift-selection, and Select All preserve the exact source range for native copy, cut, replacement, and formatting. Shift-clicking a rendered cell extends the outer selection to that cell. Collapsing the selection restores the table unless its source was opened explicitly. Selecting or formatting text within the active cell keeps that cell editor and the rendered table; preview and viewport refreshes preserve this distinction.

Each field retains multiline Markdown source. Its lifecycle-owned CodeMirror editor presents an Obsidian-style Live Preview: formatted content stays readable, while moving the caret into a Markdown construct reveals its delimiters; entering a formula reveals its LaTeX source. The supported parser covers paragraphs, headings, ordered and unordered lists, pipe tables, emphasis, strong emphasis, strikethrough, inline code, inline math, and display math. This is a bounded field parser, not the complete Obsidian note renderer or a plugin execution surface.

The active source editor and its cell editor share one sandboxed input document inside the retained field's runtime `foreignObject`. Its frame follows the field rotation and camera, while CodeMirror measures unrotated local coordinates. The frame covers only the visible clip; its fixed, clipped body cannot become another programmatic scroll owner. The source container is translated by the clip offset, retaining native windowing. Normal focused source commits reveal the caret again after adopting their matching geometry; previews and active handle leases do not trigger this reveal. The existing canonical font stylesheet, portable palette, and scoped host tokens are relayed to this document. Required native font faces are ready before editor reveal and geometry adoption. Caret bounds, handle input, and floating table controls use the owned input-to-drawing coordinate bridge; controls remain outside the clipped input document. The table hover corridor uses measured bounds across both documents and owns listeners only while active. Disposal removes this document and its registered assets and listeners. Static SVG and PDF contain neither runtime frame nor input DOM.

Pipe tables have a header and a matching separator row, with at least three dashes per column. `:---`, `:---:`, and `---:` select left, center, and right column alignment. Optional outer pipes, escaped pipes, and pipes inside inline code are supported. Missing body cells remain empty; extra cells retain their source but are not painted. Invalid table syntax stays ordinary text. Header cells start bold, subject to explicit formatting overrides; cells support inline Markdown and LaTeX.

Tables fill the field's available inner width. Columns share that width equally, cell contents wrap within their padded column, and each row takes the height of its tallest cell. Resizing reflows cells without changing the font size; resulting height growth uses the normal field and embed extent pipeline. The rendered table stays visible during cell editing. One nested CodeMirror view owns the active cell; the outer field source, formatting ranges, and history remain authoritative. As in other text, entering a Markdown construct or formula in that cell reveals its source. The active row can temporarily grow to fit revealed source, shifting the grid and following rows without changing the saved layout merely for source reveal.

Tab and Shift+Tab navigate cells; existing cell targets accept the next native input immediately through composed source-position mapping, without waiting for asynchronous parsing or layout. A missing source cell is materialized through the same canonical transaction boundary; resolving its affected row is one atomic native-input step bounded by the field source limit, cached once per current text identity. Ordinary rows require no additional parse during navigation. Tab from the last cell appends a row and focuses its first cell. Enter moves down in the same column, and arrow keys at cell edges navigate to adjacent cells. Escape leaves the active cell rendered; a second Escape finishes field editing. Continuous 16-pixel visual plus rails below and to the right append a row and column, with pointer targets of at least 28 pixels. The rails have thin foreground outlines and transparent interiors; the ellipsis has neither a border nor a background. Visible rails remain inside the field padding, shrinking at small zoom levels when necessary. Their transparent hit extensions must not intercept following text. Visible field resize grips take precedence over overlapping transparent table-control targets; a colliding plus glyph moves along its rail so both actions remain separately reachable. A shared gap after a table separates a following block in the prepared graphic and live editor. The 28-pixel ellipsis control floats above the table, aligned to its right edge. Their lifecycle-owned action layer floats in drawing-document viewport coordinates outside SVG transforms, remains viewport-clamped, and belongs to the active text session's pointer boundary. The owned table menu identifies its target using one-based row and column numbers, inserts or deletes rows and columns, sets left, center, or right column alignment, and opens the complete table source inline; a return control restores the rendered table. The return action uses the host accent on a native UI surface with foreground-adjusted contrast, an icon matching its `0.8em` label, and `0.4em` spacing before the source. The spacing belongs to the measured block rather than an external widget margin. Hovering or keyboard-focusing a menu action highlights its targeted row or column, shows the insertion edge for insertions, and uses warning feedback for deletion. This runtime overlay is never saved. A newly typed table remains source until the caret leaves it, while a valid pasted table can preview immediately. Literal pipes entered in a cell are escaped outside inline code. CR and LF pasted into one cell become spaces; normal Enter navigates rather than adding a line break.

The outer editor retains replacement blocks against the coarse native CodeMirror viewport, because fine `visibleRanges` omit their hidden source. Inline decoration queries still use those fine ranges. Large table previews retain their full extent while mounting visible rows, overscan, headers, and the focused cell. Parsing and layout still prepare the complete field; viewport windowing does not bound all table work to visible rows. Obsolete preparation is cancellable and only the latest complete result is published. Saved SVG and native Obsidian PDF use the prepared cell geometry and grid as fully rendered static content without runtime controls.

Leading spaces remain visible in both the prepared graphic and the source editor. Explicit line breaks and soft wrapping preserve spaces with the editor's `break-spaces` behavior; tabs use shared four-space tab stops. Source bytes remain unchanged. Opening an older field whose prepared layout discarded spaces or tab stops repairs that field through the existing preparation and undo history. History replay preserves the recorded layout rather than repeating the repair.

Text formatting combines a base style with source-range overrides for family, size, color, opacity, bold, italic, underline, strikethrough, background color, and background opacity. Range offsets refer to the retained UTF-16 source. Source edits remap formatting offsets. Outside source editing, a selected field receives whole-field changes, replacing overrides for the changed property. During source editing, controls report the current caret or selected text and apply only to that scope; a collapsed caret changes subsequent typing. Selecting all source applies to every selected character. Mixed values remain indeterminate, with no active accent on mixed formatting buttons. Committing a source style restores the retained text selection and input focus; dragging a slider keeps its pointer ownership until release.

While source editing is active, Style remains open after committed changes, focus returns, and continued typing. The inspector keeps reflecting the current caret or text selection. An explicit outside pointer, including a click in the owned source document, dismisses it; trigger toggling, Escape, and native Back retain their explicit dismissal paths. Only this text inspector permits focus in its exact owned editor outside the panel and uses nonmodal accessibility semantics. Other panels and tools retain their existing focus containment and dismissal behavior. Closing a font list dismisses only that list, and slider drag ownership lasts through release before returning input focus. Enter commits numeric fields through their existing blur/change path; uncommitted composition is not intercepted. Font-size inputs are canonicalized before source-range formatting reaches the document command boundary.

On phones, caret reveal respects the measured top edge of the open Style sheet and the current viewport, including keyboard resizing. The existing native scroll owner and source-extent lease supply only missing scroll space. Closing the inspector releases its temporary reserve while preserving any space required by revealed source. This presentation reserve does not change the saved document extent.

Alignment targets the current explicit source paragraph or all paragraphs intersecting the selected range. An explicit newline starts an independently alignable paragraph; automatic wrapping stays within its original paragraph. A range ending at the next paragraph's start excludes that paragraph. Markdown spans and mathematical blocks retain their existing grouping and vertical rhythm.

Background color and opacity are independent of foreground paint. Outside editing they control the field rectangle; source selections and pending typing use inline backgrounds, including a full-source selection. Base background paint is excluded beneath explicit inline overrides, which are painted once at their own opacity; a transparent override exposes the paper. The live editor measures its visible background ranges in its own layout, including revealed source and rotated fields. Its lifecycle-owned SVG luminance mask excludes their union from the base paint, publishing the mask, inline groups, and outer geometry together without a deferred rectangle partition. The static scene, portable SVG and PDF join the partition's directed boundaries into continuous contours, removing shared internal edges before rasterization. The shared background palettes include Transparent and omit Gray, while foreground and outline palettes retain Gray; previously stored Gray fills remain valid.

The corner radius follows the shared text-padding rule, capped at half the field height. Base paint and inline overrides share that outer contour, retaining their existing disjoint alpha partitioning. Inline backgrounds keep their internal rectangular edges. Editor, SVG, and native PDF use the same contour. Exact earlier square, fixed two-unit and strip-partitioned background variants remain readable and are canonicalized on the next save; arbitrary geometry and mixtures of different variants remain invalid.

Math uses documented Obsidian `loadMathJax`, `renderMath`, and `finishRenderMath` APIs when a usable native SVG result is available. The portable fallback uses the locally bundled MathJax engine and offline New Computer Modern glyph data. Width-constrained formulas go directly to portable automatic line breaking and fitting; they do not run a native host probe whose unconstrained result cannot be used. Valid formulas retain normalized SVG paths, without an external renderer, remote font, or executable HTML. Display formulas use the same paragraph alignment in the static graphic and live source preview. Recognized TeX grammar failures display the original `$` or `$$` source, including its delimiters, as local face-bound monospace text in layout and editor preview; the source remains editable and saveable. Cancellation, resource-limit, security, and normalization failures remain hard preparation failures and must not publish partial content. Formula source highlighting uses public host tokens: commands and `^`, `_`, `&` use `--code-tag`, words use `--code-property`, numbers use `--code-value`, braces use `--code-punctuation`, and dollar delimiters use `--text-accent`. The existing math cache is bounded by 2,000,000 path characters, `100000 + 16384 * 64` key characters, and 16,384 combined path/expression items; unchanged formulas reuse retained conversions during plain-text edits.

Formulas inherit the effective text size and bold state, including heading scales and explicit range overrides. Bold uses mathematical glyph variants rather than an SVG stroke or CSS weight; stored LaTeX source stays unchanged. Native previews bind their actual font resource, and display blocks retain the block font's line box even when their only visible content is an SVG. Formula range sizes do not replace that block strut. Width-constrained inline and display formulas use the portable operator line breaker before proportional fitting of indivisible groups. Inline formulas retain their original math style, glyph size, complete geometry, and first-line baseline during breaking. A matrix or other group without usable breakpoints may still require proportional fitting to remain inside the field. The formula cache distinguishes effective bold state and available width; editor preview, saved SVG, and native PDF share the prepared paths.

Opening source editing prepares native font metrics for math-bearing lines through the central scheduler. Matching retained formula dimensions and baselines can compensate for differences between saved and current native font metrics without rewriting source or stored layout. The cached adjustment uses the full line's text and mathematical ascent; source, style, or layout changes invalidate it. Decoration updates reuse this prepared result without native measurement reads.

## Fonts and Settings

The bundled families are Inter, Source Serif 4, Caveat, and JetBrains Mono. They load locally. Text defaults use Inter at 24 page units, Theme text at opacity 1, no emphasis or decoration, transparent background with background opacity 1, and left alignment. Vault defaults apply to new fields; existing elements retain their own styles.

Style and tool defaults share the font-family dropdown and keyboard selection contract in [Settings](settings.md#settings-ui). The font-family trigger fills the available control width in the Style panel. Visible options preview their own font through temporary leases, independently of embedded document resources; closing the dropdown releases those previews without changing the retained text selection.

The Style panel and text-tool default settings place the font-family dropdown above the font-size slider, followed by a single row of four icon buttons for bold, italic, underline, and strikethrough. Each formatting button toggles independently and uses the existing alignment-choice appearance, including its accent border when active. Localized accessible names and tooltips identify the icons; a mixed selection exposes `aria-pressed="mixed"`, and its first activation applies the format to the complete selection.

The font-size slider and number entry cover 1 through 100 with continuous values. Corner resizing may produce valid sizes outside that UI range; opening controls, moving focus, or changing another style never clamps those stored values. The numeric field retains their exact value while the slider thumb stays at its nearest endpoint. For selected text fields, slider input prepares live text, wrapping, page extent, and selection-frame previews without mutating the Store. One running preparation retains only the latest pending value. Release commits the prepared result as one undo step; cancellation restores the previous presentation and page-height hysteresis. The renderer publishes text and its selection geometry coherently through the existing bounded scene pipeline.

The Text toolbar control previews effective bold, italic, strikethrough, and underline states. Its glyph and decorations inherit the same toolbar foreground and active-tool accent as the other tool icons. It has no separate foreground-color preview or field-background swatch. The Style trigger retains its Palette glyph; text foreground, field-background color, and background opacity update its paint through the shared palette rules. Active source editing uses the selected range or caret, including pending typing styles; selected text fields use their common effective formatting, and new fields use Text-tool defaults. Mixed formatting flags are neutral. These decorative, fixed-size icons preserve the button, keyboard focus, and toolbar layout; the existing local paint transition respects reduced motion.

The font picker in Style and Text-tool defaults provides a separated, full-width **Add font** row with a small plus icon and visible localized text. The complete row is clickable and shares the font options' hover and keyboard-focus treatment, without a separate circular button background. It opens the same plugin-owned library dialog using the shared native desktop/tablet shell or phone bottom sheet. The initial library page shows up to eight faces with preview and non-destructive Delete actions. It has no post-import reassignment control. A preview opens inline beneath its own face, aligned with the row text and using the normal UI text size. Its disclosure button exposes expanded state and a named panel; the shared Settings panel motion animates height without scaling the sample. Closing retains the font through the collapse, releases it after the panel is hidden, and then admits only the latest requested preview. At most one preview font and panel are retained; pagination, import, dialog teardown, and errors release that ownership. Reduced motion settles immediately. Its empty-state row offers a right-aligned Add font icon that opens the same guided import. Import starts a three-step guided flow. Step 1 offers a centered, padded upload card for choosing or dropping one or more font files and explains accepted formats and limits. Pointer, keyboard, and file drops enter the same bounded preparation and review flow; no file is committed merely by dropping it. Wizard navigation uses equally padded whole-button actions, with the Back icon before its label and the Next or confirmation icon after it. Step 2 lets the user edit the detected family name, choose an optional existing family, and preview a selected face. Step 3 reviews the batch before the explicit confirmation. Returning between steps preserves the draft; leaving or closing releases staged previews. Library actions use localized icon buttons; wizard navigation pairs icons with concise labels. Both retain accessible names, shared feedback, and 44-pixel targets. Dismissal follows the shared native header, sheet gestures, and keyboard contracts without a separate closing footer. Status and failures are announced; successful import uses the existing finite import-completion illustration and respects reduced motion. Closing restores focus to the picker and releases preview, feedback, and animation ownership.

An empty library offers Add font only in its empty-state card. The separate Add font row appears once the library contains a face.

Library, family-editor, and import-step changes animate the dialog's intrinsic height through the shared [Animation Contract](quality-and-testing.md#animation-contract). The complete content replacement participates in the transition, including asynchronous preview publication, while the native scrolling and phone-sheet boundaries remain in effect.

Imported families show their exact user-assigned names in font selections and tooltips. Stable family and resource IDs remain internal; equal display names do not merge independent families.

Each imported face offers an icon-only Edit action. The family editor renames all of its faces in one metadata write without changing resource identity or binaries. Its Add font styles action opens the existing import review with that family fixed as the target, including after clearing and replacing the selected files. Returning from that review restores the family editor. Library removal retains its confirmation and uses the shared destructive action color.

The import review separates its font sample from surrounding controls with a themed background, rounded border, and inner padding. The sample retains the selected face and wraps within the available width.

The guided font library import accepts TTF, OTF, WOFF, and WOFF2 files. Each file is limited to 8 MiB; a draft can stage at most 128 faces and 32 MiB of owned binary plus portable Base64 data, accounting for Base64's UTF-16 storage. Before confirmation, selection validates the container, extracts metadata, computes the content hash, and requires native `FontFace.load()` admission in the owning window. Staged bytes and metadata are retained for preview and reused by the commit, without hashing or validating again. The name is prefilled from the detected family and can be edited to 1–128 characters. Recognized face styles and weights are presented with friendly Normal, Bold, Italic, and variable variants. One selected face is loaded for native preview at a time. Importing into an existing family requires an explicit choice; equal names do not merge families, duplicate content IDs deduplicate, and overlapping face style/weight combinations are rejected.

No vault write occurs before the final confirmation. Commit rechecks the live library index, conflicts, and capacity, then writes metadata as one batch while keeping existing document font bindings unchanged. A failed commit keeps the draft available for retry; cancellation releases staged previews and bytes. If cancellation or failure occurs after binary I/O begins, a content-addressed source file may remain without a corresponding metadata entry; existing library metadata remains unchanged. WOFF2 uses the locally bundled Brotli WebAssembly decoder with explicit byte initialization, bounded streaming output, and no network or eval dependency. Imported files live under `Inkbook Fonts/<content-hash>.<extension>`; settings retain the library index rather than binary data. Remove deletes the index entry only, preserving the source file and font data already embedded in documents. The legacy manual face override remains available internally; the user-facing import flow derives face descriptors from metadata. Custom families and Caveat follow native CSS style/weight matching, including a Medium face or synthetic bold/italic when the requested face is absent, while preserving the actual embedded face descriptors and bytes.

Exports retain the exact `layout.baseFontResourceId` used for the layout strut and every face bound by a nonempty retained layout run, deduplicated by resource identity. New run preparation resolves its effective style over the field base style; subsequent exports retain the bound face rather than reselecting from the current library. Source-only formatting ranges do not add faces. A field with no nonempty text run, including a math-only field, retains its actual base face for source editing and the line-layout strut; glyph-only layouts can share their first actual run face as the strut without embedding an unused Regular face; the mathematical paths themselves need no text font. Each selected face is embedded whole rather than glyph-subsetted, identified by the SHA-256 of its binary content, and reused across fields. Every new layout run binds its actual face through `fontResourceId`, independently of the logical family in its editable style. Canvas measurement, CodeMirror, and static SVG use the same immutable `inkbook-face-<sha256>` CSS alias. Changing library grouping cannot silently replace an existing run's face; a changed family/bold/italic signature resolves a new matching face. A document with embedded faces does not require the originating vault library to display its saved graphic.

The library cards align with the dialog content and share compact, token-based insets and gaps. The trailing content inset uses the same token as the title's top padding, with a larger mobile safe-area inset taking precedence. On phones, the shared layout wrappers pass the sheet height limit through to the library body. Only that body scrolls; the title and drag handle stay fixed, and the final row, pagination, and import navigation remain reachable when previews expand or the keyboard reduces the viewport. The body viewport reaches the lower sheet edge; the safe-area inset belongs to its scrolling content, so it follows the final row instead of leaving a fixed empty strip. The library has no introductory paragraph. Wizard steps rely on headings, field labels, and file previews rather than explanatory paragraphs; the upload hint names accepted formats and the per-file limit, and the final step retains one short storage and embedding-license notice. The retention notice appears only in the shared destructive confirmation, which names the selected face and variant. Cancel leaves the library unchanged and restores focus to its Delete action. Confirmation removes only that index entry; closing the library or its owner cancels a pending confirmation.

## Model, Layout, and Ownership

`TextElementV2` retains rectangle geometry, source, base style, range and paragraph formatting, background paint, and validated `TextLayoutV2`. Layout contains positioned lines and face-bound runs plus normalized math paths. The semantic source and retained formatting remain editable; stored layout supplies portable static presentation without requiring browser measurement in the document worker.

| Area                                 | Text responsibility                                                                                           |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| `src/domain/text/`                   | Pure bounded Markdown parsing, formatting, source edits, and family identifiers.                              |
| `src/rendering/text/`                | Font admission, native measurement, bounded layout/cache preparation, and normalized math geometry contracts. |
| `src/rendering/scene/`               | Retained SVG text nodes, culling, and the single temporary editing surface.                                   |
| `src/obsidian/text/`                 | CodeMirror source editing and public host math integration.                                                   |
| `src/obsidian/embeds/active-editor/` | Session preparation, current-result adoption, style changes, and history integration.                         |
| `src/obsidian/fonts/`                | Public Vault font storage and plugin-owned library metadata.                                                  |
| `src/persistence/`                   | Text/font validation, versioned codecs, font resources, static SVG output, and worker transport.              |

Parsing, font processing, layout, and publication use the injected central `WorkScheduler`; they do not introduce a separate scheduler. Scene visibility and retained nodes use the existing spatial-index/culling flow. Position-only changes reuse field-local layout; source, style, width, and font changes invalidate the relevant preparation. Viewport-indexed editor decorations restrict visible preview work. Vertical ascent, descent, and line height come from a lifecycle-owned native CSS line-box probe outside CodeMirror, cached for at most 256 font signatures; Canvas remains responsible for horizontal text measurement. The probe's indivisible layout read follows shared scheduler admission, and disposal releases its DOM and cache. React continues to own chrome only.

The scene's isolated drawing document temporarily admits the interactive field editor in a runtime-only SVG `foreignObject`. Its owned `overflow: clip` window follows the existing scene/host viewport; compensating wrapper and content offsets preserve the text's document position without creating a nested vertical scroll surface. The public CodeMirror `scrollHandler` routes caret visibility through the existing native host scroll owner. Viewport changes coalesce CodeMirror `requestMeasure()` into one existing scheduler frame. Revealed Markdown or LaTeX source may exceed canonical graphic height: `TextSessionExtent` coalesces content-height changes through the central scheduler and reads the native editor root's local CSS used height, independently of scene rotation and zoom. Ordinary height invalidations use public CodeMirror `requestMeasure()`; corrections to transient height-gap estimates must not become permanently retained page growth. An accepted geometry publication instead performs its immediate read once after the matching decorations and bounds, consumes an already queued extent frame, and updates the runtime surface and selection outline together. It extends the temporary host page extent through the existing selection-move layout boundary and updates that extent before caret navigation. Overlapping source and handle gestures retain separate leases on that boundary: an inner completion or cancellation cannot release the outer source reserve, and only the final owner settles the extent. While only source editing retains a lease, corrected source height may shrink its temporary reserve immediately, bounded below by the original hysteretic page height and the current Store extent. An overlapping handle gesture retains the existing growth-only policy until its own completion. Final release restores the original hysteretic page height when canonical field height is unchanged, and derives the current Store extent when a retained operation committed geometry. Source reveal alone changes neither persisted layout nor source. This exception is lifecycle-bound to active text editing. It does not authorize arbitrary HTML in saved files: safe persisted SVG forbids `foreignObject`. See [the architectural decision](decisions/text-fields.md).

## Persistence, Clipboard, and PDF

Documents containing text emit envelope and snapshot version 2. Documents without text retain canonical version 1 output; existing version 0/1 reading and migration remain available. Older strict readers cannot edit version 2 documents. The [SVG envelope](svg-envelope.md#text-and-font-extension) defines the additional static markup.

Legacy version 2 input without run bindings resolves them against its own validated embedded faces before Store adoption and requires a canonical rewrite; it does not consult the current font library. Disk metadata stores font descriptors without `data`; the font payload occurs once in the allowlisted `inkbook-fonts` stylesheet as data-only `@font-face` rules. Loading reconstructs runtime resources only from validated matching CSS faces, validates the binary content hash against the descriptor ID, and then applies normal schema/resource checks. The metadata integrity hash binds the descriptors, including those content-hash IDs. This consistency binding does not authenticate a document's origin.

Inkbook clipboard payloads retain text, formatting, layout, and required font resources and use payload version 2 when needed. Existing Inkbook clipboard representations keep priority. Otherwise Ctrl/Cmd+V and explicit Paste accept plain text, Markdown, or LaTeX source as a new field at the existing canvas invocation placement. When the text source editor owns focus, native paste inserts into that field in place instead of creating another element. One paste is one undoable change through the existing history pipeline. Markdown/math delimiters remain source and drive the ordinary parser; clipboard HTML is not executed. The transport MIME and prefixed fallback remain compatible with the existing clipboard entry points.

Document preparation is a general session boundary, not a PDF-only hook. Pending input and in-flight preparation conservatively keep the session dirty. Lock, detach, unload, and explicit export first finish native CodeMirror batches, prepare and commit current layout, and wait for glyph readiness before releasing the editing scene or persisting the snapshot. A preparation failure performs no stale write: the single detached dirty session retains its source and scene for retry. External reload and local-copy export cannot bypass pending input. Mutating external commands finish active source editing through the same boundary as toolbar commands. If another authoritative operation removes the edited element, the session releases its input and export hook and does not reinsert it. Model replacement or explicit discard releases retained ownership; unload I/O failure keeps the committed model retryable. This is bounded in-memory retention, not a durable draft-recovery format. Native Markdown PDF preparation completes current text editing before capturing the authoritative document. Static text, field backgrounds, math paths, and the required local font faces join the same complete graphic used by existing pagination. No live CodeMirror editor or `foreignObject` enters the saved SVG or PDF preparation.

## Capacity and Verification

The ordinary document/clipboard byte, geometry, element, depth, and connection limits still apply. Additional text bounds are:

| Resource                                                                 | Limit                                                                                                                        |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| Field source                                                             | 100,000 UTF-16 code units; null characters rejected                                                                          |
| Style ranges and paragraph records                                       | 4,096 each per field                                                                                                         |
| Combined layout line/run/math/path items, table frames, rows and columns | 16,384 per field                                                                                                             |
| Rendered run text                                                        | 200,000 UTF-16 code units per field                                                                                          |
| Formula source                                                           | 8,192 UTF-16 code units per expression                                                                                       |
| Normalized math path data                                                | 100,000 characters per path; 2,000,000 combined per field                                                                    |
| Aggregate retained text payload accounting                               | 32 MiB per document                                                                                                          |
| Font binary import                                                       | 8 MiB; declared decoded container size at most 32 MiB                                                                        |
| WOFF2 decoder                                                            | 32 MiB decoded output, 16 MiB maximum Brotli window, 64 MiB WebAssembly linear-memory cap, at most 328 KiB retained metadata |
| Font library                                                             | 128 faces                                                                                                                    |
| Document resources                                                       | 64 faces; 32 MiB aggregate Base64 data; 8 MiB Base64 per face                                                                |

Payload accounting includes source, formatting, retained runs, and math path storage; it is not a measured total-browser-heap guarantee. Font admission and text preparation failures leave existing authoritative elements intact.

Acceptance requires focused deterministic Unit/Integration and observable work/resource coverage for parsing, source edits, reflow, font admission/reuse, culling, serialization, clipboard, current-edit PDF preparation, cancellation, and cleanup. Real Obsidian desktop/tablet/phone, keyboard, accessibility, software-keyboard, light/dark, external SVG fidelity, and physical-device checks follow the existing [quality contract](quality-and-testing.md) and [manual release checks](manual-release-checks.md). Source implementation and automated coverage do not by themselves establish those manual results or physical latency. Large-field acceptance must confirm native editor windowing and mounted-line bounds against the complete document size; source-level clipping alone does not establish this result.
