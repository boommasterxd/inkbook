# Performance CI

## Status and Evidence Boundaries

This performance gate remains a draft: its timing method is not ready for acceptance. All 90 classified contract executions passed, but complete forced-comparison validation and fresh hosted validation remain pending. A default run with identical candidate/reference sources can legitimately skip timing comparisons and does not validate the comparison method. No speedup or physical-device acceptance is established.

The complete integrated `npm run ci:quality` passed: 388 test files, 3,503 passed tests and one expected failure; coverage was 90.04% statements, 83.82% branches, 92.39% functions, and 93.04% lines. Formatting, lint/style/layout, architecture, type checks, duplication (zero clones), dead-code checks, audit (zero vulnerabilities), build, and package verification passed. These quality results do not establish timing stability or complete performance acceptance.

The product budgets, fixtures, refresh rates, and physical reference-device obligations remain canonical in [Quality and Testing](quality-and-testing.md). The gate separates three kinds of evidence:

| Mode        | Evidence                                                                                           | Does not establish                                                                       |
| ----------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `contracts` | Full-size scenario correctness, operation counts, cache/resource bounds, and controlled scheduling | Absolute latency or physical-device responsiveness                                       |
| Paired gate | Paired mean work cost against matching source references on the same runner                        | A statistical confidence interval or compliance with absolute product budgets            |
| `reference` | Original unscaled p95/p99, maximum, and total-time limits with original samples                    | Browser, GPU, host input, or physical mobile behavior without the required device checks |

Controlled time decides scheduling only. A 0.05-millisecond modeled cost per domain scheduler checkpoint determines where it yields during contracts and paired execution; recorded CPU or elapsed measurements remain real. This cost is not measured device speed, and an expensive loop between checkpoints can remain invisible to that model. The fallback scheduler also advances its injected deadline clock by 0.05 virtual milliseconds per real clock read in contracts and paired execution mode, independently of its CPU measurements. Reference mode retains real-deadline scheduling in both fixtures. Actual process heap limits are runtime-specific measurements, distinct from deterministic retained-object and cache bounds.

## Commands and Execution

```bash
npm run benchmark
INKBOOK_PERFORMANCE_MODE=contracts npm run benchmark
INKBOOK_PERFORMANCE_MODE=reference npm run benchmark
```

The default is the complete gate; only `contracts` and `reference` are supported explicit diagnostic modes. The former `compare` mode is removed. Contracts-only and reference execution are explicit local diagnostics; both are rejected as substitutes for the complete gate when `CI=true`. Reference mode checks the original absolute limits without hosted multipliers. `INKBOOK_PERFORMANCE_PROFILE` is obsolete and rejected. The existing [local contention guard](quality-and-testing.md#coverage-and-ci-gates) still applies.

The [exhaustive manifest](../scripts/performance-test-manifest.mjs) owns all 50 files and 90 file/profile executions: 16 invariant files at 120 Hz, 24 budget-only files at 240 Hz, and 10 cadence-sensitive files at each of 60, 90, 120, 144, and 240 Hz. Seven serial batches execute these contracts. Vitest retains file isolation, one worker, and disabled file parallelism. Batching reduces runner startup overhead; it does not remove scenarios, reduce fixture dimensions, or replace a file with a representative subset.

Only statistical repetition in clipboard and serialization/export scenarios is shortened to one sample in contracts mode. Stateful scenarios, repeated lifecycle checks, continuous 600-frame profiles, maximum fixtures, and all five cadence rates retain their behavioral repetitions. Reference mode retains its original five runs and scenario-specific 20/100 samples through [sample-policy.ts](../test/performance/sample-policy.ts) and its explicit callers. Paired kernels declare their own sampling below; those mean-cost samples do not replace reference-mode latency samples.

Every selected file must supply successful test results and one timing envelope. The exhaustive `TIMING_PERFORMANCE_FILES` list identifies 44 files that must emit nonempty, valid timing measurements; their empty envelopes fail. The other six structural/resource-only files must emit empty timing envelopes and still run every contract. Missing, duplicated, malformed, or incomplete reports fail. Structural-only files remain mandatory contracts; comparison rounds need only repeat files that emit timing metrics. Time and output caps protect the harness against hangs and excessive reports, not product responsiveness.

## Same-Runner Comparison Policy

The [gate](../scripts/performance-gate.mjs) checks the candidate against both the current PR base and a fixed source anchor. `INKBOOK_PERFORMANCE_BASE` defaults to `origin/main`; pull-request CI supplies the event's base SHA. The anchor is `ec7471a17fd19c2072141d8edbb177ae1d998ded` in [performance-policy.json](../.github/performance-policy.json). It never advances automatically. Replacing it requires review against the previous anchor.

All variants use the candidate's identical test harness, configuration, Node runtime, and installed dependencies; only their `src/` tree changes. Both reference dependency manifests and complete lockfiles must match the candidate. A missing reference or dependency mismatch blocks comparison rather than silently comparing different environments. Source and harness hashes and resolved source commits identify the compared inputs, including dirty local candidate content.

Candidate contracts run before timing comparison. Matching candidate/reference source hashes with verified matching dependencies are reported as `identical-source`: duplicate timings cannot reveal a runtime source regression and are omitted. Identical references can reuse the same measured source. Every candidate contract still runs. This shortcut is proof of identical inputs, not a timing measurement or a measured speedup of changed-source CI.

A second conservative check uses each scenario's complete transitive esbuild input graph and actual source-file content hashes. Equal resolved hashes yield `identical-inputs` and skip that scenario's duplicate measurement while retaining its contracts and coverage accounting. Missing edges/files, dynamic loading, `import.meta`, or externally resolved source graphs prevent this shortcut. Shared package dependencies must already have passed lockfile verification. A module-name heuristic or incomplete import list is insufficient.

Changed inputs use [paired kernels](../test/performance/comparison/paired-runner.ts) with separate reference and candidate implementations in the same fresh process. Three fresh process rounds run serially. Preparation/reset and result verification stay outside measured intervals; synchronous operations add no artificial promise scheduling. Two execution forms preserve different workload lifetimes:

| Execution                                      | Pairing and sampling                                                                                                                                                                       | Result                                                                                                       |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| Small atomic `sync`/`async` operations         | Warm both variants, then two ABBA/BAAB blocks, with collection before blocks when exposed; reference warmup calibrates one shared operation count                                          | `mean-operation-work`: sum all measured phase intervals within each operation, then average operation totals |
| Stateful `sequence`/`async-sequence` workloads | Execute the original full trajectory once per process round, alternating AB/BA at every matched yielded step; preserve original internal warmup and all 600/50/101 or other declared steps | `paired-sequence-work`: measured work across the complete original trajectory                                |

Atomic calibration targets 100 milliseconds of measured reference work per measurement, capped by an estimated 250-millisecond reset/run/verify lifecycle and 10,000 operations. The count is at least one and is fixed for both variants after their equal warmups; a single expensive operation can exceed the estimate. Reports retain the selected count, calibration observations, limiting caps, and whether the work target was estimated and actually reached. No best sample is selected or discarded, and the count is not increased after observing a failed comparison.

Sequence lengths are exact contracts: early completion, extra yields, or unequal variant progress fail. Complete trajectories are not wrapped in atomic block repetition. Summing phase intervals before aggregation prevents additional slices from making an unchanged total operation appear cheaper. Every real interval, operation total, and relevant block/sequence metadata is retained. These work metrics do not establish original p95/p99, worst-frame, or end-to-end latency requirements; reference mode retains their original sample counts and absolute budgets, and physical-device acceptance remains mandatory.

The registry maps every original timing phase to comparison scenarios and checks both directions of coverage. This prevents omissions but does not alone prove behavioral equivalence: review full inputs, phase boundaries, state transitions, and verification against the original test. All original controlled cadence and work/resource contracts remain mandatory at every classified rate.

Comparison metrics use stable scenario identity plus refresh rate. Each round must contain exactly the expected measured identities and explicitly account for skipped identical inputs; mismatched, missing, or duplicated populations fail. No raw measurement may be reused as a fresh round, and failed attempts cannot be retried until green.

Per-scenario statistics additionally retain the original p50/p95/p99, maximum, total, or mean measurement identity. They use raw phase intervals or raw operation totals, never block means. Quantiles use nearest rank (`ceil(n * p) - 1`); each statistic declares its original minimum population. Insufficient samples fail unless the original contract explicitly permits a maximum fallback. These statistics use the same three-round relative gate as work metrics; they do not prove absolute device latency. Population metadata and complete scenario coverage are still being finalized.

The decision rule in [performance-comparison.mjs](../scripts/performance-comparison.mjs) is fixed before validation measurements. For each metric, divide candidate by reference in each paired round:

| Observed result                                                                     | Classification                              |
| ----------------------------------------------------------------------------------- | ------------------------------------------- |
| Every paired ratio is greater than 1.1                                              | `regression`, even if round spread is large |
| Every paired ratio is at most 1.1 and neither variant's maximum/minimum exceeds 1.2 | `pass`                                      |
| Mixed ratios, excessive spread, or a zero measurement                               | `inconclusive`                              |

Both regression and inconclusive results fail the gate. Invalid/nonfinite values, duplicate keys, mismatched populations, or anything other than three paired rounds fail report validation. Three observed ratios are an engineering decision rule, not a confidence interval or a prediction of all future runner behavior. Failure requires investigation; no automatic tolerance increase, anchor promotion, or retry policy is permitted.

## Hosted Execution and Retained Evidence

The required `Performance (shared)` and `Performance (refresh profiles)` checks remain two parallel standard `ubuntu-latest` Node.js 26 jobs. The shared job owns the invariant and budget-only batches; the refresh job owns all five cadence batches. Each job runs its own complete selected contracts and comparisons serially. The `CI` quality job remains on Node.js 24, and `gitleaks` and `Validate PR Title` retain their required identities. Release tags rerun the complete gate before publishing.

`INKBOOK_PERFORMANCE_RESULTS_DIR` selects the report directory; otherwise the gate creates and prints a retained temporary evidence directory. Keep the top-level summary and raw kernel reports together, including incomplete/failing runs; hosted jobs retain `performance.json` artifacts for 30 days, including failures. Preserve provenance, selected file/profile completion, elapsed batch costs, round measurements, and comparison classifications. Do not check large raw cohorts into the repository. Compare actual duration and runner-minutes with [PR run 34992504129](https://github.com/boommasterxd/inkbook/actions/runs/34992504129), reporting identical-source and changed-source costs separately. Until fresh runs exist, startup and deduplication savings are hypotheses.

The former [calibration run 34989636630](https://github.com/boommasterxd/inkbook/actions/runs/34989636630) observed a greatest measured/reference ratio of 4.9893.
Its reserve rule required factor 6.25 and blocked adoption above the previous factor-5 ceiling.
The replacement removes that multiplier, calibration-only jobs/scripts, and checked-in raw cohort; the historical result does not validate the new gate.
