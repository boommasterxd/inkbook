# Performance CI

## Evidence and Acceptance

The gate separates deterministic work/resource/scheduling contracts, relative timing on the same runner, and absolute latency on reference devices. Product budgets and physical-device obligations remain canonical in [Quality and Testing](quality-and-testing.md). A fast development machine or a GitHub runner cannot establish responsiveness on weaker devices.

The direct-comparison implementation is under validation. An earlier paired-kernel prototype passed the source-identical hosted path but remained unstable for unchanged synthetic-DOM tails and was too expensive in broad forced comparisons. Those passes and runtime savings do not validate this replacement.

| Evidence                | Establishes                                                               | Does not establish                                                           |
| ----------------------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Contracts               | Original scenario behavior, bounded work/resources, controlled scheduling | Physical speed or device latency                                             |
| Same-runner comparisons | Observed relative costs against the PR base and fixed anchor              | Hardware-independent absolute latency or a statistical confidence interval   |
| Reference execution     | Original unscaled timing budgets and original populations                 | Browser/GPU/OS/physical-mobile behavior without the prescribed device checks |

## Execution

```bash
npm run benchmark
INKBOOK_PERFORMANCE_MODE=contracts npm run benchmark
INKBOOK_PERFORMANCE_MODE=reference npm run benchmark
```

The default command runs the complete gate. Contracts-only and reference execution are explicit local diagnostics and cannot substitute for it in CI. An internal measurement mode retains the original test repetitions, real deadline clocks, and timing statistics while reporting absolute measurements without applying a development-machine latency limit. It is used only by the comparison orchestrator. Legacy hosted multipliers and the former profile configuration are rejected.

The [exhaustive manifest](../scripts/performance-test-manifest.mjs) classifies all 50 files and 90 file/profile executions: 16 invariant files at 120 Hz, 24 budget-only files at 240 Hz, and 10 cadence-sensitive files at 60, 90, 120, 144, and 240 Hz. Seven serial contract batches use isolated Vitest files and one worker. Every candidate contract runs, including unchanged scenarios.

Contracts shorten only pure statistical repetition in clipboard and serialization/export tests. Stateful lifecycles, full-size fixtures, continuous input, and all refresh rates retain their original trajectories. Controlled scheduler time advances by 0.05 virtual milliseconds per checkpoint/read in contract mode; it is not presented as measured speed. Measurement and reference modes retain original sample populations and real deadline scheduling.

The manifest identifies 44 files that must supply nonempty timing reports and six structural/resource files that must supply empty reports. Missing, duplicated, malformed, unexpected, or unsuccessful test results fail. Existing [local contention protection](quality-and-testing.md#coverage-and-ci-gates) remains required. Actual heap checks are runtime-specific; deterministic cache and object limits remain separate.

## Comparison Policy

The [gate](../scripts/performance-gate.mjs) compares with the current PR base and the immutable anchor in [performance-policy.json](../.github/performance-policy.json). The anchor never advances automatically. Both reference dependency manifests and lockfiles must match the candidate; a mismatch blocks comparison. Every variant receives the same candidate test harness and configuration, with only its source tree replaced. Reports retain resolved commits and source, harness, and dependency hashes, including dirty local input.

The original benchmark files supply comparison measurements directly. There is no second implementation of their scenarios, fixtures, warmup, percentile estimators, maximum windows, or assertions. Missing or changed metric identities and contracts block comparison. Structural assertions remain active while the timing assertion helper records its original measurement.

Source-identical references skip redundant timing, with explicit identity evidence. The [input planner](../scripts/performance-inputs.mjs) can also skip complete original test files whose resolved transitive test/fixture/source input graphs match. This optimization requires verified identical dependencies and the reviewed Vitest configuration hash. Configuration changes, unresolved imports, dynamic source loading, filesystem reads, and external source edges conservatively require measurement. All candidate contract files still execute.

Changed files run in separate normal-V8 processes for the reference and candidate. Both sides use the same selected files, profiles, original sample counts, and clocks. Neither side shares a heap with the other. Measurement runs disable Vitest results caching and use a stable file selection, preventing earlier measured durations from changing test order. The graph-only esbuild configuration preserves value-form imports used as types, so compiler-erased edges resolve to their actual dependencies instead of forcing unrelated benchmarks to run. This does not change the Vitest runtime configuration; opaque or unresolved inputs still require measurement. No samples are removed. Each affected profile batch has two predeclared decision points: six paired runs and, only if unresolved, eighteen in total. Before measuring, independently shuffle a balanced block of three AB/three BA pairs and a second block of six AB/six BA pairs. Record that order. A decided batch stops; other affected profiles still run. After six pairs, the second stage includes only files with an unresolved metric. Earlier measurements stay in the evidence, and all candidate contract tests always run. There is no decision between these points or retry after eighteen.

The relative acceptance target is the median paired ratio of each original trajectory statistic, compared with a calibrated factor of 1.50. It does not estimate a process-distribution tail or replace the absolute product budgets. Six of six ratios strictly below 1.50 establish pass at the first stage; fourteen of eighteen establish pass at the final stage. The symmetric upper-side rule identifies regression. Ties, zero durations and insufficient evidence cannot establish pass. Decisions reached after six pairs are frozen even when other metrics require eighteen. Both base and fixed anchor must pass, preventing cumulative drift beyond the anchor margin.

This fixed two-look sign test has a one-sided false-pass bound of `1/64 + 4048/262144 = 0.03106689453125`, assuming independent, comparably distributed process pairs. The bound concerns the median ratio for a metric; it is not a simultaneous confidence guarantee for a list of reported regressions. Raw ratios and stage-specific median bounds remain in the report. See [NIST's sign-test definition](https://www.itl.nist.gov/div898/software/dataplot/refman1/auxillar/signtest.htm). A rare process slowdown may escape a median comparison; unchanged reference-device worst-run acceptance and deterministic work/resource contracts remain separate safeguards. Scheduler and platform dependence must not be described as eliminated.

The former 1.10 ratio and 1.20 spread were provisional hosted policy, not product budgets. The user authorized evidence-based relative calibration. Thirty prior independent control pairs supplied calibration data; a separate, predeclared local control passed all six arrangement/phone/chrome metrics with the new rule after eighteen pairs (52.8 seconds). The original mutation adding 500,000 square-root operations per arrangement command was rejected after six pairs (three regressions, one unresolved metric); a 5,000,000-operation mutation produced four regressions after six pairs. All mutations lived in disposable source copies. The independent [hosted control and mutation run](https://github.com/boommasterxd/inkbook/actions/runs/35024965492) also passed all six unchanged metrics after eighteen pairs (141.3 seconds), and rejected both mutations after six pairs each (three regressions and one unresolved metric in each case). This validates the selected controls, not every possible workload. A local performance-neutral source edit exercised the actual gate, including immutable workspaces, input selection and base/anchor deduplication: the chrome comparison passed at six pairs in 4.9 seconds overall. Broad changed-source runtime remains a separate measurement requirement. Thresholds must not be fitted to held-out results.

## Hosted Execution and Evidence

Preserve required checks `CI`, `Performance (shared)`, `Performance (refresh profiles)`, `gitleaks`, and `Validate PR Title`, standard Ubuntu runners, quality Node 24, and performance Node 26. Shared and cadence shards run in parallel on separate runners; benchmark work within each shard is serial. Post-merge main pushes do not repeat the tested squash tree. Release tags rerun the complete gate.

Raw measurements, failures, input identities, and comparison decisions remain available as job artifacts. Local default evidence is retained outside disposable workspaces. Time/output limits bound the harness and must not be interpreted as product latency budgets. Source-identical CI duration must be reported separately from changed-source duration.
