# Rendering and Performance

Performance verification follows the [Unified Verification Model](performance-ci.md#unified-verification-model): direct work/resource bounds and simulated scheduling protect automated contracts; physical reference-device acceptance separately evaluates speed. The rendering and latency requirements below remain the product contract.

## SVG Instead of a Bitmap Canvas

The active drawing area is an SVG.

All actual content is located within a camera `<g>`:

```
screenX = (pageX + camera.x) × camera.zoom
screenY = pageY × camera.zoom
```

`camera.y` does not exist in version 1. Vertical navigation is owned exclusively by the Obsidian note scroller.

Screen-relative overlays are located outside this transformed area:

- selection handles
- lasso
- eraser radius ring
- tool icon

Selection handles, crosshairs, tool icons, and the eraser radius remain screen-sized as defined in [Tool Cursors](editor-tools.md#tool-cursors).

## Tool Cursor Rendering

The scene owns a retained, decorative SVG cursor surface attached to the owning document body, fixed to the viewport with pointer events disabled. Client coordinates anchor it independently of compositor-driven native scrolling; nesting it in the contained canvas would make it scroll again. The surface copies the canonical palette and clips to the intersection of the canvas content box and native scrollport. Its nodes are removed with the scene. It contains only an eraser ring and an icon slot; the input surface uses the native system crosshair. The host adapter obtains the exact registered toolbar icon only when its resolved ID changes and retains at most one imported icon. After the first resolved frame, pointer movement updates only the retained group transform synchronously using client coordinates; cached content bounds still gate visibility and project page-space hit tests. Unchanged coordinates write nothing; hidden or pending cursor presentations and invalidated layout wait for the normal frame. A passive `pointerrawupdate` listener can move an already tracked mouse or pen decoration earlier without scheduling a frame or changing gesture input. It retains only the latest coordinates and timestamp, ignores foreign pointers and obsolete samples, and prevents an older ordinary move from restoring an older position. Ordinary pointer events remain the fallback and own tool state, contact processing, and hover lifecycle. Movement changes the group transform; color, fill, and opacity changes reuse cached icon geometry. Missing icons leave the native crosshair available and are cached until the ID changes. Pointer bursts retain only the latest client position for the next presentation frame while distinct movement samples can each write one immediate transform; ordered drawing and eraser samples retain their existing processing. Tool, paint, visibility, and hover-target changes use the existing scene frame scheduler, update only changed attributes, and create no React renders, UI notifications, document mutations, history, worker requests, exports, or saves. Cursor-only frames perform no content reconciliation, culling query, or element geometry construction.

Selection rendering and cursor hit testing share the same prepared overlay geometry. Hover samples reuse it; pointer-down resolves one fresh geometry for both handle lookup and hit radius. Camera-only changes reproject that geometry and the retained selection frame without fetching all selected records again. Selection identity or model revision changes invalidate this reuse. Handle completion and cancellation use the same revision-bound reuse after clearing gesture previews, avoiding another selected-record traversal when the model and selection are unchanged. An exactly zero anchor-correction delta checks cancellation and preserves element identities without requesting per-element scheduler frames.

The owning presentation caches and invalidates its coordinate measurements across pointer, scroll, resize, and camera changes. Layout reads for cursor projection remain bounded independently of raw pointer-event count. Navigation commits apply native scroll and layout changes before the final cursor projection and feedback write in the same frame, so the decoration cannot drift for one paint and recover in the next scene frame. Native scroll notifications invalidate clipping and page-space cursor projection for the next coalesced scene read/write phase. A burst performs no synchronous cursor measurement or feedback write per scroll event; the fixed viewport decoration position needs no scroll compensation. Navigation-provided layout measurements remain reusable within that frame. A stationary pointer remains anchored in screen space through native scrolling and zoom. Clearing feedback sets `display="none"` on the retained cursor group so explicitly visible SVG children cannot keep painting after pointer departure or pen proximity loss. The offset tool icon stays visible during live drawing; there is no filled cursor disk or cursor-to-ink handoff. Listeners, pending updates, and nodes follow the owning window and presentation lifetime.

## Live Stroke and Saved Stroke

While the pen is touching the screen, an imperative live-stroke group is updated directly.

The process:

1. `pointerdown` starts a point list.
2. `pointermove` adds all available coalesced pointer samples.
3. Samples that are very close together are merged or only replace the current tip.
4. Finalized geometry is appended to immutable preview chunks, while only a bounded mutable tail is rebuilt.
5. `pointerup` creates an `AddStrokeCommand`.
6. The same stroke is then rendered through the regular element store.

A successful freehand commit transfers the existing inner stroke group into an element-ID-owned handoff group in one node move, without cloning or individually moving its paths. The group retains its render band and group opacity until the corresponding committed node mounts in the same synchronous scene write. Budget-deferred frames preserve the handoff; subsequent gestures and cancellation affect only the new live stroke. Removal, completed culling, and scene disposal release pending handoffs. IDs are unique and bounded by the document element limit, and each handoff inherits the bounded live chunk count. Direct creation never receives entrance motion.

Live preview and saved output share center simplification, pressure radii and capsule construction. Stable pressure windows use the canonical compressed contours. The mutable pressure tip paints complete capsule contours in the same opacity group; their filled union is exact and avoids repeating geometric union preparation on every input sample. Canonical outward approximation is applied when that window is finalized, within the bound below.

The live builder MUST NOT rebuild the complete path for every sample. Derived center simplification uses fixed 64-interval raw-sample windows independent of input batch boundaries. It finalizes a raw window after 131 retained samples of context become available and advances 64 samples. The mutable tail contains at most 130 retained samples, with preceding simplified-center context. Completed raw-window previews are reused, so only the incomplete raw window is rebuilt for a new sample.

Pressure geometry has a separate capacity of 64 emitted capsules or disks per canonical window. At most 63 pending pieces remain between completed windows. Each completed canonical window is prepared once, retained immutably and appended to the preview. The renderer retains one mutable tail path and inserts newly finalized chunk paths before it. All paths share one opacity group. Release transfers prepared geometry through a lazy, once-only handoff into the bounded scene path cache. The regular mount reuses completed records and prepares only the remaining bounded tail before serializing the canonical path; it does not reread the complete raw prefix. The handoff also publishes canonical windows into the store-owned pressure cache for selection reuse. Cancellation, eviction and scene disposal release retained preparation. Final string assembly is linear in retained geometry and remains an indivisible boundary; the 16,384-sample limit does not itself guarantee release latency. Input uses a geometrically growing numeric buffer and preserves the committed canonical sample triples.

One gesture retains at most 16,384 points as one selectable, erasable, undoable element. Once a new point would exceed that capacity, freeze the accepted geometry for the remainder of the gesture and issue one notice asking the user to lift the pen. Further valid samples neither move the endpoint nor rebuild geometry; release commits the accepted stroke and cancellation discards it. This lifetime capacity is independent of the 4,096-sample pending frame batch.

The numeric input buffer holds five 64-bit scalars per retained sample: position, pressure, movement timestamp, and filtered velocity. At the point cap it occupies 655,360 bytes, excluding canonical points and geometry. Distance, timing, and pressure decisions read scalar values directly from that numeric buffer. The pointer hot path does not reconstruct temporary sample objects or replacement sample arrays for already retained points.

Constant-width strokes use one SVG centerline; pressure-sensitive strokes use the continuous filled outline defined below.

## Deterministic Stroke Construction

New strokes store `smoothing: 0.5`. Input processing uses these rules for both the live path and committed output:

1. Convert each coalesced sample to page coordinates and reject non-finite values.
2. Merge nearby samples by replacing only the mutable tip while its accumulated screen-space travel since the last appended point stays below 0.5 CSS pixels. Count every movement, including reversals; at or above the threshold append a new point and reset the travel budget. Measuring only each incoming step against the moving tip is forbidden because a dense curve could otherwise collapse into one arbitrarily long chord. Retain the first and final accepted sample.
3. Smooth interior center points as `0.25 * previous + 0.5 * current + 0.25 * next`. Endpoints remain unchanged. The stored raw points do not change; smoothing is deterministic path construction.
4. Pressure filtering uses screen distance `d = distance * zoom` from the preceding retained sample. Mouse and finger input always use simulated pressure: compute measured speed in CSS pixels per millisecond as `v = d / dt`, where `dt = max(1, deltaTime)`. Initialize filtered speed from the first nonstationary movement, then update it as `filteredSpeed + (1 - exp(-dt / 32)) * (v - filteredSpeed)`. Apply the nonlinear curve only after velocity filtering: `target = 1 / (1 + (filteredSpeed / 0.35)^2)`. Start at pressure 0.5 and use response length `L = max(4, 0.5 * style.width * zoom)` CSS pixels. Store velocity alongside each retained input point so mutable-tip replacement recomputes from its unchanged predecessor. Exact duplicate mouse or finger positions retain the latest pressure, velocity, and movement timestamp; stationary events must neither inflate the tip nor shorten the next measured movement interval. Pen input starts at its clamped measured pressure; subsequent targets are finite measured pressure clamped to `0..1`, with response length `L = max(2, 0.35 * style.width * zoom)` CSS pixels. A non-finite pen sample is rejected. Both sources update as `previousPressure + (1 - exp(-d / L)) * (target - previousPressure)`. This spatial response damps sample jitter while retaining deliberate pressure changes; zero movement keeps the preceding pressure. Tip replacement recomputes from the preceding retained sample rather than repeatedly filtering the replaced tip. The owning window clock initializes capture time and timestamps direct updates; coalesced samples retain their event timestamps. When a pen drawing gesture ends, consume validated coalesced contact samples, but do not append or replace the final contact with a zero-pressure, primary-button-up release sample. Actual contact samples, including a zero-pressure sample with the primary button held, remain authoritative. Mouse, touch, shape, and selection release coordinates retain their normal final-update behavior.
5. Simplify derived smoothed centers in fixed 64-interval windows. Preserve each window's endpoints. For pressure input, prepare a derived pressure average from at most three neighbors on each side within that window. Clamp its radius displacement to the same `min(1, style.width / 32)` budget and retain a local pressure extremum unchanged when both adjacent radius differences exceed that budget. Recursively retain the largest combined center/radius error, always comparing the original samples against the candidate filtered endpoints. Thus filtering and point reduction together, rather than each independently, remain within `min(1, style.width / 32)` page units. Constant-width input has zero radius error and no pressure filtering. Editable samples are not simplified or rewritten. This bound applies to the derived centerline and radius, not to arbitrary later curve fitting.
6. Constant-width pen and highlighter strokes use the simplified centerline with native SVG round caps and joins. Do not construct another midpoint quadratic from widely separated simplified centers: that can cut corners beyond the simplification bound.
7. Pressure diameter remains `style.width * (0.35 + 0.65 * pressure)`. Each derived center defines a circular nib. Common external tangents form the convex hull of adjacent nib disks; a contained pair reduces to its larger disk. A disk already covered by an adjacent capsule need not be emitted again. Adjacent capsules reuse each prepared center nib, including its canonical radius, rather than preparing their shared endpoint twice. Empty capsule ranges prepare nothing.
8. Partition the emitted capsule/disk stream into independent windows of at most 64 shapes. These are distinct from the raw-sample simplification windows. Regular connected capsule chains first use a linear tangent-join contour: outer joins retain nib arcs and valid inner joins trim adjacent tangent segments. Its nonzero fill represents the same capsule coverage, but the contour need not have Boolean-union boundary topology or omit every internal edge. Invalid or ambiguous joins use the exact fallback. A single capsule directly uses its existing closed boundary. In the exact fallback, conservative source-boundary rectangles and roundoff-padded carrier-distance checks reject disjoint comparisons before analytic line/circle intersections clip boundaries covered by other shapes. Carrier rejection tests the complete circle or infinite supporting line, retaining near-tangent and numerically ambiguous cases for the original intersection calculation. Endpoint checks reject coordinate differences outside roundoff before evaluating a Euclidean distance. Arc parameter checks also reject points provably outside a roundoff-padded squared-radius band before computing the radial distance; ambiguous points retain the original distance and angle checks. Exact-union work lazily retains each original arc's start angle within that one canonical window; repeated arc-parameter checks reuse it without changing query angles or intersection order. The cache is released with the window. Coincident boundaries have deterministic ownership; retained directed fragments form closed union contours, including holes. Numerical ambiguity or exhaustion of the linear union-work allowance falls back to complete capsule contours instead of dropping ink. The allowance is 512 observed geometric operations per source shape, checked after each bounded clipping step. Union preparation yields between bounded clipping and stitching operations. Approximation yields during arc expansion, boundary reduction and quantization, caps intermediate contours at 4,096 points, and falls back to native union contours if the emitted-command allowance of 16 commands per source shape or the retained allowance of 16,384 outward-addition triangles would be exceeded. Work counters observe intersections, containment, boundary classification, interval checks and fragment capacity.
9. Simplify and quantize the resulting fill contours within `T = min(0.5, style.width / 32)` page units. The output grid is `0.1` for widths at least `10`, `0.01` for widths at least `1`, and `0.001` otherwise. Reserve `sqrt(2) * grid` for vertex displacement and the final thousandth-coordinate rounding allowance; split the remaining allowance equally between circumscribed arc approximation and boundary reduction. If no positive approximation allowance remains, preserve the exact contour. Conservative outward changes must not remove ink or exceed the original window bounds. Selection consumes the same final prepared geometry. Live fragments, committed paths, resize previews and export share the canonical preparation rules. All compound paths composite once through the [SVG opacity group](svg-envelope.md#strict-static-markup-allowlist). Compact SVG spelling changes encoding only. The [decision](decisions/compact-stroke-contours.md) defines reference output budgets and verification limits.

Commands first canonicalize stored samples as defined in [File Format](file-format.md). The serializer rounds only derived final SVG coordinates beyond that canonicalization. Path construction never reads current zoom except for the input merge threshold and input pressure filtering, so a later zoom change does not alter committed geometry.

Pressure-union clipping, stitching, approximation, simplification, and quantization expose cancellation and scheduler checkpoints after at most 16 relevant bounded inspections, edges, vertices, or local-removal probes. These generator intervals bound indivisible work; they do not force a frame handoff while the shared deadline remains. Progressive pressure preparation uses that deadline without a separate generator-step quota. The canonical geometry and fallback capacities above remain unchanged.

## Imperative Scene Ownership

React owns only stable application chrome: the toolbar and coarse editor lifecycle. Obsidian integration owns adaptive menus, operational feedback, and recovery surfaces. One imperative SVG scene renderer owns the camera group, committed content nodes, live previews, background geometry, culling, and overlays. React components MUST NOT render individual ink elements.

Framework-free motion contracts live under `src/rendering/motion/`, imperative scene code under `src/rendering/scene/`, and React-owned chrome under `src/rendering/ui/`. Static linting rejects React, ReactDOM, JSX, TSX, React-owned UI imports, roots, portals, and state APIs from the complete Scene path. This restriction does not forbid the imperative `Document`, DOM, and SVG APIs required by the retained renderer.

Each attached scene owns one `.inkbook-scene` host with an open shadow root containing one attached, inert `about:blank` iframe. The frame uses `sandbox="allow-same-origin"`, has no scripts, `src`, or `srcdoc`, and makes no network request. Its child document is the sole owner document for the scene SVG: the SVG and every later ink node or fragment are created there before renderer caches retain them. The SVG is attached once, without a duplicate in the host document. If the attached child document or its body is unavailable during construction, scene setup releases the partial frame and host and fails closed.

The frame isolates the large decorative SVG subtree from host document style invalidation. Focused theme, selection, and motion styles stay inside the SVG. The canonical light or dark palette is already applied directly to that SVG; the host surface relays only `--interactive-accent`, `--text-normal`, and `--inkbook-scene-foreground-visibility` to the child document. The presentation supplies its owned root explicitly; root, container, and document theme changes invalidate the theme read even when the light or dark scheme stays the same. The parent document continues to own the accessible canvas input surface, tool cursor, native scrolling, and the injected central window `WorkScheduler`.

Scene surface invalidations enter the renderer's existing `SceneFrameScheduler` and coalesce with scene work. `ResizeObserver` caches fractional `contentRect` width and height; the central frame reads host theme values before its write phase, then applies only changed child-body dimensions and relayed tokens. The existing central preview-handoff frame reveals the child foreground directly before its first paint without a new style read or a separate observer frame. This surface adds no animation-frame loop or work-yield loop. Release is idempotent and disconnects its observers and load listener, removes the SVG and frame, and removes the host; the owning scene also removes input listeners and its input surface. An unexpected replacement of the drawing document removes the input surface, disables the active editor, and enters the existing lock/save lifecycle. See the [Pointer Input, Preview, Commit, and Rendering](architecture-flows.md#pointer-input-preview-commit-and-rendering) ownership map and the [Isolated Scene Document decision](decisions/isolated-scene-document.md).

The following are updated by the scene renderer:

- the live stroke
- the camera transform
- the grid
- selection handles
- transformation previews
- eraser markings
- scroll compensation during zooming

Pointer-move, wheel, scroll, pinch, animation-frame, culling, snapping, and gesture-preview callbacks MUST NOT call a React state setter, notify a React-visible external-store subscription, create JSX, or wait for a React render or commit. A committed transaction may notify coarse UI subscribers once after the authoritative store and scene are consistent. A discrete selection, tool, or lifecycle transition may enqueue one coarse UI update after imperative input feedback completes, never one update per sample or animation frame. Subscribers receive only derived toolbar, selection-summary, history, save-status, and accessibility state.

Chrome callbacks keep stable identities for the lifetime of one active presentation. Before calling the React root, the chrome adapter compares a semantic snapshot of toolbar, active-menu identity, dynamic shape and style icons, layout, and callback state and skips the render when that snapshot is unchanged. Toolbar overflow measurement is keyed separately to layout-relevant state and runs only after a relevant state change, a dirty layout observation, or a changed positive width. Root height-only resize notifications reuse the existing toolbar measurement; changed root inline size, toolbar size, and layout-relevant chrome mutations still invalidate it. Obsidian menu contents are derived only when a menu opens or a committed coarse state change requires the open menu to be rebuilt.

The renderer coalesces scroll, resize, camera, store-delta, and observer invalidations into at most one pending scene update per animation frame. Horizontal touch and trackpad momentum contribute their elapsed-time-derived deltas to that same camera frame and never own a parallel render loop. Native trackpad inertia remains direct input and postpones the bounded synthetic X-only tail through an adaptive 8-to-40-millisecond missing-event window derived from the observed Wheel cadence, preventing both concurrent application and a fixed handoff stall. Trackpad speed response is a bounded constant-time calculation over the current delta and preceding timestamp; its adjusted delta drives both the direct camera frame and the allocation-free fixed-capacity velocity buffer. Direction reversal clears that buffer rather than allowing stale opposing movement to flatten the new velocity. The deadline is checked inside the existing camera frame coalescer without per-Wheel timers or callback allocation. A pre-deadline frame performs no layout read or DOM write, while the first overdue frame applies the elapsed share from the exact deadline. It discards stale queued work by generation. Within a frame, it performs all required layout reads first, then pure calculations, then DOM writes. It MUST NOT call `getBoundingClientRect()`, `getBBox()`, or computed-style and scroll-range reads after the first DOM write. Gesture-local container and scroller geometry is cached until resize, remount, or host-layout invalidation. `ResizeObserver` delivery is coalesced and unchanged sizes produce no scene update. Once the initial positive width is stable, each changed positive width updates the proportional camera zoom, page block size, viewport, and toolbar stage in the next coalesced frame. The outer presentation also listens to its owning window so an old inline-size clamp cannot prevent a growing pane from being remeasured.

Mount and unmount must release every presentation-owned React root, menu session, event listener, observer, animation frame, timer, worker, and host reference. Repeated lifecycle verification covers chrome roots and adaptive menus, note and attachment switching, worker creation and termination, and the 10,000-stroke memory lifecycle.

Content bands and decorative canvas overlays use `pointer-events: none`. One focusable transparent input surface above the content uses `pointer-events: auto` and normally `touch-action: pan-y`; it owns the canvas pointer, wheel, `contextmenu`, and keyboard event handlers. Finger drawing switches only that surface to `touch-action: none` before contact. Stylus hover and active stylus contact also switch it to `touch-action: none`, then restore the configured finger behavior after the stylus leaves. Pending and dominant vertical one-finger touch events remain available to Obsidian and the browser. The owning-window capture boundary stops propagation only after Inkbook has claimed horizontal page pan, pinch, finger drawing, movement from a selected overlay, or stylus input. It additionally cancels the claimed non-passive `touchstart` and `touchmove` stream, including Android compatibility touch events emitted alongside an active stylus pointer, so browser scrolling and host drawer gestures cannot take over an Inkbook gesture. Unclaimed vertical finger contacts retain the browser-native scroll path. Inkbook retains claimed gestures, while native browser scrolling and its kinetic tail remain available to the resolved Obsidian scroll owner for unclaimed contacts. Vertical wheel and trackpad events are likewise left unclaimed, and purely horizontal camera frames never write `scrollTop`. Toolbar controls and Inkbook-owned menus remain above that surface with normal pointer events. The renderer resolves elements through the spatial index and selection handles through their bounded screen-space overlay geometry rather than browser SVG target lookup, so no content or overlay node owns an event listener. Context-menu behavior is defined in [Features](features.md#canvas-context-menus).

## Delta Domains and Applied Node State

Every published store delta classifies each affected ID with one or more domains:

- `geometry`: path commands, geometry-affecting width, bounds, anchors, or spatial membership changed
- `paint`: color, opacity, fill, cap, join, or dash presentation changed without geometry
- `order`: stable rank changed inside a render band
- `connection`: reverse-map membership changed; affected resolved endpoints also carry `geometry`
- `visibility`: creation, removal, or another change to mounted-set eligibility

The store assigns monotonic safe-integer `geometryVersion` and `paintVersion` values at command commit. It never hashes records in the render path. A paint-only command reuses path strings, bounds, anchors, and spatial cells. An order-only command touches rank and affected SVG child order only. Selection and hover are scene state and do not replace element records.

Each mounted ID-to-node entry retains the last applied geometry version, paint version, preview-transform version, render rank, and relevant serialized attribute values. The renderer writes `d`, `fill`, `stroke`, opacity, width, dash, cap, join, class, or `transform` only when the corresponding applied value differs. Camera-only and overlay-only frames MUST perform zero content-node attribute writes. A theme change updates the presentation root palette once and never walks content nodes.

## Frame Priorities and Dirty Flags

One frame may contain several dirty domains, but work is always attempted in this order:

1. live ink and current pointer feedback
2. camera transform, connected-endpoint preview, and screen-space overlays
3. changed nodes that are already mounted
4. required visible entrants, visibility cleanup, and affected order
5. background regeneration, nonessential animation, and cache prewarming

Separate dirty flags prevent an overlay-only frame from querying visibility and prevent a paint-only frame from rebuilding geometry. At measured checkpoints the renderer stops before lower-priority work would exceed the current interaction-frame budget, retains the last complete scene, and queues one successor frame. A live gesture pauses cache prewarming, background work that is not required for correctness, tombstone creation, and worker-result adoption on the main thread. No lower-priority task may delay pointer feedback.

After pointer feedback, pending mounted-node updates and visibility reconciliation alternate which queue receives the first remaining frame slice. The other queue also runs when budget remains. A sustained changed-node queue cannot monopolize publication of newly visible elements; unfinished work retains one coalesced successor frame. This fairness does not make an indivisible geometry or DOM operation preemptible.

`SvgSceneRenderer.observeFrames(observer)` optionally reports one snapshot after each centrally admitted scene frame; passing `undefined` disables observation. Snapshots expose the original shared deadline, signed remaining budget, physical content-root and fragment publication counts, and actual reconciliation blockers (`publication`, `deadline`, or `paths`). Pending query and remote-request flags are separate from those blockers. `readyContours` counts received contours still reserved by the bounded remote pipeline; `readyElements` counts prepared, unpublished SVG element entries. Neither value scans the store or represents every warm geometry-cache entry. Observation retains no history; consumers own and bound their records. A throwing observer is disabled without interrupting rendering. Disposal releases it, and disabled observation adds no diagnostic clock reads or state snapshots.

### Central Work Scheduling

All cooperative main-thread work shares one `WorkScheduler` per owning Obsidian window. The workspace owns these schedulers, injects them into consumers, and retains them while persistence drains. Pop-out windows have separate budgets. Each document worker uses the same portable scheduler on its own thread with task-based admission; it does not spend the main thread's budget or wait for a synthetic display frame. The bridge forwards initial and changed frame settings to the worker, including while work is already pending.

The selected refresh-rate profile reserves 55 percent of a frame for cooperative work: approximately 9.17, 6.11, 4.58, 3.82, and 2.29 milliseconds at 60, 90, 120, 144, and 240 Hz. The remainder is available to Obsidian and browser style, layout, and painting. `Auto` measures 18 valid native animation-frame intervals once per visible owning window, with a maximum of 48 attempts, then stops. Until measurement completes, or if no valid interval exists, it uses 120 Hz. Fixed settings bypass measurement. The finite detector measures native cadence rather than scheduler queue throughput. Workers use the selected duration as their maximum cooperative slice, then yield through the central task adapter and resume without reserving the unused display-frame remainder. The main-thread fallback retains the owning window's frame admission policy.

`SharedFrameScheduler` owns the absolute epoch deadline. Consumers read that deadline and never start a fresh budget for each task, callback, helper, or document. A new native epoch starts its work clock once at central scheduler entry; an earlier browser animation timestamp must not consume the plugin allowance before its first callback runs. The first native frame after synchronous work still carries its consumed allowance until a real interval boundary; established native frame timestamps then identify subsequent epochs without requiring exact floating-point interval equality. Live profile changes adjust the allowance without erasing time already consumed. After an idle period, a later host task may start a new epoch only after a full frame interval. Long synchronous work cannot renew its allowance by repeatedly calling a checkpoint. Animation timestamps remain separate from the work deadline.

Central admission prioritizes `input`, then `frame`, then `background`, preserving FIFO order within each class. Coalesced pointer and camera updates use `input`; rendering, bounded selection work, and terminal selection-transform preparation use `frame`. Move/resize replacement preparation and its Undo/Redo continuations retain that priority through the Store adapter. Required viewport contour requests, their buffered contour adoption, and their matching model synchronization use `frame` for dispatch and result adoption and may proceed during navigation. Drawing/tool gestures still gate them. Speculative navigation-strip contour preparation uses background admission and yields to required scene and model work; input and navigation start cancel its current request. Encoding and dispatch of an already requested worker export also use `frame`, but wait during drawing and navigation. Other worker requests and result adoption retain background admission and both input gates. Unused budget remains available to lower-priority work. A running indivisible unit cannot be preempted by newly arrived input.

`checkpoint(signal?, priority?)` returns `undefined` while budget remains and a `Promise<void>` only when central admission requires waiting. The priority selects the existing central FIFO queue only after budget exhaustion; omitted priority remains `background`. Specifying `frame` or `input` never forces an in-budget handoff or starts a new allowance. Input gates use the same contract when no lease blocks work. Consumers await only a returned promise, then recheck cancellation, generation, input ownership, and the shared deadline. An exhausted checkpoint waits for central admission; pending asynchronous continuations are admitted separately, with a host-task boundary that lets nested Promise continuations spend their time before another waiter is admitted. `requestFrame()` coalesces through one host frame source and admits newly queued frame work in a later epoch. `nextFrame()` is an intentional frame dependency, not a generic unconditional pause. Existing frame publication limits, such as the 192-new-root limit, can require a later frame even when time remains. Input-priority gates retain their semantic ownership and wake background work on release rather than polling.

Only the approved window and worker adapters use native primitives to schedule cooperative work. The shared policy owns cancellation and hidden/stalled-frame progress; it does not run an idle animation-frame loop when no work is queued. Disposal cancels native handles and settles pending waits. Consumer generation, transaction, and abort checks remain mandatory before publishing resumed work. A document wait rejected because its former window scheduler was disposed may retry once on a different current owner; aborts and failures on the same owner never trigger that retry. Autosave debounce, gesture recognition, animation durations, menu event ordering, and I/O deadlines remain semantic timing rules, not independent work budgets. The source-layout AST gate rejects new native work schedulers outside these boundaries; its static checks do not prove arbitrary JavaScript callback intent. Window and worker zero-delay task delivery share a portable FIFO transport through one lazy reusable MessageChannel per scheduler, with at most one posted wakeup and one callback per delivered task. Native channel ownership remains in the approved adapters, and transport never grants work admission or renews deadlines. Unavailable or failed channels use cancellable timers; positive-delay timers retain their delay. All document-worker consumers use this transport. Worker-runtime termination disposes its owned scheduler, while main-thread fallback retains the shared window scheduler.

An admitted slice may finish one bounded indivisible unit even if that unit crosses its soft deadline; it must then stop before another unit. A different consumer does not receive its own minimum-progress exemption after the shared budget is exhausted. Immediate pointer-finalization feedback remains synchronous against the same accounting and must remain bounded. A scheduler cannot preempt native DOM, style/layout, an atomic store commit, or one indivisible geometry step. The existing 16.7-millisecond acceptance limit for atomic adoption is unchanged. Deterministic scheduling tests establish admission and work bounds, not measured device latency. See the [decision record](decisions/central-work-scheduler.md).

CPU work does not have a second element-, sample-, or step-count slice quota. Store hydration, replacement preparation, heap construction, detached previews, mounted geometry preparation, and motion sweeps continue within the shared allowance. Small generator steps and temporary batches remain bounded so the next deadline and cancellation check is reachable. Memory/cache capacities, worker message sizes, schema limits, synchronous heap-maintenance bounds, and live SVG publication/filter-start caps serve different purposes and are not removed. Native DOM work and deferred browser painting are not preemptible by the JavaScript scheduler.

Store mutation preparation checks the shared deadline between bounded element, index, and copy operations, and checks cancellation before work and after yielding. Element counts and estimated geometry charges do not impose additional slice limits. Cheap preparation loops do not force a separate timer for every small batch. Unchanged immutable record identities bypass element cloning and comparison when deriving deltas; order changes are still classified. Prepared mutations remain atomic. Checkpoints continue synchronously until a real yield is required; cancellation reads the store mutation version without allocating a source wrapper. History replay passes its retained forward or reverse mutation and reuses the existing transition. Replay still validates changed elements, affected connections, ordering, capacity, and the combined history payload limit before publication, but estimates inverse payload directly from source records instead of cloning inverse elements or copying history band arrays. ## Viewport Culling

The store always retains every element. During initial editor preparation, the active scene opts into `deferInitialOverscan` and mounts every indexed element intersecting the actual visible area without overscan. The viewport includes both the currently clipped height and the pending transition target, so growth cannot expose unprepared visible content. Animated input handoff requires complete visible geometry and background plus the same `sceneCommitProof` before and after the intervening paint. Reduced motion permits an immediate atomic handoff with a current complete proof. Camera, viewport, layout, Store, or commit-generation changes invalidate that proof and postpone handoff. Immediately after input is enabled, `releaseInitialOverscan()` schedules ordinary reconciliation through the same central scheduler and live-root publication limit, reusing prepared visible paths.

Ordinary visibility refreshes mount indexed elements intersecting the visible area plus 80 screen pixels of overscan. The resulting envelope is retained while the current visible area plus a 40-screen-pixel safety reserve remains inside it. This hysteresis avoids classification and ordering work during small camera movements while preserving every visible element; a retained trailing edge may temporarily extend to 120 screen pixels before the next refresh.

The visible area is the intersection of the active scene container and its resolved native scroll owner's client viewport. A document scroll owner uses its client dimensions with an owning-window fallback, without an unused rectangle read; a nested owner uses its client box. Scroll, resize, and layout changes invalidate this measurement, which is clamped into container-local coordinates before zoom conversion, spatial lookup, and background coverage. Culling MUST NOT substitute the complete embed rectangle or a stale `scrollTop` estimate for that actual intersection.

Progressive viewport preparation prioritizes missing elements intersecting that exact visible area before overscan, across both render bands. Scrolling down prepares from smaller to larger Y, scrolling up reverses it; horizontal panning applies the equivalent X order. Zoom changes prioritize distance from the visible center. This spatial preparation order is independent of SVG paint order: completed elements are published at their canonical band and rank among retained anchors. Ready entrants receive the first publication opportunity before the old-mounted-node exit scan. Subsequent slices alternate cleanup and entrant publication within the shared deadline, so obsolete nodes do not remain throughout a large fill. Pending removal feedback must start before affected exits detach. A suspended cold path does not prevent reuse of already prepared candidates. Atomic existing-element order changes retain their complete ordering path.

Membership-only retargets preserve one flat owner of missing candidates while their retained-order proof remains valid. The initial delta IDs are owned rather than borrowed from reusable visibility buffers; retargets add entrants, release exits, and update spatial priority without retaining historical iterator chains. A still-visible local contour keeps its progress even when it temporarily moves into overscan. Interrupted successor searches retain their start and cursor, and new publications update the successor evidence instead of discarding already proved empty ranges. Partial node-detachment repair retains the progressive browser-publication cap; explicit existing-element order commands remain atomic.

Selection-edge autoscroll keeps at most one scheduled animation frame. That frame resolves the current scroll owner and reads its viewport once before preview writes, then uses the same measurement for its edge deltas. The next frame measures again, so a pane move, resize, or pop-out transfer cannot reuse stale viewport geometry. This does not cache the active scene container rectangle across lock transitions.

Exceptions:

- Visible selected elements remain logically mounted. Offscreen selected elements use one aggregate selection-bounds overlay. Their committed SVG roots may remain connected only as bounded offscreen cache entries; they do not join the visible or active transform subset.
- During a transform, at most 256 selected retained roots form an active preview subset, counting extra filled arrow-node paths against that budget. For selections above 256 IDs, candidates come from the spatial index within one viewport width and height around the viewport, plus the previously retained subset. A bounded nearest-candidate heap per path cost retains at most 470 candidates before final distance/ID ordering; camera changes never read or sort the complete selection. Selection membership is cached for the stable gesture ID array; its IDs, membership slots, and retained subset count toward active preview memory and are released with the preview. Small selections retain their offscreen behavior; large selections without a viewport wait for measured context. The remaining selected elements use aggregate bounds during the gesture and receive the same canonical transform once on commit.
- Export and saving always use the complete store.

This allows the 10,000-stroke acceptance document to remain interactive without mounting every complex SVG path at the same time.

Membership-delta storage is bounded by document capacity, independently of the 192-root DOM-publication limit. Changed retained ranks use the complete band sort. Unchanged membership keeps its sort bypass. Eligible fringe queries can retarget an ongoing publication pass while retained ordering remains valid. Unsupported order state and partially detached repairs retain the full reconciliation path. Band arrays are built once per changed target; exits are collected in that pass, and commit adopts the resulting array reference. Published arrays are immutable to pending reconciliation. Full sorting creates replacement arrays, leaving prior committed and pending snapshots intact.

Eligible membership-only changes reuse retained DOM order and stage entrants and exits, including during an unfinished retargetable publication pass. Exit IDs come from visibility-buffer cleanup rather than another full mounted-node scan. Retained nodes are not rewritten solely to refresh their order epoch. Preview-protected exits are rechecked when preview ownership changes. Boundary-strip queries classify deduplicated fringe candidates for overlapping envelopes. Both fringe and full candidate acquisition use the generation-safe spatial query cursor; actual cell, membership, and record visits stop at the shared deadline and retain bounded cursor state. A target or index-generation change discards stale acquisition. Exact record classification stages privately and exposes no partial membership. Fresh acquisition and exact filtering share one admitted record step when no earlier filter backlog remains. Acquired records, including prior exclusions, remain reusable within the same candidate generation; a bounds retarget over the same cell range resets only the exact-bounds filter cursor and rechecks current bounds under the shared deadline. Candidate or index generation changes, order invalidation, and release discard this classification cache. The last record or index visit cannot start membership adoption after exhausting the deadline. Final marker and array-reference adoption, sorting or merging, and reference cleanup remain synchronous bounded operations admitted only with remaining budget; they do not establish a maximum physical frame duration. Their actual slot/rank work and the preceding indexed/record visits have deterministic regression bounds. Wide elements and dense cell collisions may still visit many indexed memberships, and finalization can still traverse the logical visible IDs. Cursor buffers and deduplication ownership count in active-document resource accounting and are released on cancellation and disposal.

Numeric rank shifts caused by removals or insertions do not reparent retained nodes when a completed reconciliation scan proves their relative order is unchanged. A completed full reconciliation refreshes the retained order proof during the existing committed-visibility adoption; partial publication and cancellation do not stamp a completed proof. Preview nodes, animation tombstones, and crossfade nodes count toward the mounted-node ceilings.

## Path Caches

After required visibility, mounted changes, and previews settle, the scene may prepare missing stroke contours in a bounded leading strip in the latest scroll or horizontal-pan direction. The strip extends half the current envelope along the dominant axis and examines at most 256 indexed candidate IDs per target; this bounds speculative region capacity, not CPU work per slice. Cache hits, non-strokes, and candidates already inside the visible envelope are skipped. If worker preparation is available, the scene sends the remaining eligible IDs in one speculative `prepareScenePaths` batch, capped at 256 IDs and 4 MiB of contour output. Progress and terminal delivery coalesce into at most one background-priority navigation callback without rerunning the complete scene frame. The main thread adopts complete contours into the existing 25 MiB scene path cache under the same original injected `WorkScheduler` deadline; it creates no SVG nodes, export fragments, or metadata. It does not poll for worker completion, renew a deadline, or run a separate timer or scheduler. Initial activation, live input, and memory pressure disable this speculation. Required scene work, model synchronization, input, or navigation preempts it in the bridge, worker, and main-thread fallback. Stale geometry versions, model revisions, and worker epochs cannot be adopted. Retargeting or cancellation aborts the current request and releases its retained IDs and payload immediately. Cancellation and disposal release all cursor, contour, and request ownership. This background work may use only the remaining navigation-frame budget; export and persistence keep their own input-priority rules.

The cache never exceeds its byte ceiling by moving entries into a cleanup queue. Subsequent requests exclude locally reusable contours and retain at most one in-flight request. ## Background Geometry Cache

Each presentation owns one namespaced `userSpaceOnUse` SVG `pattern`, one bounded tile, one current coverage path, and one optional terminal-edge path. A shared domain layout derives the fixed inner frame from the page margins for active rendering and standalone serialization. The repeated tile keeps the requested spacing and top-left phase. A non-divisible final interval is closed exactly at the immutable right or bottom frame edge by the terminal path instead of resizing or shifting the frame. Lines, Dots, and Squares share the absolute 25, 100 / 3, 50, and 100 page-unit series without type-specific multipliers or buffer-dependent scaling. Squares retain all four boundaries, Dots use the exact corresponding square intersections, and Lines retain only horizontal guides. Floating-point interval counting recognizes the 100 / 3 step as an exact three-way subdivision of every canonical 100-unit layout row. The coverage path extends by half the current screen-space stroke width so SVG fill clipping cannot remove a terminal guide or dot. Guide paint uses normal SVG antialiasing and one shared 25-percent-alpha, scheme-specific neutral instead of `crispEdges`. The pattern stroke width is derived from current zoom rather than browser support for `vector-effect` inside pattern content.

The locked surface does not use an externally scaled CSS image because Chromium applies that outer image scale after SVG non-scaling-stroke evaluation, producing subpixel guide widths and phase-dependent intensity. Recognition time-slices strict safe-envelope inspection, retains validated source only in an LRU cache bounded to 256 entries and 32 Mi code units except for one individually valid larger document, and imports presentation markup only for a recognized visible block. Before import it removes the potentially large editable metadata and standalone stylesheet. A refreshed source and its aspect ratio are adopted atomically from the same validated SVG bytes, and `xMidYMin meet` prevents non-uniform distortion if host geometry is temporarily inconsistent. The resulting inert SVG owns the fitted viewport directly; scoped light/dark rules then apply the same guide color and non-scaling stroke as the active scene. No React root, event handler, pointer target, object, iframe, script, URL-bearing SVG node, or native image exists in this path.

The geometry cache key is `{ backgroundType, spacing, innerWidth, margin, pageHeight, guideBounds }`; theme, viewport, and camera pan are not part of it. A page or background change atomically replaces this single geometry entry and releases the previous strings. Viewport clipping, scrolling, toolbar reflow, and pure container-height animation perform no background build. Zoom updates only the screen-space stroke and coverage inset. A discrete spacing preview replaces active pattern and terminal geometry atomically while preserving active page height, container height, camera, and native scroll position. Committing it updates the derived locked target used by the next save and lock.

All individual cache caps are maxima, not reservations. The active-document memory ceiling in [Quality and Testing](quality-and-testing.md) overrides them and forces earlier least-recently-used eviction.

## Page-Height Rendering Handoff

Automatic active-page growth and shrink use one bounded 180-millisecond animation-frame transition owned by the layout adapter. Selection moves and geometry-handle gestures may coalesce a larger writing-row-aligned preview target into that transition, never request a smaller target during the gesture, and do not acquire passive scroll stabilization while pointer or autoscroll input owns scrolling. A time-sliced handle commit retains its reservation until completion. Cancellation returns to the captured original height, while the scene surface never falls below the current Store-derived extent. Commit reconciles against both the Store-derived maximum bottom and the final rendered preview bottom and cannot settle below either extent. The SVG scene is pinned to a writing-row-aligned height at least as large as the settled, transitioning, queued, preview, and committed-content requirements, remains top-anchored, and is clipped by the outer rounded background container. React does not participate, and no content node is recreated merely because page height changes.

For growth, the renderer receives the complete aligned target envelope first. The container remains at its current height until the renderer reports a complete scene commit and that committed scene has remained available for one paint opportunity. Only then does the outer container reveal the already complete scene. Intermediate frames change clipping and visibility only; background geometry does not follow the viewport.

For shrink, the renderer retains the aligned larger page surface while the outer container clips it. Clip-driven viewport measurements update visibility and culling but never rebuild background geometry. Once interpolation reaches the target, one final scene commit applies the smaller aligned page and exact outer height together. Rapid direction reversals recompute the envelope from the currently visible CSS height instead of a stale settled target. A presentation-level hold suppresses browser scroll anchoring, samples one visual root anchor in constant time per frame, corrects only measured drift, retains the hold through two settlement frames, and defers repeated host measurements. If a lock begins at the native bottom and its final shrink would make that root anchor unreachable, the presentation preallocates the complete additional scroll range before the first animation frame, including any trailing host content between the embed and the scroll extent. A still-required range reserve transfers from the editor to the mounted presentation before editor disposal, without retaining scroll-anchor suppression. Deliberate Wheel, Touch, or keyboard scrolling releases it; a subsequent unlock adopts it and removes it as soon as the recovered natural range can preserve the same root anchor. A new gesture, reduced-motion change, lock, or disposal resolves or cancels the bounded transition without leaving a pinned scene envelope or active stabilization hold.

Eraser feedback animates opacity and a CSS blur on existing mounted paths, or once on the existing pressure-stroke group. It creates no geometry, clones, timers, or JavaScript animation frames. CSS keyframes explicitly start at zero blur and the element's base opacity, then end at the width-dependent inline blur target and zero opacity with forwards fill; they do not depend on a previously painted transition state. The blur follows page-space zoom; duration and radius are defined in [Editor Tools](editor-tools.md#eraser). Cancellation clears both effects immediately, and reduced motion hides ink without applying a filter. Browser-owned filter rasterization and GPU memory are not covered by deterministic work counters and require device verification.

An element that has reached eraser-removal feedback remains hidden until its successful removal delta detaches the mounted node. That delta consumes the fade, suppresses an exit tombstone, and makes a later generic fade cleanup a no-op for the removed ID. Failed or cancelled removal restores the existing element normally.

## Ordering, Snapping, and Connections

The renderer derives the highlight and content bands from element kind and mounts each band in snapshot order. An arrange command updates only stable rank data and the affected visible SVG child order. It does not rebuild paths, bounds, or spatial-index cells. Hit testing and equal-distance snap candidates use the same front-to-back ranks.

Endpoint snap lookup queries the existing spatial index with a page-space square that encloses the input-specific screen radius. It generates anchors only for eligible returned targets, then compares exact screen-space distance. Line and arrow endpoint anchors include other line and arrow endpoints, while self-targets and cycle-forming targets are excluded. Creation, endpoint editing, and movement of a single selected line or arrow reuse this lookup. Multi-selection movement and resizing do not acquire semantic targets; group movement skips endpoint candidate searches entirely. It never scans the complete element array. Line and arrow creation and endpoint edits also apply an absolute 90-degree angular snap, while coordinate-system axis and origin edits apply an absolute 45-degree angular snap using a five-CSS-pixel threshold converted through zoom. Origin editing evaluates every fixed axis endpoint, chooses the closest candidate, preserves each endpoint in world space, and emits a guide for every other axis that satisfies the same threshold at the resolved origin. A bent element suppresses the angular chord guide until the prospective rendered curve reaches the same straightness threshold. Straightness remains a gesture-local preview derived from the immutable start geometry; only pointer release in that state persists `bend: null`. Plain connection-target crosses, angular guides, separator guides, complete rotation-axis guides, and bend chord guides share one overlay path outside the camera group and remain screen-sized. Marker dimensions, dash style, and the minimum visible length for angular feedback follow [Editor Tools](editor-tools.md#line-and-arrow-connections). Separator and bend guides use only their guide axis and add no marker cross. A rotation guide follows the bounding-box handle axis through the rotate handle, its adjacent box anchor, and the opposite box anchor instead of using an offset element pivot. Guide extensions are applied after page-to-screen conversion and remain visually constant at every zoom level and device-pixel ratio. Snap feedback updates without an exit transition and clears in the same input frame that releases the candidate.

Eligible target anchors use a main-thread LRU keyed by target ID and `geometryVersion`. Entries store only canonical semantic anchor identifiers and page-space coordinates. Paint, order, selection, and theme changes are cache hits. Geometry replacement or target deletion releases the old entry. The cache is capped at 4,096 targets and 8 MiB, whichever is reached first, and the active-document memory ceiling may evict earlier. Candidate lookup still performs exact screen-space distance and deterministic tie resolution on every gesture frame.

The store maintains one derived reverse connection map keyed by target ID. A gesture constructs its affected acyclic dependent order once from that map, then each pointer frame resolves only the cached selected linear targets and ordered dependents. Commit replaces the target and affected linear records, recalculates their shared bounds, and updates their spatial-index entries atomically. Dependent linear targets are propagated through a bounded queue until the complete downstream chain is resolved, without rescanning the store. Unchanged dependents retain stable identity. The map is rebuilt once during validated document load and maintained incrementally thereafter.

## Spatial Index Bounds

The sparse uniform grid uses 256-page-unit cells. An element is inserted into every intersected cell only while that requires at most 256 cells. A larger element is stored once in an overflow collection, never expanded across all covered cells. The file format caps that collection at 512 elements and caps all retained grid memberships at 262,144 cells per document. Store construction, clipboard adoption, insertion, and replacement preflight the aggregate before allocating cell buckets. Every query checks intersecting grid cells and the overflow collection, then performs exact conservative-bounds rejection. Removal and geometry commits update the index atomically. Adversarial million-unit strokes and shapes are covered by the performance fixtures.

For every non-overflow element, the index retains its current cell keys so removal and replacement never scan grid buckets. Each interaction reuses owned candidate and deduplication scratch buffers instead of allocating full-store arrays or one result set per cell. Selection stores IDs rather than copied records. Its bounds and overlay primitives are calculated when membership changes and transformed algebraically with the same move, scale, or rotation preview applied to content; pointer frames allocate no replacement records. Non-empty overlay path replacements during a gesture update geometry directly without restarting entrance motion, so the overlay remains visible and synchronized with the content preview. A single line or arrow keeps its three canonical handles instead of a conservative spatial-index bounding box. Selection centerline indicators are separate from selection-frame fill. The visible selection contract is defined in [Editor Tools](editor-tools.md#select). Highlight preparation and camera-independent rendering follow [Selection Highlight Geometry](#selection-highlight-geometry). Closed-shape and group overlays retain the translucent accent fill. Their bounding-box border is a centered, non-scaling 1.5-CSS-pixel stroke on the geometric frame, without paint-width expansion or an inset clip. Frame bounds, handles, hit testing, and resize calculations share this geometry. Degenerate frames do not gain a minimum geometric extent. Handle hit radii are pointer-type and zoom dependent while their visible circles remain screen-sized. Rectangle and bounded freeform-lasso selection query the index once by area bounds, then apply the configured visible-geometry touched or fully-enclosed predicate only to returned candidates. Lasso sampling is owned by one editor session. It consumes a coalesced frame batch before one overlay write, keeps a maximum of 512 screen-error-bounded points, and uses an explicit even-odd fill rule in both rendering and hit geometry. The active-canvas input boundary similarly preserves ordered freehand and eraser samples across raw S Pen events while limiting live geometry and feedback publication to one update per animation frame. Freehand tail geometry is rebuilt once after each admitted batch rather than once per raw sample, and eraser candidates found across the batch are published through one incremental fade update. Endpoint-only creation previews retain only the latest sample. The shared pending batch is bounded to 4,096 samples with deterministic endpoint-preserving compaction, flushes synchronously before commit, and is discarded on cancellation. The maximum 4,096-sample browser batch is covered by the strictest interaction budget.

Prepared structural mutations stage removal and insertion checks through the injected scheduler. A local patch is retained only while its estimated atomic work stays within 1,024 units, accounting for cell memberships and overflow/heap work. This selects an algorithm; it never forces a frame wait. Larger patches build a private replacement index under the same scheduler, reusing immutable retained bounds and cell keys. Commit adopts the prepared index state atomically instead of repeating cell and heap changes. Cancellation or a changed source generation discards the preparation. The temporary replacement duplicates index structures until adoption or release; it does not duplicate stroke samples. Record, capacity, and reverse-connection publication remain separate Store work, so this is not a constant-time guarantee for the whole command.

The same index owns a versioned maximum-bottom heap for page extent. Geometry replacement pushes one new `(bottom, id, recordVersion)` entry; extent lookup lazily removes at most 256 stale heads per frame and compares a valid head with overflow bounds. While cleanup remains, page height may conservatively overestimate but never underestimate content. When stale entries exceed the live indexed count, a time-sliced rebuild replaces the heap. Bulk replacement preparation also builds the maximum-bottom heap cooperatively, checking cancellation and the shared deadline after each bounded sift; it does not heapify the entire replacement set in one uninterrupted preparation step. Page growth, shrink, and deletion of the lowest element therefore never scan the complete store or create an unbounded cleanup task on an interaction frame.

A handle-based selection transform affecting more than 1,000 elements, more than 16,384 aggregate geometry samples, or more than the synchronous reverse-dependent budget materializes only changed immutable records plus incremental spatial-index and reverse-connection patches in input-aware slices while the final preview transform remains visible. Scale previews preserve every visible line and outline width through retained affine stroke transforms or canonical shape replacements as defined above. Clearing or committing the gesture discards obsolete preview work and publishes only complete canonical replacements. Box-resize previews derive each box pivot from the rounded top-left and dimensions, so the committed pivot is always the canonical bounds center. Reverse-dependent counting stops as soon as a budget is exceeded and never scans the complete store. Draft construction, connection propagation, candidate classification, and patch preparation each check the same gesture generation and cancellation token before and after every yield. Preparation leaves the authoritative map, index, reverse map, and unchanged record identities untouched. The final synchronous transaction rechecks and consumes its one-shot token, applies only the prepared patches and publishes one delta. Presentation retains the committed preview basis across frames while one versioned progressive job prepares replacements. Each completed path swaps atomically with its transform correction; a new gesture composes with the retained basis, and a newer canonical preview waits until that basis is ready. Both synchronous and sliced model commits use this handoff, so pointer release and autoscroll completion cannot expose an intermediate untransformed frame. Retained transform strings, deferred IDs and the active geometry job count toward preview memory. Cancellation or stale work discards the detached patches. No partially transformed store is observable. A translation initiated by dragging selected content retains only the latest sample and performs snapping, connected-preview propagation, overlay geometry, and page-extent work at most once per animation frame. Browser-coalesced S Pen batches bypass per-sample preview iteration, and pointer release synchronously flushes the latest pending sample. The same sliced commit path remains in use above 1,000 elements; its transform-only preview does not require per-element sample materialization. The outer active-canvas container is the sole visual clip for the imperative SVG scene. The SVG viewport remains overflow-visible inside that container, allowing preserved off-page geometry to become visible during an inward transform preview instead of only after commit.

## Selection Highlight Geometry

Each scene owns retained centerline indicators for mounted selected elements. Pressure strokes prepare a centerline from the smoothed input samples through the bounded ordinary centerline simplifier, without reconstructing pressure outlines. One pressure indicator build is synchronous, bounded by the 16,384-sample document limit and 64-segment simplification windows; the scene scheduler yields between element updates, not within this build. Its actual single-stroke latency still requires device verification. Constant-width strokes, highlighters, and shapes reuse geometric center paths. Filled arrow decorations contribute their logical polygon or circle contours without paint-width expansion. The visual contract belongs in [Editor Tools](editor-tools.md#select).

Indicators use non-scaling SVG strokes and preserve original document paint. There is no selected-ink union, morphology filter, silhouette clip, or camera-dependent indicator geometry. Camera-only updates reuse paths; movement and rotation reuse transforms. Geometry and preview changes update affected indicators through the scene scheduler, while essential frame and handle feedback remains independent of pending preparation. Each indicator uses one SVG path directly in the decorative group, with geometry and paint prepared before attachment. Only complete indicator paths are mounted. The shared deadline limits actual geometry preparation and bookkeeping; cached centerlines, unchanged trace geometry, and reused constant-width paths incur no synthetic sample-cost charge. Cache lookup results are passed into the update so an admitted hit or miss is not looked up again. Deadlines and the live-root allowance still apply. New indicators and progressive content publication share the per-frame live-root allowance; their queues alternate priority, while already mounted indicator updates keep immediate gesture feedback.

Retain indicators only for mounted selected elements and account for their geometry and SVG resources in scene memory. Culling, deselection, disabling optional highlights, and scene disposal release their owned nodes. ## Document Worker, Autosave, and Export

Compact stroke metadata decodes directly into exact-size numeric buffers under the [disk-format contract](file-format.md#disk-metadata-encoding). The bounded parser attaches a single-use proof of finite JSON numbers, node count, maximum depth, and maximum container width to its exclusively owned parsed root. Complete semantic schema validation consumes that proof only for the exact root and applicable limits, avoiding a second generic JSON-tree traversal. Compact decoding may bind decoded sample extrema to the same proof and exact buffer identity; semantic validation consumes that numeric proof once only after the matching root proof succeeds. Point-count, aggregate-capacity, current coordinate-limit, translated-extrema, geometry, ordering, and connection checks remain. Absent, consumed, mismatched, or inadequate proofs retain the complete structural or numeric validation path. Compact decoding preserves the parser-owned root identity.

The serializer also retains validated original `json-varint-v1` sample strings in its session-owned LRU encoding cache, capped at 20,000 entries and 32 MiB. It may reuse an entry only for the exact immutable current-model point-buffer identity; header-only edits preserve that identity, and reset reconciliation retains only entries that still match it. Changed samples, removal, migration, and disposal invalidate or exclude entries. Failed or cancelled parsing never publishes staged encodings. Raw point values, canonical file output, full metadata assembly, and output hashing remain unchanged.

Element fragments retain prepared UTF-8 bytes for their metadata and SVG content. Their string properties decode lazily for callers that need strings, while output assembly consumes the retained bytes directly. Unchanged fragments therefore avoid another UTF-8 encoding pass; changed fragments are rebuilt under the existing validation, cancellation, byte-capacity, and hashing rules.

Trusted hydration transport reuses worker-validated numeric samples without another complete point-value scan. Receiver validation still requires exclusive full-span typed buffers, exact batch identities and totals, per-stroke and aggregate sample capacities, derivation alignment, detached ownership, and terminal success. Stroke bounds include validated local bounds; Store hydration reuses them only after checking their consistency with world bounds and the retained offset. Concurrent safe-suffix inspection and one cancellable staging task may overlap; failure in either path cancels and settles staging before its records are released. At most one unacknowledged batch is staged, retaining the 256-element and 4-MiB transport caps. No partially validated store or input surface is published.

Every committed content change schedules:

- incremental export and save after 1,000 milliseconds of content inactivity

There is no periodic full-snapshot export. The validated unlock state initializes the worker baseline, and only a gap, restart, timeout, invalid order, validation failure, or explicit mismatch recovery permits another full snapshot. A current incremental-export failure immediately requests one full-snapshot recovery without waiting for another edit. A failed full recovery remains in retryable-error state and does not schedule an unbounded retry loop. A recovered output does not write the vault file again when the same revision is already confirmed and its output hash matches.

Camera, zoom, scrolling, focus, hover, and animation changes do not dirty the file. If drawing or transforming is still in progress, saving waits and checks again every 200 milliseconds until the gesture transaction commits or cancels.

The single document worker starts when a document session begins unlocking and remains owned by that session lifecycle, including a detached-save lease. It terminates only after the session is clean and released or recovery reaches a confirmed terminal outcome. There is no worker pool, per-window worker, renderer worker, or second document worker. Before a full read, the main thread rejects a `TFile.stat.size` above the total file limit. The guarded `Vault.readBinary()` starts concurrently with asynchronous worker bootstrap; an activation cancelled or disposed before that work starts performs no read. The first executor consumes that one input buffer, and executor recovery performs a fresh read rather than reusing potentially transferred or stale bytes. Ownership transfers directly to the worker. The worker incrementally decodes UTF-8 chunks through one bounded non-networked XML tokenizer. It retains only the bounded root and metadata text and hashes the original bytes incrementally. A normal unlock checks each static group against the safe SVG allowlist without regenerating contours and discards supplied static path text before decoding the next chunk. A current preview proof skips only this repeated static scan; proof ownership and byte-mismatch failure are defined in [Snapshot-Authoritative Unlock and Output Reuse](decisions/validated-unlock-geometry-reuse.md). The worker never joins the complete SVG or keeps static input ranges. The worker and main-thread fallback use the same bounded chunked JSON parser, enforcing structural width and depth before decoding another object key or appending another container entry. Strings decode through one reusable 16,384-code-unit scratch buffer. It then performs schema validation and all remaining limits. The input buffer, metadata string, and parser scratch are released at the earliest stage that no longer needs them. With an available worker, metadata, schema, and static scans remain executor-owned; the main thread may hash all freshly read bytes under the central scheduler solely to match current preview evidence before transfer.

The worker is also checked as an isolated TypeScript program starting at `src/persistence/worker/runtime/document-worker-entry.ts`. Its compiler environment contains only `ES2021` and `WebWorker`, with no DOM, `Window`, React, or Obsidian types. The main-thread `worker-factory.ts` remains outside that entry graph because it legitimately creates `Blob`, `URL`, and `Worker` objects through the owning window. This entry-based check complements the architectural import rules without rejecting valid worker platform APIs such as `self`, `MessageEvent`, `TextEncoder`, `Transferable`, `AbortController`, timers, and `crypto`.

When a validated snapshot uses an older supported version, the same worker applies the sequential pure migrations to its parsed representation before creating runtime batches or an export baseline. Migration revalidates the resulting current-version schema and limits. A stale activation generation, migration error, or post-migration validation error publishes no partial runtime state and leaves the original file unchanged in a read-only static state. The first later write still follows the backup rule in [File Format and Geometry](file-format.md#versioning-and-migration).

The static preview stays visible while the worker builds immutable snapshot fragments and converts each stroke into one worker-owned canonical `Float64Array`. Parser-owned snapshot copies reuse sample validity only when the validation derivation matches the exact source sample buffer and its cached extrema. Copying retains ownership, size, cancellation, and scheduler boundaries; it does not repeat the numeric sample scan. Unproved copying paths retain validation. The completed snapshot validation calculates each element's conservative bounds, spatial membership count, overflow classification, and document maximum bottom in the same pass that enforces those limits. That revision-bound derivation bundle is transferred beside the corresponding runtime element batches and is adopted by the worker serializer and detached main-thread store builder. Both receivers recheck element IDs, finite ordered bounds, batch alignment, and spatial-capacity consistency, but they do not rebuild element geometry merely to rediscover the same bounds. The spatial index still constructs its required cells from the validated bounds. After metadata structure, schema, sequential migration, root version, revision, and derived locked height validate, the worker may begin transferring hydration batches while it continues checking the remaining supplied static groups for safe structure and resource limits unless a trusted proof is supplied. These batches are staging input only: the main thread appends them to a detached builder, applies backpressure per batch, and cannot publish a store, enable input, or hide the static preview before the terminal result confirms either a complete safe scan or an exact proof match, exact batch totals, and the source hash. A later mismatch, cancellation, stale identity, derivation mismatch, or terminal-count error cancels the builder and releases every staged record. Each transfer uses distinct typed-buffer copies capped at 256 elements and 4 MiB, whichever is reached first, and never transfers the worker-owned regeneration source. The main-thread receiver independently verifies both limits and adopts only exclusive full-span buffers, then time-slices index construction and publishes no partial document. The first interactive frame waits for all validated runtime records, the complete index, and visible paths, not for complete static export geometry. The worker builds remaining static-SVG fragments at background priority, then releases legacy parsed point arrays as soon as the canonical buffers exist. This initializes the export baseline without a second JSON parse, a second complete snapshot validation, or duplicate bounds construction; both canonical buffer copies and the transient parsed representation count toward the memory ceiling. Page-only editor commits validate this hydrated runtime representation with the runtime-aware schema path, preserving the same strict numeric, geometry, connection, capacity, and extent checks while accepting exclusively owned `Float64Array` stroke samples. They do not convert every unchanged stroke back to a JSON array merely to change page background settings. Shape records may use structured clone in the same bounded batches. If the Worker API is unavailable or construction fails, the session uses the same pure operations in the bounded fallback defined below and reports fallback unlock timing separately. The worker:

Unlock publishes only after matching operation identity, sequential bounded batches, terminal batch and element counts, and detached Store ownership, render-band, and rank checks. Worker-validated elements cross the trusted structured-clone transport without a second canonical serialization or content hash on either side. The receiver checks cancellation and yields while proving that the finalized Store owns the exact received element objects in the expected order. External SVG and metadata validation remains at ingestion. Stale operations, missing or duplicated batches, count divergence, and invalid Store adoption discard the detached builder. The one-time executor recovery may restart unlock under a new worker epoch; no partial Store becomes interactive. Canonical integrity manifests used for export remain a separate contract.

- validates and migrates the file during unlock before runtime publication
- initializes from the validated unlock snapshot and receives a complete snapshot only for recovery
- serializes and validates clipboard payloads, including paste limit checks and operation-local ID remapping
- subsequently receives only changed or removed elements for SVG export
- keeps its own bounded outline and serialized-fragment caches warm
- hashes and validates preflight and read-back file content
- discards results whose session, worker epoch, or operation identity is stale

Every worker message is checked for protocol and lifecycle correctness at the receiving boundary. The worker runs plugin-owned code; its structured-clone transport is not a second external-file ingestion boundary. Before adoption, the main thread validates the purpose-specific discriminator and identity, ordering and batch totals, exclusive full-span `ArrayBuffer` ownership, and the applicable element and byte limits. A complete export result remains ineligible for `preparedSuccessor` or persistence until bounded owned-output adoption and the independent Store manifest checks below succeed. A verification response instead remains bound to the exact submitted file hash and revision. Unknown external SVG still requires its full safe-envelope inspection. Any failure invalidates the result without publishing runtime state or writing it.

Persisted-output verification retains at most two executor-local scalar `{ outputHash, revision }` proofs: one accepted canonical input identity and the latest successful export identity. Safe snapshot-authoritative unlock does not seed either slot. Each verification hashes the complete newly supplied bytes in bounded, cancellable slices and enforces the input byte limit. It may match an executor-owned proof or caller-owned confirmed-base proof supplied only for that request; the confirmed base is not retained in another executor slot. A miss follows full canonical parsing and validation. Initialization, clear, and executor replacement invalidate executor-owned proof state. Neither slot stores SVG, metadata, or geometry. Save-operation identities, exact-base conflict checks, serialized writes, and mandatory read-back remain unchanged. Successful serialization is trusted for an own-export hit, so canonical parity and regression coverage protect against serializer defects. The detailed proof and verification boundaries are in [Snapshot-Authoritative Unlock and Output Reuse](decisions/validated-unlock-geometry-reuse.md).

Unlock preview-proof reuse and autosave confirmed-base verification follow the [canonical reuse decision](decisions/validated-unlock-geometry-reuse.md). Host reads, file identity checks, and the independent authoritative Store-to-export integrity check remain required under [Obsidian vault verification](obsidian-integration.md#vault-file-and-link-apis).

Confirmed-base autosave preflight reuses the native WebCrypto helper inside the existing document worker for UTF-8 inputs up to 20 MiB; the workspace own-event fallback retains the same helper. Encoding checks the injected scheduler and cancellation between at most 64 Ki code units without splitting surrogate pairs, and exact host byte count must match before native digest dispatch. ASCII input uses one temporary byte buffer; multibyte growth can temporarily retain at most 40 MiB of owned buffers, excluding the source string and browser-internal digest copies. No complete-file buffer is cached. Content or known byte count above the native limit uses the existing bounded streaming hash; crossing the byte limit during encoding can discard at most 20 MiB of preliminary encoding before streaming restarts. Missing WebCrypto and native digest failure retain exact SHA-256 with cooperative checkpoints; digest failure reuses the encoded bytes with 64 KiB hash steps. Cancellation and current operation and host identity are checked after native completion. Unlock candidate binding remains on its existing sliced hash path. The 64 MiB file limit, confirmed-base equality, conflict handling, and 1,000-millisecond inactivity debounce remain mandatory.

Before an export can become a prepared save, the worker derives a new integrity manifest from its canonical model before output assembly, while the main thread independently derives the expected manifest from a fresh snapshot of the authoritative Store with the current page and revision. The receiver requires an exact manifest match and requires the inspected SVG envelope's snapshot hash to equal the manifest content digest before any Vault preflight or write begins. The first Store-to-worker manifest divergence discards the output and permits exactly one complete Store snapshot to rebuild the worker baseline and retry the export. A repeated manifest divergence enters executor-failed recovery, preserves the original file unchanged, and performs no `Vault.process()` call. A malformed canonical root, invalid hash spelling, revision mismatch, or envelope-digest mismatch rejects that exact output through executor recovery without writing it. The bundled worker and fallback serializer are trusted internal producers: receiver adoption decodes their bounded UTF-8 output and checks the root without repeating full SVG allowlist scans or SHA-256 hashing. Internal save entry points consume only these canonical outputs; external SVG validation is unchanged. Exact actual readback and conflict checks remain mandatory, as detailed in the [reuse decision](decisions/validated-unlock-geometry-reuse.md). Recovery-copy export applies the same Store-to-worker manifest and envelope-digest checks before creating a candidate file.

The worker's `modelRevision` is the document revision of its atomically applied canonical records, order, page state, and fragment dirtiness. It is independent of the main thread's last vault-confirmed revision and does not imply that SVG output has been assembled or persisted.

Clipboard API access remains on the main thread because it depends on browser user activation. On Paste, it accepts at most 256 clipboard items but inspects supported representations only on the first item. A later Inkbook item never overrides an unrelated first item. Before the first `Blob.text()`, it rejects any first-item representation above 8 MiB and a combined custom-plus-plain budget above 16 MiB, then verifies decoded UTF-8 bytes again. An over-limit system clipboard does not fall through to an unbounded `readText()` call and changes no editor state. For Copy or Cut, the main thread constructs a `text/plain`-only `ClipboardItem` and starts exactly one `navigator.clipboard.write()` during the same activation. Its data promise resolves to the worker-produced prefixed payload, which contains the complete validated Inkbook selection. The standards-prefixed custom format remains accepted on read for compatibility but is not written because a platform may reject an otherwise valid multi-format write when that optional type is unsupported. The validated worker payload becomes the in-session fallback before the system-write outcome can affect clipboard-operation availability. An unresolved system write never blocks in-session Paste. A rejected standard write retains that fallback and reports that the system clipboard is unavailable; no late unauthenticated retry is attempted. A later settled success may only update which source is authoritative. Before the codec runs, the main thread synchronizes the complete revision delta not yet present in the worker, including changed records, removals, render-band order, and page state, through the same bounded protocol used for export. This atomically advances `modelRevision`, updates or invalidates the affected snapshot and SVG fragments, and marks that model revision as needing output; it does not acknowledge an export, clear dirty state, or remove the scheduled save target. A later export at the same `modelRevision` may therefore assemble correct complete output with a zero delta. Copy and Cut then send selection IDs rather than cloning a complete selection, and the worker returns the custom and `text/plain` payloads from its current canonical records.

Every clipboard request and result carries `{ sessionId, workerEpoch, clipboardOperationId, basisRevision }`. Paste transfers the untrusted clipboard bytes or text to the worker, which parses, validates, remaps IDs and internal connections, applies the requested placement, and validates resulting document limits before returning immutable insertion records. Transferable stroke buffers are converted back to JSON-compatible point arrays at the paste-plan wire boundary before Store insertion. The main thread rechecks all four identity values and current document limits against attachment state, not the temporary input-disabled operation state, before one atomic paste command. A stale Paste result changes nothing and is recomputed from the current revision if the user action is still pending.

Only the worker's validated model at the exact clipboard basis revision may supply retained page and aggregate-capacity facts to Paste. This path queries existing IDs directly instead of materializing or rescanning the complete model. Clipboard decoding, generated-ID collision checks, translated insertion bounds, document limits, and connection fanout still validate the new records. Direct paste planning without those model facts retains the complete existing-document check. If an export advances the internal model but fails before confirming output, published and internal revisions diverge; both old and new clipboard bases are rejected until full synchronization or recovery.

Cut additionally captures the exact selected IDs and each selected record's identity or `geometryVersion` and `paintVersion`. After the exact payload reaches the system clipboard or the validated in-session fallback, and immediately before removal, the main thread rechecks the session, worker epoch, clipboard operation, basis revision, current selection, and every captured record. If any value changed while the presentation remains active, the copied payload remains available but no element is removed, no Cut history command is created, and attached feedback reports that Cut stopped because the selection changed while the copied elements remain available. A detached or disabled presentation adopts no stale feedback. Only a fully current operation removes the captured selection in one command.

Activation does not request eager whole-document fragment prewarming. Visible scene preparation has priority; fragments are generated on demand by export. The worker runs one non-preemptive job at a time. Unlock validation and migration are exclusive until activation completes. Thereafter required lock, recovery, preflight, and read-back work has priority, followed by one explicit clipboard operation, a due coalesced autosave export, and background fragment prewarming. A second clipboard action cannot start until the first reaches a terminal result, and UI availability reflects that state. Export retains its single coalesced successor below; background work is interruptible and retains no queue entry. This bounds queue length and prevents background work from delaying data-safety operations.

DOM creation and mutation, React, pointer arbitration and capture, live-stroke construction, camera and scroll handling, layout, viewport culling, hit testing, snapping, the spatial index, command history, Vault and Clipboard API calls, and Obsidian lifecycle work remain on the main thread. Moving them into a worker would duplicate authoritative state, transfer viewport-sensitive data per frame, or add latency to the live-input path. Pure stroke translation checks scheduling between elements and reuses unchanged samples without charging a hypothetical sample-traversal cost. The initial spatial-index build, a selected-content translation above 1,000 elements, and a handle transform above either its 1,000-element or 16,384-sample cap remain input-aware main-thread slices unless concrete work/resource failures or physical-device profiling justify changing this boundary.

Worker result identity is separated by purpose. `workerEpoch` identifies the current worker instance or synchronous-fallback executor and changes only when that executor is replaced or invalidated. `exportGeneration` is a session-local safe-integer counter incremented only when an SVG export is dispatched, and that dispatch assigns `newestDispatchedExportGeneration`. An export result not yet admitted to persistence occupies at most one replaceable `preparedSuccessor` slot. Admission creates the single non-replaceable `activeSaveOperation`, whose `saveOperationId`, revision, complete-output hash, and write phase remain unchanged through preflight, `Vault.process()`, and read-back. Unlock, migration, clipboard, background, and verification recovery use their own operation IDs and never advance `exportGeneration` or replace an active save. Timers and queued work own none of these identities; merely scheduling or firing the 1,000-millisecond timer never invalidates in-flight work.

Revision is a non-negative safe integer and increments exactly once for each committed content or page change, including Undo and Redo when they alter persisted state. Session-only changes and no-op history traversal do not increment it. Reaching `Number.MAX_SAFE_INTEGER` makes the document read-only until it is duplicated into a fresh revision sequence.

The main thread serializes worker state transitions. At most one export request, one `activeSaveOperation`, one `Vault.process()` call, and one `preparedSuccessor` may exist per document session. While export is in flight, later commits coalesce into exactly one pending target revision: changed elements use last-write-wins by ID, removals override changes, each band stores only a dirty flag, and page state retains only its latest value. The latest complete order for a dirty band is materialized exactly once when the successor dispatches, never once per intermediate reorder command. A baseline-invalidating condition upgrades that pending request to a full snapshot and never creates another queue entry. Export computation for a newer revision may overlap an active save's vault I/O, and its latest valid result may replace only `preparedSuccessor`; `newestDispatchedExportGeneration` never invalidates `activeSaveOperation`. No successor enters preflight until the active save finishes classification and updates the confirmed vault base. Writes to the same file remain serialized.

A full export request contains `{ sessionId, workerEpoch, exportGeneration, baseModelRevision: null, modelRevision, snapshot }`. An incremental export request contains the same identities plus `{ baseModelRevision, modelRevision, changedElements, changedElementDerivations, removedIds, orderChanges, page }`; a zero-delta export omits those delta fields when the worker already holds `modelRevision`. Each optional derivation belongs to the same delta and element revision as its changed record. Coalescing retains it only while that exact latest changed record remains authoritative; a later change without a matching derivation drops the stale value. The worker validates changed element fields and derives conservative bounds once as part of delta validation. A placement-only stroke change reuses validated sample facts and retained local bounds when shape identity matches; other changes recompute their bounds. An optional Store derivation must have the correct element identity, finite ordered bounds, and internally consistent spatial-capacity facts. If its bounds differ from the canonical recomputation, including floating-point rounding from translating retained bounds, the worker uses the recomputed bounds for aggregate capacity, page extent, fragment bottoms, and export. No epsilon permits a hint to change canonical capacity facts. Invalid hints or actual document-limit violations still reject the delta atomically without model advancement. This preserves delta protocol checks while eliminating later duplicate bounds calculations. Missing derivations safely use the same single geometry calculation. Page deltas receive isolated complete page-schema validation. Connection-affecting deltas receive complete aggregate-limit and semantic target, anchor, fanout, and endpoint-position validation over the already validated runtime records, without revalidating every unchanged stroke sample or recalculating every unchanged bound. `baseModelRevision` is the last canonical model revision successfully applied by the worker, whether through export or clipboard synchronization. `orderChanges` is empty or contains the complete ordered ID list for each changed render band. A result returns the same identities and model revision plus complete SVG output, output hash, or a structured error. The main thread assigns `saveOperationId` only when it admits a prepared export to `activeSaveOperation`.

Incremental wire requests may reference the confirmed model's existing stroke samples instead of transferring them again. The sender requires the exact immutable sample identity and matching session, worker epoch, and base revision. The receiver resolves only that model's existing stroke ID; missing or stale references fail. Full requests always transfer complete samples. A failed request does not publish a new reference baseline. Runtime point identity survives placement-only synchronization, allowing subsequent export to reuse its local contour. Validation still checks changed headers, offsets, effective coordinate limits, and aggregate capacity; previously validated sample extrema avoid rereading an unchanged owned buffer.

The worker accepts a state delta only when `baseModelRevision` equals its `modelRevision`, applies records, removals, order, page state, and fragment invalidations atomically, and advances `modelRevision` only on success. When several commits occur before dispatch, `changedElements` contains the latest form of every ID changed since `baseModelRevision`, including connected lines or arrows re-resolved by target changes. `removedIds` contains IDs absent at the target revision, and the two sets are disjoint. An order-only command sends no fabricated geometry change but includes its changed band in `orderChanges`. A gap, worker restart, timeout, invalid order, or error invalidates the model baseline and requires the next state-bearing request to contain a full snapshot.

For an incremental change without removals, explicit order changes, insertions, or render-band moves, the worker reuses its validated band arrays. Structural order changes still receive complete order validation. During delta preparation, complete ordered records are materialized only for relation checks that need them; successful ordinary synchronization retains the serializer model and revision without rebuilding a full snapshot. Clipboard Copy materializes a snapshot on demand, while Paste reads revision-matched page, aggregate facts, and ID membership directly.

Before an export result may enter `preparedSuccessor` or become `activeSaveOperation`, its model revision must still equal the current document revision, its worker epoch must be current, and its export generation must equal `newestDispatchedExportGeneration`. Promotion from the prepared slot repeats all three checks; a stale prepared result is discarded while the latest in-flight or coalesced export remains pending. Immediately before `Vault.process()`, the active save rechecks its exact preflight base and that its revision still equals the editor revision. Before that write begins, a newer edit terminates the unwritten active save and permits only a newly current prepared or coalesced successor to replace it. Once `Vault.process()` begins, later edits or export generations cannot invalidate the active save or its mandatory read-back. Every normal phase checks the session and `activeSaveOperation.saveOperationId`, not `newestDispatchedExportGeneration`.

A confirmed active-save read-back always advances the session's confirmed vault base revision and hash to that written result, even when the editor has advanced and a prepared successor exists. Dirty state clears only when the current editor revision equals the confirmed active-save revision. Otherwise the document stays dirty, the successor later preflights against the newly confirmed base, and a detached-save lease remains until the exact latest authoritative revision is confirmed. Complete-file parsing or hashing is never performed synchronously on the main thread.

Worker bootstrap, clipboard revision synchronization, full-recovery preparation, export assembly, UTF-8 encoding, and SHA-256 hashing are input-aware and time-sliced in both the production worker and fallback executor. Runtime snapshot copies reuse retained immutable point buffers and copy uncached samples in triple-aligned blocks bounded by the active input-byte profile. Clipboard post-parse validation shares one implementation with synchronous validation and exposes resumable JSON, element, sample, and aggregate-bound checkpoints. Complete payload validation is still required before publication or caching aggregate clipboard bounds; cancellation publishes no partial result. Final native allocation, JSON-container preflight, and atomic model/store publication remain indivisible boundaries. Point-heavy worker copies use packed typed buffers and transfer ownership of those copies without detaching buffers owned by the editor store. Small incremental records may use structured clone only while measured dispatch work remains within the selected refresh-rate slice budget. The reference comparison measures cloned strings against transferred UTF-8, including sender encoding, structured transfer or clone, and receiver adoption, for both reference profiles. UTF-8 remains the version 1 complete-export wire format. Reference-device acceptance requires its measured median to beat string cloning; a Node runner does not establish that choice for every device. CI verifies buffer ownership, adopted sizes, and bounded observable dispatch and adoption work under [Performance CI](performance-ci.md); it performs no timing measurements or PR-base comparisons. Decoding, joining, hashing, validation, and adoption count fully toward the applicable slice budget.

Stroke samples retain shape identity across translation. Scene paths use local geometry with the persisted offset composed into the SVG transform; world-space hit testing and spatial bounds still apply the complete placement. A mounted stroke can retain its current local path across a pure move, including history replay, even when the shared path cache has evicted its entry. World-space pressure-window caches must not be interpreted as local geometry. See [Retained Stroke Shape and Position](decisions/retained-stroke-position.md).

The worker retains at most one current serialized snapshot fragment and one current static-SVG fragment per element. The fragment-pair cache is least-recently-used and capped at 20,000 elements and 64 MiB; an evicted fragment is regenerated from the worker's current element record when output assembly next needs it. An incremental request rebuilds fragments only for changed elements, removes deleted fragments, and reuses unchanged fragments. Order-only changes rebuild no element fragment; page-only changes rebuild only root and background fragments. One export resolves its ordered fragment-reference list once and reuses that list for byte accounting, metadata hashing, render-band emission, and metadata emission; those phases must not repeatedly touch and reorder the LRU map. Complete output is assembled deterministically but is never cached for zero-delta reuse; a later zero-delta export reassembles from the bounded current fragments.

Full model resets may adopt a retained stroke fragment without decoding its metadata or re-encoding samples only when its source is the exact previous validated runtime record with transferred or privately copied samples, or verified immutable Store samples. Adoption compares canonical headers and either identical immutable sample buffers or every sample value exactly; mutable or unowned records retain the complete canonical-metadata comparison. Changed headers or samples invalidate the fragment. General runtime and validated-reset APIs default to conservative ownership: validation or a typed-array shape alone does not establish immutability. Unowned runtime input is privately copied before entering identity caches. This preserves canonical output bytes and does not simplify persisted points.

After a successful, cancellation-checked export has verified every fragment's current element identity, complete cache coverage closes the prewarm cursor in constant work. Cache eviction or refused admission retains the existing bounded prewarming path. Failed or cancelled exports cannot claim complete coverage; later model synchronization resets the cursor. The central scheduler continues to own all remaining prewarm work.

Every successful export wire result creates exactly one acknowledgement lifetime keyed by `{ requestId, sessionId, workerEpoch, exportGeneration, modelRevision }`. The receiver sends `accepted: true` only after exact identity, transferred-buffer ownership, byte limit, valid hash spelling, UTF-8 decoding, and bounded canonical-root checks succeed; rejection, orphan or stale delivery, adoption cancellation, dispatch failure, executor termination, or the 30-second acknowledgement timeout closes the lifetime with `accepted: false`. The worker accepts only the exact current identity, ignores late or mismatched acknowledgements, and retains at most one unacknowledged identity without retaining the complete output. Encoding transfers ownership of the result buffer, and all sender-side complete strings, chunks, and buffers become unreachable after post, acknowledgement, replacement, rejection, or termination.

Each serializer additionally owns a bounded local stroke-shape cache, capped at 20,000 entries and 32 MiB including retained sample storage, path strings, and entry overhead. Placement-only changes reuse the local contour and rebuild the position-bearing fragment. Removal retires a cached contour without retaining its serialized fragments. Undo may reuse that contour when the shape fields match and the restored sample buffer is identical, or a retired entry with a different buffer passes an exact value comparison. After restoration, the current buffer identity becomes authoritative. Retired entries remain inside the same LRU and byte limits. Shape changes, eviction, or session disposal remove this reuse opportunity. Complete output assembly and hashing remain linear in the emitted file.

Serialization accounts for actual UTF-8 bytes incrementally. Static envelope, metadata prefix, background, and each reused or rebuilt element fragment reserve against separate metadata and 64 MiB output budgets as they are collected; exhaustion returns a structured limit failure before retaining a complete output. Chunked assembly independently re-enforces the total byte limit while hashing the exact emitted bytes. Estimated character counts or a final post-allocation length check alone are insufficient.

If Worker construction fails, a worker crashes, its protocol is violated, or it times out, the coordinator invalidates its `workerEpoch`, terminates it, and switches exactly once for the current session to the same pure validation, migration, clipboard-codec, export, hashing, and persisted-output verification algorithms on the main thread under a new epoch. The first fallback activation in each owning window writes one developer-console warning without source content, document identifiers, or repeated per-document noise. This fallback yields between input-aware slices bounded by the selected refresh-rate profile, pauses while a live gesture is active, and never performs DOM or Obsidian API work inside a computation slice. Safe-SVG inspection first checks for unsupported declarations and processing instructions in at most 256 Ki code units plus one overlapping code unit per step so forbidden markers cannot cross a step boundary undetected. Safe-SVG path validation then resumes inside one path after at most 16 KiB, 256 commands, or the current slice deadline; trusted-output hashing checks cancellation between 64 KiB chunks. A partial path or hash is never accepted.

Failure before `Vault.process()` begins discards partial computation and restarts the affected unwritten operation under the new epoch and a new purpose-specific operation ID. Epoch invalidation also discards any old-epoch `preparedSuccessor`; the authoritative main-thread model later regenerates it. Failure after the write begins, after it succeeds, or while its outcome is indeterminate MUST NOT discard or repeat that write. The coordinator retains immutable `{ saveOperationId, revision, outputHash }` proof from `activeSaveOperation`, creates a new `verificationOperationId` under the new executor epoch, reads the file through `Vault`, and classifies it against that proof and the previously confirmed base. Matching revision and bytes confirm the old save and update the confirmed base without another write; an unchanged prior base permits a retry; every other result is an external conflict. The worker is not recreated until a new document session, so repeated failure cannot create a retry loop.

Each persistence pass atomically writes one complete SVG file with one matching snapshot revision. “Incremental” refers to worker computation, never a partial file write. Autosaves write compact XML and compact JSON. Pretty-printing is intentionally avoided because reformatting large SVG files during a write would cause noticeable pauses.

Static export MAY merge only consecutive paths in the same render band when their conservative bounds do not intersect, every paint, opacity, fill-rule, cap, join, width, and dash attribute is identical, and concatenating their subpaths preserves appearance and order. A merged `d` attribute is capped at 256 KiB. Non-consecutive paths, intersecting paths, pressure groups or their child paths, and paths participating in an animated editor preview are never merged.

The 10,000-stroke fixture, latency targets, memory ceiling, DOM limits, cache requirements, and animation constraints are normative in [Quality, Performance, Animation, and Testing](quality-and-testing.md).

Standalone output, theme classes, external fidelity, and the strict serialized stylesheet are defined in [Standalone SVG Envelope and Theme Rendering](svg-envelope.md).

## Reusing Owned Validation and Integrity Work

Geometry, style, and page-only export requests do not eagerly copy complete render-band orders. A band-order callback materializes an order only when that band is dirty at dispatch. Prepared pressure hints enumerate the current version-matched Store cache lazily, visiting at most 1,024 entries and retaining at most 4 MiB. Explicit zero offsets are eligible; nonzero offsets remain excluded because those cached world-space contours do not represent the worker's local geometry.

Canonical metadata digest assembly consumes cached fragments synchronously. It checks cooperative scheduling after 64 elements or an accumulated 64 KiB length threshold; this collection phase does not copy payload bytes. Output copying checks after at most 64 KiB or 64 fragment chunks, splitting large fragments at the remaining byte budget. Changed-element encoding retains its own checkpoints. Cancellation, exact canonical hashing, and cache limits remain enforced; asynchronous encoding rechecks current Store ownership before retaining bytes.

Internal style replacement reuses sample validity only for the exact Store-owned stroke buffer. It validates changed fields once, freezes the small source and replacement headers, and binds the resulting proof to that exact source identity. The proof weakly references its source and is revoked when the replacement becomes Store-owned, so it cannot retain an obsolete source chain. Subsequent preparation reuses field validation only while this proof still matches; unowned drafts and stale sources take the normal validation path. Aggregate limits, connections, and version-bound commit checks remain enforced. Large move and handle commits materialize candidates before one version-bound model preparation; stale tokens cannot publish. The synchronous small-handle path retains its existing no-op and connection planning.

The main thread computes the same independent canonical metadata digest used to verify worker output. A session-owned cache retains segmented canonical element bytes under the authoritative Store's ownership proof; a shallow frozen wrapper is insufficient. Complete fragments require exact element identity. For a new Store-owned stroke record with the same ID and immutable sample-buffer identity, the sample segment survives while header and suffix segments are rebuilt. A placement-only edit therefore neither rereads nor re-encodes samples and does not copy them into a replacement element buffer. Mutable or unowned records cannot claim that reuse. The cache uses weak element and sample references; its 20,000-entry/32-MiB LRU counts each retained segment once and clears on disposal. Ordered metadata assembly and exact hashing still process the complete output. Native SHA-256 is preferred when available, with the existing incremental fallback and cancellation checks. No alternate digest or weaker worker-output binding replaces the canonical hash.

Export integrity checks recheck cancellation and current export identity before and after each asynchronous metadata checkpoint. An obsolete digest stops before continuing its traversal, cannot consume the one full-snapshot integrity retry, and cannot authorize a write. An already dispatched native SHA-256 operation cannot be interrupted; its result still requires the final current-identity check. Cancellation does not interrupt an active Vault write or its required readback.

Page/background updates validate changed page fields and their extent against retained Store bounds without rematerializing and validating all stroke samples. Complete band and extent traversal can remain even where expensive point work is removed.

Recognition retains the last safe presentation while the existing document lifecycle checks a modified file identity. Only freshly read bytes matching an own-save hash, revision, and current file signature may replace recognized source without another safe-path scan. Unknown or external changes invalidate recognition and follow its strict inspection path. Aborting obsolete recognition cancels the scanner, not merely its pending-map entry. Own recovery output reuses owned-output adoption; verification responses remain bound to exact output bytes and revision.

The lasting decision and verification boundaries are recorded in [Bounded Interaction Work](decisions/bounded-interaction-work.md).
