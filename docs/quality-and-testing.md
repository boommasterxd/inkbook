# Quality, Performance, Animation, and Testing

## Quality Priorities

No animation, abstraction, or background task may degrade live ink input. When requirements compete, use this order:

1. prevent data loss and unsafe file handling
2. preserve live input responsiveness
3. preserve correct geometry and history
4. provide smooth, understandable transitions
5. reduce background CPU, memory, and file size
6. add optional visual polish

## Performance Acceptance Dataset

The standard large-document fixture contains:

- 10,000 freehand pen strokes
- 500,000 total stroke points, with realistic variation from 1 to 500 points per stroke
- 500 additional mixed shapes, including coordinate systems and tables
- 500 lines and arrows with endpoint connections distributed across shapes, including one target at the 512-endpoint limit
- a derived page height of at least 200,000 page units
- the complete shared palette, including theme-dependent Auto and fixed Black, White and grayscale styles
- selected content in and outside the viewport
- adversarial long strokes and large shapes that enter the spatial-index overflow collection

The stress fixture contains the maximum supported 15,000 strokes and 2,000,000 points. It is used for bounded-load and failure behavior, not for the interactive frame budgets below.

The dense-viewport fixture contains 2,500 simple paths whose exact conservative bounds all intersect the reference viewport, with alternating highlight and content membership, fixed overlapping ranks, 100 predetermined hit points, and enough entrants to exceed both normal mounted-node budgets. The generated `dense-expectations.json` contains the exact unique visible-ID sequence in back-to-front band order and the expected element ID at each hit point. After camera motion stops and no pointer is active, reconciliation MUST equal that sequence with no omission, duplicate, or rank change within 30 submitted frames and 500 milliseconds on desktop or 60 submitted frames and 1,000 milliseconds on mobile, whichever limit is reached first. A hit on a visible but not-yet-mounted element promotes that element by the next submitted frame without changing final order.

### Generate the manual datasets

From an installed checkout, run the [fixture generator](../scripts/manual-performance-fixtures.mjs). Each output path must be absolute, outside the checkout, and point to a new directory whose parent already exists.

```sh
fixture_root="$(mktemp -d /tmp/inkbook-fixtures.XXXXXXXX)"
node scripts/manual-performance-fixtures.mjs "$fixture_root/reference"
node scripts/manual-performance-fixtures.mjs "$fixture_root/stress" --stress
```

The default command generates `standard.svg`, `standard.md`, `dense.svg`, `dense.md`, `dense-expectations.json` and `manifest.json` through the production serializer. The manifest identifies the expected standard content and the element IDs to select for the centered-viewport scenario. The optional `--stress` command generates `stress.svg`, `stress.md` and `manifest.json`. Its manifest also records the schema's expected rejection of one additional stroke or sample when each limit is exceeded independently.

Record the generator revision, fixture version and SVG SHA-256 from the manifest in the working evidence. Use the same generated input for comparisons and prepare separate copies for edits. Open the files in the [isolated QA vault](manual-release-checks.md#manual-obsidian-display-verification).

## Reference Profiles

The device timing protocol and latency targets below are release acceptance requirements outside CI. Automated tests no longer measure elapsed time, CPU time, or latency percentiles; they verify work/resources and simulated scheduling under [Performance CI](performance-ci.md).

Performance is measured on both profiles:

| Profile | Minimum class                                                                                                                             |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Desktop | 4 physical CPU cores, 8 GiB RAM, integrated graphics, 60 Hz display, current supported Obsidian desktop                                   |
| Mobile  | 2021-or-newer mid-range iOS or Android device, 6 GiB RAM where the platform exposes RAM, 60 Hz display, current supported Obsidian mobile |

Every release report records the exact devices, OS versions, Obsidian versions, document fixture hash, build mode, and measurement method. Production builds are required.

## Measurement Protocol

Production builds use a 1,200 by 800 CSS-pixel desktop viewport and a 390 by 700 CSS-pixel mobile viewport at 60 Hz, width-fit zoom, a centered viewport at 50 percent of page height, and the same generated fixture identified by its SHA-256. Each release names one exact desktop and one exact mobile reference device meeting the minimum classes; changing a device creates a new recorded baseline and requires one comparison run on the previous device when available.

Each scenario has one warm-up run followed by five measured runs. Duration and sample counts are minimums:

The release result is the worst measured run, not a percentile pooled across runs.

Memory is additional heap compared with the same Obsidian pane and locked preview. Record retained and peak live heap from unlock start through worker parsing, migration, buffer transfer, fixture indexing, one full scenario cycle, maximum clipboard Copy and Paste codecs, full export, result handoff, `Vault.process()`, conflict recovery, five rapidly coalesced incremental saves, and five idle seconds. Use an explicit development-tools garbage collection only when supported and record that fact; otherwise take three stable heap readings one second apart and use the maximum. The test fails if the ceiling or an unexplained upward trend across five repeated cycles is observed.

Measure memory in running Obsidian with the same standard fixture on both reference profiles. Separate the main-window and worker measurements where the profiler permits it, and account for buffers held across the transfer, live vault input and conflict recovery. Use [direct runtime verification](performance-ci.md#direct-runtime-verification) for changes to those boundaries. The automated performance contracts cover viewport publication and coalesced pen input.

Additional rules:

- Supported refresh profiles are 60, 90, 120, 144, and 240 Hz with frame intervals of approximately 16.67, 11.11, 8.33, 6.94, and 4.17 milliseconds. Production interruptible work shares one owning-window budget reserving 55 percent of each interval. When changing scheduling, directly verify coalescing, progress, bounded work, nested asynchronous continuations, live setting changes, cancellation, complete atomic adoption, and absence of an idle frame loop. Competing consumers must spend the same budget. Physical reference-device measurements establish the latency requirements above.
- No input-related main-thread task may exceed 16.7 ms. A prepared transaction adopts as one indivisible task with the same 16.7-millisecond hard limit. Chunked preparation may span multiple tasks, but each slice follows the selected soft deadline and the already rendered preview remains visually stable.
- No pointer sample supplied by `getCoalescedEvents()` may be silently dropped. Nearby samples may be deterministically merged by the documented path builder.
- Unlock, pan, zoom, and drawing must not eagerly prepare or logically mount the complete 10,000-stroke document. The mounted-path and mounted-node budgets apply to the logical viewport and active previews. Offscreen committed roots are physically removed through bounded cleanup and may remain connected only until that cleanup completes. The [Path Caches](rendering-and-performance.md#path-caches) retain detached roots separately; all pending and retained ownership counts toward total active-document memory.
- Background generation, bounds updates, spatial-index updates, and cache invalidation must be incremental.
- Camera-only, overlay-only, and theme-only frames perform zero committed-content attribute writes. Paint-only and order-only commits perform zero path construction, bounds calculation, anchor generation, or spatial-index mutation.
- Snap lookup uses the spatial index, and target transforms use the reverse connection map. Neither may scan the complete element store.
- A synchronous document-worker fallback may exceed the corresponding worker duration, but it MUST yield immediately after the bounded unit that crosses the selected soft deadline and MUST pause while a live gesture is active.
- Autosave timers do not count as permission to perform work during an active gesture.
- Worker verification observes validation runs, bounds reuse, fragment and contour generation, cache reuse and bytes, prewarm visits, queues, and retained ownership through production counters and focused boundary instrumentation. Hydration checks actual buffer copies, bounded batch transfer, Store adoption, cancellation, and cleanup without elapsed-phase recording. Physical-device save measurements cover representative message handoff, receiver adoption, conflict-check, host-I/O, and confirmation costs where those adapters participate. Main-thread preparation follows the interruptible soft-deadline contract, and indivisible adoption follows the 16.7-millisecond hard limit.
- A standard-fixture size report records total bytes, metadata bytes, static-markup bytes, and bytes per stroke point. Pretty-printed output fails regardless of the total.

## Performance Architecture Rules

- Locked embeds use the static SVG preview and mount no editor store or React tree.
- The runtime store is one aggregate containing the private ID map, three ordered ID bands, derived ranks, capacity counters, spatial index, reverse connection map, and commit-time versions. Synchronous commands preflight all affected capacity, connection, and index changes before publishing one atomic delta. Time-sliced mutations prepare all affected members against one source mutation version and adopt them as one transaction. A cancelled, failed, or stale preparation changes none of the aggregate; ordinary commands retain unchanged record identities and do not clone a persisted snapshot.
- Viewport queries, hit testing, erasing, and page extent queries use the spatial index.
- React owns application chrome and coarse editor state only. Individual ink elements are owned by the imperative SVG scene renderer.
- Pointer-move, pan, zoom, pinch, scroll, snapping, culling, and preview frames produce zero React renders, React state updates, and React-visible store notifications. Discrete selection and tool changes may enqueue one coarse UI update after imperative feedback. Cursor-only updates retain fixed SVG-node identity, share at most one pending scene frame, bound actual layout reads independently of pointer-event count, allow at most one synchronous transform write per changed pointer position without rebuilding nodes, and perform no content query or geometry build. For cursor performance changes, verify the affected work with the 10,000-stroke fixture and all five scheduling profiles.
- Chrome callbacks remain referentially stable for one active presentation. A semantic chrome snapshot suppresses `root.render()` when toolbar, active-menu identity, dynamic shape and style icons, layout, and callback state are unchanged.
- Pointer-move processing never clones the complete element array or snapshot.
- The live-stroke builder appends finalized chunks and rebuilds at most 130 retained tail samples plus bounded boundary context; the 16,384th point does not reconstruct the first segment.
- Live-stroke distance, timing, and pressure decisions read the numeric sample buffer directly without reconstructing temporary sample objects for retained points.
- Selection transforms preview with one parent SVG transform when possible and commit geometry once. Raw handle-pointer bursts retain only the latest sample and modifiers, perform at most one complete preview update per animation frame, and synchronously flush that sample before pointer-up commit. A pen handle release with zero pressure and no contact button commits the queued contact position instead of introducing a final hover-coordinate update. Cancellation, pointer-capture loss, and disposal cancel the scheduled frame and discard its sample. Exact element previews, transforms, selection paths, and snap paths are staged and written together by the scene frame writer. The imperative selection overlay applies the same transform in that frame and never falls back to stale Store bounds. Handle layout, grab offset, selected geometry, transform input, preview bounds, page-growth extent, and overlay use one gesture-start snapshot and one resolved frame result. A stationary pointer produces no resize delta after target acquisition, perpendicular noise produces no uniform scale delta, and crossing the fixed anchor cannot reverse into growth. A singly selected line or arrow uses its centerline plus start, canonical bend, and end handles with no box or rotation handle. Pointer-type and zoom-dependent invisible handle targets must cover resize, endpoint, bend, coordinate, and rotation handles without changing their visible screen-size geometry. Exact per-element handle previews require at most 256 elements, at most 16,384 aggregate geometry samples, and at most 256 samples in each freehand stroke. The per-stroke threshold is chosen once from gesture-invariant input. All mounted selected roots receive continuous scale feedback. Expensive canonical replacement preparation remains bounded to 256 path costs, including filled arrow nodes, under the snapshot handoff defined in [Rendering and Performance](rendering-and-performance.md). Constant-width freehand strokes transform their canonical centerlines without rebuilding; pressure strokes and non-affine shapes use canonical replacement geometry with continuous snapshot-relative feedback. For affected handle changes, verify zero sample materialization in pointer updates, stable retained path-node identity, and complete pressure snapshot publication. Exercise affected element kinds for canonical preview and commit geometry and paint, dense pressure self-overlap, local pressure, alpha compositing, camera changes, fair progress and same-frame visual movement during continuous coalesced input, snapshot-relative transforms, cancellation, and atomic commit handoff. A handle commit may materialize synchronously only at or below 1,000 elements, 16,384 aggregate geometry samples, and the reverse-dependent budget; larger work prepares in input-aware slices and adopts once. Every slice and final token adoption rechecks cancellation and the gesture generation. Dragging selected content uses its transform-only preview and switches to sliced commit preparation above 1,000 elements.
- Each eraser update continues resumable spatial traversal and exact intersection checks while the shared scheduler deadline permits, checking that deadline every 1,024 work units. This checkpoint quantum bounds indivisible work; it does not force a frame wait while budget remains. Traversal charges occupied or empty cell/column visits, iterator transitions, duplicate memberships, rejected bounds, and overflow entries. Candidate batches contain at most 128 IDs; one active query retains deduplication state bounded by the indexed document capacity. The sweep retains at most 512 segments. Owning-window animation frames continue unfinished work while the pointer is stationary. Commit cancels the live continuation frame and drains cancellably before one atomic removal command; its 12,288-unit feedback quanta retain bounded inner checkpoints and only wait for another frame when the shared deadline is exhausted; queue overflow, document revision changes, or stale index cursors cancel the entire sweep and release pending work. Cancellation never commits a truncated result.
- Selection size never disables logical culling: visible selected content receives complete live transform feedback, while offscreen selection uses aggregate bounds. Large selections reuse current scene membership rather than mounting every selected element. Preview bounds preserve still-visible transformed roots; camera reconciliation releases obsolete offscreen feedback. Canonical replacement preparation retains its separate bounded cohort.
- World-space bounds, prepared paths, and semantic anchors validate the element ID plus its commit-time `geometryVersion`. Retained local stroke paths instead use immutable sample identity and a matching local shape signature, so placement-only changes can reuse them. Paint, order, selection, and theme changes are cache hits. Main-thread path strings are limited to mounted nodes and the bounded caches in [Path Caches](rendering-and-performance.md#path-caches). Unlock does not transfer prepared paths; demanded visible geometry uses bounded construction, and missing or evicted cache entries use that same path. Mounting a retained prepared path performs no pressure-union construction.
- Viewport invalidations coalesce into one pending animation-frame update. Visible-ID diffing mutates only entrants, exits, changed records, and affected order; scene groups are never replaced wholesale.
- Visible-set reconciliation uses stable numeric slots, reusable buffers, and epoch markers or bitsets. An ordinary frame allocates no replacement full candidate, visible, entrant, exit, or deduplication collection.
- Committed paths and decorative overlays use `pointer-events: none`; one presentation-owned focusable input surface handles the canvas. No SVG content node owns an event listener.
- Applied-node state suppresses unchanged SVG attributes. Geometry, paint, order, connection, visibility, camera, overlay, background, and theme dirtiness remain independently observable in renderer instrumentation.
- Each scene frame completes layout reads before DOM writes. Repeated observers and unchanged dimensions schedule no work. Toolbar overflow reads run only after a changed positive width, a dirty layout observation, or a semantic layout-key change.
- Document-worker state synchronization contains changed and removed IDs, order, and page state after initialization; it atomically advances `modelRevision` and fragment dirtiness, while clipboard encoding uses selection IDs rather than a complete selection clone.
- Order-only changes carry explicit render-band order, and target changes carry every automatically re-resolved line or arrow.
- The newest dispatched export generation orders only replaceable export results and `preparedSuccessor`. Once admitted, `activeSaveOperation` remains valid through mandatory read-back even when a newer export is dispatched. Other worker jobs have independent operation IDs; queued timers have no identity.
- At most one export request, one non-replaceable active save, one prepared successor, and one vault write are in flight. Later commits occupy one coalesced target, vault writes are serialized, and superseded prepared outputs are released.
- Worker state retains one canonical typed geometry buffer per stroke plus bounded current per-element snapshot and static-SVG fragments. Main-thread and worker allocation together remains inside the memory ceiling.
- One document worker runs one bounded queue; ordinary speculative document prewarming (excluding navigation-reserve requests) is the sole job that cooperatively suspends at central scheduler checkpoints for higher-priority clipboard, export, preflight, and read-back worker operations. It resumes the same operation after blockers reach a terminal result; navigation-reserve and required visible scene work retain priority. The worker performs unlock validation and migration, clipboard codecs, SVG export, hashing, preflight, and read-back verification, but receives no DOM, pointer, scroll, camera, spatial-index, React, or Obsidian API object. Separately, navigation suspends export work while required read-only viewport contours may proceed under the [central scheduling contract](rendering-and-performance.md#central-work-scheduling).
- Worker failure invalidates the worker epoch and permits one native replacement before at most one equivalent input-aware main-thread fallback. Opening and later failures share this session-wide budget; recovery is single-flight and retains authoritative state and active save proofs. Follow the [bounded recovery contract](rendering-and-performance.md#document-worker-autosave-and-export) without an automatic restart loop.
- Every active patterned background uses one presentation-owned SVG pattern tile and one bounded full-page coverage path derived from the same canonical guide layout as standalone export. Geometry is independent of viewport clipping and camera pan. Guides use normal antialiasing, a scale-independent one-screen-pixel stroke, and the same 25-percent-alpha scheme palette in both presentations. Static export estimates guide subpaths and serialized bytes before allocating any background path fragment and rejects an over-budget page without partial output.
- Background coverage is keyed by page and pattern geometry and regenerates only when that key changes. It spans the complete prepared page, so viewport clipping and camera movement never change the key. Theme changes reuse its geometry.
- A culling refresh uses the axis-specific mounting margins and hysteresis reserves defined in [Viewport Culling](rendering-and-performance.md#viewport-culling), converted to page units at the current zoom. Verify both navigation directions, zoom conversion, exact initial preparation, and replenishment before the leading reserve is exhausted. Once prepared offscreen nodes enter the viewport, unchanged geometry must require no new geometry builds or DOM insertions.
- Dense viewports eventually mount every exact visible element in input-aware batches; they may disable animation and unrelated prewarming but may not rasterize, merge, or hide editable content. Mount preparation uses the shared absolute deadline between bounded geometry steps, without additional point-, element-, or step-count CPU quotas. Cache hits do not rebuild or charge geometry. The separate live-root publication limit bounds deferred browser work.
- Every cache has an entry or byte limit, invalidates removed records immediately, and is released on editor unmount. Physical SVG cleanup may run later through the central scheduler; queued nodes remain owned and fully accounted until removal.
- Lifecycle soak tests repeatedly mount and unmount React chrome and adaptive menu sessions, switch notes and attachments, create and terminate workers, and run the 10,000-stroke memory lifecycle without retaining roots, menus, listeners, observers, animation frames, workers, or host references.

## Animation Tokens

```ts
const motion = {
  fast: 120,
  surface: 220,
  standard: 180,
  erase: 150,
  layout: 240,
} as const;
const easing = {
  erase: "cubic-bezier(0.645, 0.045, 0.355, 1)",
  standard: "cubic-bezier(0.2, 0, 0, 1)",
  emphasized: "cubic-bezier(0.2, 0, 0, 1)",
} as const;
const layoutEasing = "ease-out";
```

Durations are milliseconds. The shared `surface` value controls toolbar and feedback presence, adaptive phone sheets, and adaptive content resizing. Inkbook-owned desktop and tablet modal motion and adaptive-panel entrance use the `fast` value. Element and chrome motion shares one default curve. Eraser and Selection Delete use the `erase` ease-in-out curve for opacity feedback. The locked-to-active height transition uses the immediate-start layout curve, equivalent to `cubicBezier(0, 0, 0.58, 1)`. Automatic height changes, first appearance, removal, loading growth, and active-to-locked height retain their documented smoothstep interpolation.

Implementation rules:

- Settings disclosures use the shared native Motion adapter in their owning window. ## Reduced Motion

Static stacking and lock-layout transition suppression belong to lifecycle classes in the plugin stylesheet. Completion, cancellation, reduced motion, and disposal release those classes. - all non-essential durations become 0 ms; live preference changes settle active and queued ordinary removal fades to their removal endpoint through the existing bounded scene admission and cleanup budget, without restarting them when full motion returns

## Automated Test Strategy

Keep permanent tests only for reachable failures that would break a core Inkbook
flow, lose or corrupt user data, admit unsafe content, or let CI silently omit
required work. Use the lowest reliable layer and assert the user-visible result,
persisted state, or required gate outcome. Prefer one case per distinct outcome.
Use Unit tests for pure behavior and focused Integration tests for host and worker
boundaries. Keep End-to-End and smoke suites out of the project.

| Core outcome                           | Automated evidence                                                                                                                                                                                 |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Create and safely open a drawing       | The insertion command creates and verifies the SVG before writing the Markdown link. Recognition follows the host lifecycle and invalid or unsafe SVG cannot mount or substitute editable content. |
| Edit and undo drawings                 | Pen input commits the stroke, erasing and selection update the underlying document, and Undo/Redo restores the intended content as one action.                                                     |
| Preserve drawings on save and recovery | The latest confirmed save survives reopen. External edits are preserved and worker failure or an invalid export cannot confirm a bad write.                                                        |
| Preserve portable data                 | Supported historical documents and current text and image resources survive reopen. Clipboard copy and paste preserve content and remap identities safely.                                         |
| Hand off active work                   | Switching Obsidian presentations keeps one authoritative session and preserves dirty work or recovery ownership when the previous presentation detaches.                                           |
| Enforce the required checks            | CI validates the complete diff, runs proven affected tests or the full fallback, and fails on missing, invalid, failed, or unexpectedly skipped work.                                              |

Reuse appropriate fixtures and assertions. Prepare the same immutable inputs once
where safe and initialize fresh mutable state for each case. Combine closely
related assertions when this avoids repeating costly setup. Verify ordinary
appearance, accessibility, motion, and interactions directly in [running
Obsidian](manual-release-checks.md#manual-obsidian-display-verification) using affected modes.
Integration tests exercise production paths through isolated host adapters.

The two [performance contracts](performance-ci.md) observe bounded viewport
publication for 10,000 strokes and one latest-tip pen publication per frame at the
supported refresh profiles. Profile affected runtime work separately. The
[measurement protocol](#measurement-protocol) and all product budgets remain
required for physical-device acceptance.

## CI Gates

`typecheck:cache-lifecycle` applies strict CheckJS to the portable cache runtime
through `scripts/cache-lifecycle/tsconfig.json` and remains part of the native CI
quality gate.

Local npm checks use one exclusive loopback listener on `127.0.0.1:47839` across checkouts and worktrees. `ci` and `ci:quality` expand into their existing sequential steps under that single guard; standalone test, benchmark, lint, build, and other validation commands use the same guard. If the port is already occupied, the second command exits unsuccessfully before starting any tool. It does not wait, retry failures, skip tests, or change any acceptance threshold. A different service using that port also blocks checks conservatively. Normal completion releases the guard after the active tool exits. On POSIX, handled interruption signals the tool process group and waits for its running members to finish; Windows forwards the signal to the direct child only. After five seconds, remaining children receive `SIGKILL`; another second without confirmed shutdown, or an unverifiable group state, produces an explicit cleanup failure. Direct tool invocations, the development watcher, and unrelated applications are outside this cooperative guard; avoid competing heavy checks. Killing the runner forcibly can leave tool descendants running even though the operating system releases its port. Check for those processes before starting another check. Tooling files use the explicit `tsconfig.tooling.json` project for type-aware ESLint analysis, avoiding the default-project file-count limit without disabling lint rules.

Hosted CI uses [affected selection](ci-selection.md) for pull requests. Every
non-documentation PR keeps quality, audit, build, and package checks. A proven
no-impact plan may skip the automated tests. Uncertain selection runs the complete
suite and both performance contracts. Manual dispatches and release tags run the
complete gate. `npm run ci` provides the same unfiltered local checks.

The final `CI` job requires successful selection and quality, and each performance
context must complete its selected work or report validated no-work. Required
names and branch protection are defined in [CI and Repository
Protection](../AGENTS.md#ci-and-repository-protection).

The hard ESLint gate fails on functions over 100 lines, files over 500 lines, cyclomatic complexity over 20, cognitive complexity over 25, more than 6 parameters, or nesting deeper than 4 levels. Reviewers still assess large or complex units for clear responsibilities, cohesion, and readability, but the project does not emit a second set of arbitrary lower numeric warnings.

TypeScript and TSX source filenames use `kebab-case`; ambient asset declarations use the standard `kebab-case.d.ts` extension. Executable tests use `*.test.ts`, `*.test.tsx`, or `*.test.mjs`. Types, classes, and React components use `PascalCase`; functions, methods, and variables use `camelCase`; genuine module constants use `UPPER_CASE`; public exports use meaningful names without interface-style `I` prefixes or unnecessary defaults. ESLint enforces identifier and export rules, while the source-layout gate enforces filenames, test suffixes, Scene TSX absence, the 500-line CSS limit, and the central scheduling boundary. The scheduling AST gate rejects native work primitives and consumer-local deadline renewal outside approved adapter or narrowly documented semantic timing sites.

The dependency-cruiser gate evaluates the complete `src/` graph including TypeScript type-only edges. It rejects every cycle and every import that violates the documented `domain`, `editor`, `rendering`, `persistence`, `obsidian`, and build-entry directions. The Scene-specific ESLint gate rejects React, ReactDOM, JSX, TSX, React-owned UI imports, roots, portals, state APIs, selector queries, and descendant DOM walks while allowing imperative DOM and SVG. The entry-based worker typecheck uses `ES2021` plus `WebWorker` and excludes DOM, `Window`, React, Obsidian, and the main-thread worker factory. Stylelint verifies source CSS syntax, known properties, duplicate selectors, specificity, qualifying types, and nesting depth.

CI MUST run:

- formatting verification
- hard linting with project size, complexity, naming, mobile, Obsidian, and architecture-boundary rules, including the renderer restriction rejecting `querySelector`, `querySelectorAll`, and descendant selector walks in scene reconciliation
- source-layout and CSS linting
- complete import-graph cycle and area-direction verification
- main, test, and isolated worker TypeScript type checking
- affected critical Unit and Integration tests, the complete suite on full fallback, or validated no-work when the plan proves no test impact
- `jscpd` with `minTokens: 50`
- `knip`, including a fatal production-only pass for unused files, exports, and types so source code reachable exclusively from tests cannot survive the gate; `ignoreExportsUsedInFile` keeps internally consumed module exports valid while still rejecting exports with no production caller
- native installed dependency and peer graph validation with `npm ls --all`; invalid or missing required dependencies fail even when installation succeeds
- production dependency security audit with `npm audit --omit=dev --audit-level=high`; high/critical findings and audit execution errors fail
- production build and release-artifact verification
- applicable [deterministic performance contracts](performance-ci.md)

No gate may be bypassed through broad exclusions, empty assertions, raised limits, or disabled rules. Node.js type declarations track the reviewed Node.js 26 tooling baseline; reconsider their newer-major exclusion only with a reviewed LTS runtime upgrade. The root compiler uses supported TypeScript 6: the CI import graph, dependency-cruiser, and type-aware ESLint still consume its compiler API. Remove the TypeScript 7 exclusion only after the complete stable toolchain supports that compiler and passes the existing gates; a beta API or a broadened peer range alone is insufficient. See the [supported parser versions](https://typescript-eslint.io/users/dependency-versions/) and [native compiler integration](https://github.com/typescript-eslint/typescript-eslint/issues/10940). The root manifest allows Moment only as a direct development dependency tracking the `$moment` security override for Obsidian's pinned dependency. This keeps native npm and Dependabot updates available, including resolvable major-update proposals. Manifest lint rejects production and optional Moment dependencies, retains other dependency-replacement checks, and preserves the runtime rule requiring Obsidian's host export instead of a direct Moment value import.

The complete [manual release checklist](manual-release-checks.md) defines the required native-host and physical-device acceptance checks. Each release records pass/fail evidence and any accepted limitation.

## Release Gate

A release is acceptable only when:

- all Blocker and Required behavior in the specification is implemented
- the complete local quality, core test, and deterministic performance gates pass
- the 10,000-stroke budgets pass on both reference profiles
- no known critical or high security issue or data-loss path remains
- documented manual accessibility and motion checks pass
- the public Obsidian API and Community directory requirements in [Obsidian Integration](obsidian-integration.md) pass against source and release artifacts

## Image Import and Crop Acceptance

Image behavior follows [Images and PDF Pages](images.md). When affected, verify version 1/2 compatibility, legacy version 3/4 image reading, version 5 resource round trips, digest, MIME, dimensions, malformed references, capacity rejection, image/highlight/content order, selection and transform geometry, nondestructive rotated crop and reset, ordinary and page-width locked import, one-step import/crop history, clipboard resource remapping and deduplication, safe locked-preview references, cancellation, and temporary-resource cleanup. Profile actual raster-resource reuse and retained resource bounds when changing that work. Exercise import and crop in Obsidian with keyboard, pointer, and touch across desktop, tablet, and phone, both themes, and constrained phone viewport height. Physical-device responsiveness and the existing 10,000-stroke requirements remain separate acceptance obligations.

Element locks follow [Element Locks](editor-tools.md#element-locks). When affected, verify all element kinds, old-document and version 4 round trips, mixed-selection commands and exact Undo/Redo state, lasso and keyboard selection, mutation and eraser protection, clipboard and whole-canvas actions, connected-dependency conflicts, and stale or cancelled operations. Profile lock changes on large selections to check that they avoid unaffected geometry rebuilds, stroke-sample copying, and spatial membership replacement. Exercise the affected context menu, pointer and keyboard selection, locked-image annotation, and import in Obsidian on desktop, tablet, and phone.

Color acceptance covers the complete shared palette, Auto switching only with the document scheme, unchanged explicit RGBA values across light and dark schemes, image transparency and overlap, and consistent style, fill, text-background and settings choices. Live text editing, saved text, strokes and shapes must apply the same Auto semantics. Fixed Black annotation over a light image must remain dark after switching schemes; Auto never samples or adapts to image pixels. Text paint bounds include actual glyph overhang, and legacy text preparation preserves its source and layout while safely upgrading its stored bounds. The active scene, saved SVG, locked preview, and PDF export must preserve the same logical result in supported renderers. When those costs are affected, profile geometry preparation, resource reuse, cache invalidation, and export capacity. The external-viewer matrix remains subject to the renderer compatibility boundary in [Standalone SVG Envelope](svg-envelope.md#external-compatibility-and-verification).
