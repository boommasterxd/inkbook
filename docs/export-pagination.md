# Native PDF Export Pagination

## Scope

Sectionless Markdown export produces a static, locked Inkbook graphic for Obsidian's native Markdown-to-PDF path. This document defines its print-only pagination contract. Normal Reading view, Live Preview, Source mode, and the isolated locked-preview iframe keep their existing behavior.

## Source and Geometry Preparation

Export correlates rendered standalone embeds with Markdown source from the requested note path. A matching active `MarkdownView` contributes its current `Editor` buffer when `getMode()` returns `source`, which includes both Live Preview and Source editing and therefore includes unsaved text. Reading view uses `Vault.cachedRead()`. Export does not edit either editor buffer. If source and rendered blocks cannot be correlated safely, the host-rendered block remains unchanged. Confirmed occurrences retain their rendered DOM order, including noncontiguous repeats of the same document, so earlier print fragments settle before later placement is measured. Described graphics reuse the already normalized readable label for their accessible name; Markdown emphasis and character entities are not exposed as literal syntax. The target color scheme comes from the export root's computed CSS `color-scheme`: an unspecified or light-only target resolves to light, a dark-only target resolves to dark, and a target allowing both follows `prefers-color-scheme`. The export target controls ink, guides, page, and locked shell; the source editor scheme does not leak, and no private host selector is needed.

Each successfully exported occurrence also paints its normalized label, or the existing `Handwriting` fallback, as actual SVG text in its first viewport. An opaque rectangle in the locked shell's canonical page color immediately covers that text before the retained drawing references are painted. The rectangle covers only the central 90% width and 75% height around the text, leaving the original graphic at the rounded clipping boundary untouched. This preserves the visible graphic even when a validated legacy drawing has no opaque page path, while native PDF text extraction retains the description. Continuation viewports omit the text; repeated occurrences retain their own descriptions. Text and cover are created only during reference activation after layout reads, with constant DOM work per occurrence and no additional drawing scan. Unload restores the original owned children. This supplies PDF text alternatives; it does not add document tagging or establish full screen-reader conformance for Obsidian's untagged native PDF output. RTL extraction order depends on the PDF reader and extraction mode: visual glyph-order output can differ from the original logical Unicode text.

For each distinct referenced document, export reuses the existing bounded recognition path and may pass an authentic current `SafeStaticProof` to skip only the repeated static-envelope scan. One temporary batch-owned native document worker runtime serially handles the stateless `prepare-export-geometry` requests for unique documents; it validates the complete editable metadata and returns only compact element-bound intervals, never point buffers or a model. The runtime is disposed in the render child's finalization before printing begins. Only native worker construction or infrastructure failure uses the bounded main-thread fallback; no editor session is activated. The main thread cooperatively sorts the returned intervals and builds the query index using the central scheduler. The index contains stored elements only; background geometry is excluded. Strokes and shapes are independent elements, with no word-level or semantic grouping guarantee.

After source correlation produces at least one actual export candidate, the render child acquires a temporary reference to the existing owner-window refresh-rate profile. Acquisition does not wait for profile measurement; ongoing export preparation uses the central scheduler and its profile can update while work runs. The release is idempotent and occurs at render completion or child unload. A short export may finish before Auto detection and retain the conservative default; its measurement lease never outlives preparation.

Cut-index preparation limits each numeric step to at most 256 interval, endpoint, or tree operations. These are cooperative step boundaries only: the central `WorkScheduler` decides whether to hand off, and operation counts never force a yield.

Cut selection prefers a candidate with no element interval crossing it; among crossing candidates it minimizes the number of intersected element bounds. `printScale` is rendered media width in CSS pixels divided by the canonical SVG viewBox width, so the desired document-space clearance is `1 / printScale`. A boundary cut moves into the adjacent gap by up to one CSS pixel, limited to half the available gap, to avoid antialiasing a tangent endpoint. Zero-width gaps between touching endpoints are not clear spans. If no clear span exists, the least-crossing candidate is used. This is a conservative bounds heuristic, not a painted-pixel or semantic-content optimizer. A stroke or shape that crosses a cut remains continuous through shared geometry references and source-coordinate viewBox fragments. The source coordinate scale and guide-grid phase remain unchanged.

## Native PDF Scaling

Obsidian's native downscale enlarges the print-layout viewport by the inverse factor before the final PDF render. Percentage widths alone therefore do not shrink with the text. The isolated [native PDF-options gateway](obsidian-integration.md) supplies a validated immutable scale only to its freshly bound output root; persisted preferences alone are insufficient.

For a bound native target below 100%, the print lifecycle prepares a print-only maximum inline size before printing starts. Its limit is `round(up, calc(100% * native scale), 1px)`, bounded by the root's original maximum when present. The percentage follows the actual print containing block, and CSS-pixel rounding preserves the native whole-pixel root width without guessing paper size or margins. Installing the rule before initial page allocation avoids empty trailing pages left by shrinking an already paginated root. Unsupported CSS expressions, transforms, writing modes, box sizing, or failed reads retain complete graphics. The native paper, margins, and scale options are never written. The 100% path writes no width override. Other sectionless renderers retain their public-only rendering behavior.

The cap proportionally scales the temporary document's content, including text wrapping, drawings, and their locked shells. Screen layout retains the original maximum through a CSS-variable fallback; only print media activates the prepared limit. Page fragments and drawing media are measured in the same layout coordinate system, with no callback-time width write or viewport probe. Original inline properties, priorities, and the owned marker are restored after printing or unload; a later `beforeprint` can prepare the same output again. Missing cut geometry still receives native scaling while retaining the complete graphic. Normal Reading view, Live Preview, Source mode, isolated scenes, and pointer/frame rendering acquire no print DOM or sizing work.

## Print-Time Layout and Placement

Pagination is prepared before printing but reads page geometry only after the temporary export document's public `matchMedia("print")` query changes to `true`. At that point, `getClientRects()` on the export root supplies the actual print-page fragments, including preceding forced page breaks. Screen height, `beforeprint`, and predicted page dimensions are not substitutes for those fragments. The final fragment may contain only the document tail and is not assumed to be a full page.

If the complete graphic fits on the current page, it always stays there. If it does not fit the current page but fits a full page, it moves whole to the next page only when the current remaining room is at most 16% of page height. If a positive Markdown host start margin would push that whole graphic beyond the full page, the owned host carries the break with a zero start margin; smaller graphics retain their original spacing. Restore, fallback, and unload remove this temporary host state without changing inline styles. Otherwise, a high embed may start on the current page and continue across pages. If current room is below `max(64px, 2 × shell radius + 2 × border + 24px)`, it starts on the next page. Every fragment adds block padding equal to the shared shell radius; continued fragments also reserve a 12px top gap, preserving the rounded locked frame without cropping ink.

For a cut, the preferred search looks backward by at most `min(16% of full page height, 30% of current available room)`. If its result crosses an element, at most one additional indexed query searches earlier in the same piece, down to its existing minimum-height boundary. Only a truly crossing-free result replaces the preferred cut; otherwise the original least-crossing result remains. Crossing counts include the actual clearance-adjusted side of a boundary. Both queries are logarithmic and never reread document elements. The piece also observes a 64px minimum when available geometry permits. Each piece has its own shared locked frame and references the document's one retained geometry tree. Piece viewBoxes remain contiguous, non-overlapping source intervals from zero through the full locked SVG height.

At most 256 new pieces are published per render. Invalid geometry, unsupported print layout, an unavailable page-fragment result, a failed cut plan, or piece-capacity overflow keeps the continuous complete graphic instead. Fallback never drops ink. The temporary print listener and any published pieces are restored or disposed with the Markdown render child's lifecycle.

A ticket-bound native export also checks the final root fragment count once, before activating references. Chromium may retain the initially allocated PDF page count after a print-media layout change. When the root gains fragments, publication is retained only if the last content element demonstrably ends within the original capacity derived from uniform full fragments and the original tail's position. Extra fragments containing only trailing padding or margins are harmless; the tail's partial height is never treated as a full page. Unproven geometry or actual content overflow restores all original complete graphics while keeping the prepared native scale, so an improved cut cannot remove following note content from the PDF.

## Retained SVG Fragments

Export builds a balanced tree of references to consecutive static-SVG fragments, cooperatively, once per distinct document in the render. Fragment bounds come from validated static path geometry, including stroke extents, not editable-metadata intervals used for cut selection. Non-scaling guide strokes use an unbounded vertical range because their SVG-space extent depends on print scale. The tree preserves render-band order, opacity groups, translations, and background geometry. Each page references only intersecting fragments in paint order. Validated unrotated SVG arcs use conservative finite ellipse bounds with the [SVG radius correction](https://www.w3.org/TR/SVG/implnote.html#ArcCorrectionOutOfRangeRadii), covering both possible centers and numerical rounding. If bounds are missing or unproven, or fragment counts do not match the drawing, export references the complete graphic instead.

Synchronous page publication admits at most 128 fragment references and visits at most 512 tree or interval records per piece. If either bound is exceeded, it publishes one reference to the complete drawing with the same piece viewBox before activating any page references. This resource-admission guard bounds work even for interleaved paint order; it is not a CPU-yield quota. Cooperative preparation continues to use the central `WorkScheduler`.

Fragment admission extends each vertical query by two output CSS pixels converted through the measured print scale. This retains antialiased edge contributions from nearby paths without changing any piece viewBox, cut, position, or clipping boundary.

During print pagination, exact original SVG viewports and shell boxes remain in place while the original children and references are removed. Export measures page fragments and publishes deferred pieces, then activates each piece's references only after all geometry reads finish. Fallback, `afterprint`, and render-child disposal restore the original children and references. This avoids repeated SVG instance work during layout reads while preserving the original screen output.

On a geometry-cache miss, one cooperative scan of canonical safe markup computes actual painted fragment bounds and builds the detached SVG through the shared parsed-element factory. The retained reference tree is prepared from that SVG while the export worker validates editable metadata and computes cut intervals. Host publication and cache insertion wait for both preparations to finish. A failed fused scan of canonical markup fails closed; the generic preview builder remains for simplified, unmarked boundary fixtures. On a warm cache hit, export uses cached bounds to build detached DOM without another path-command scan or worker request.

The shared path parser retains complete bounded canonical-decimal validation. Its fixed-point grammar, trailing fractional-zero rejection, and negative-zero rejection avoid reformatting every numeric token; parsed numeric values, coordinate limits, relative positions, and arc checks remain unchanged.

The export-only worker parser uses the existing chunked input parser's terminal full SHA-256 and byte-count check against the authentic static proof; it does not perform a preliminary hash pass or adopt snapshot/sample-encoding caches. A stale proof triggers a fresh full safe-envelope parse without the proof, while cancellation does not retry. Metadata parsing reuses the measured raw UTF-8 byte length for entity-free literal chunks instead of encoding those bytes a second time; independent raw and decoded metadata-byte limits remain enforced. UTF-8 request encoding uses the proof's byte count only as an allocation hint, checks that every input code unit was consumed and the exact byte length was written, then falls back to counting and encoding the complete input if the hint is stale. Every decoded and hashed input slice remains an owned copy made before suspension. Normal unlock retains its existing pre-hash path.

With an authentic matching byte-input proof of at most 20 MiB and available native crypto, export may collect those consumed bytes in one private exact-size buffer and use the existing native SHA-256 helper for the terminal digest. This replaces the JavaScript document digest only; metadata hashing, schema validation, byte counts, and final proof matching remain complete. Native digest failure uses the existing cooperative JavaScript hash of the same owned bytes. Short, overflowing, or overlapping input fails closed. Normal parsing and larger exports retain incremental hashing. The owned collector is bounded to 20 MiB, and the native API may temporarily retain another input copy. Completion, failure, or abort releases parser ownership; an already pending native digest may retain its bounded input until completion, but an aborted result cannot be published.

The plugin-owned export-geometry LRU retains only complete validated cut indexes and static fragment bounds, keyed by validated output hash and revision. It retains no DOM, SVG strings, or source descriptors. It is limited to 8 entries and 8 MiB of numeric payload, and is disposed on plugin unload. It is populated lazily by export, so ordinary preview rendering does not prepare or retain export geometry.

## Verification

Native print verification compares the same locked document at the same target width and color scheme, and checks that the complete graphic continues across real page breaks without gaps, loss, scaling changes, or rounded-edge clipping. See the focused [manual release checks](manual-release-checks.md).
