# Local Eraser Work

Status: Accepted.

## Context

Repeated eraser sweeps can rescan long non-hit strokes. Deleting a small subset can also copy unrelated band orders, copy removed samples already retained for private history, and rebuild the surviving spatial index. Separately, autosave can prepare a hidden preview before another lock needs it. These paths share a central scheduler, so reducing repeated work must preserve admission, cancellation, atomic publication, and ownership proofs.

## Decision

Use a gesture-owned index of stroke sections only for privately proven immutable Store elements. A first complete miss retains a cold identity marker within the same LRU entry limit, without buffers or section preparation. Build leaves only during a subsequent exact scan, prepare parents incrementally, and retain exact segment checks for surviving leaves. This pays one additional cold full scan for repeated misses, while avoiding unused index preparation for first-hit and one-off candidates. Reuse adjacent local endpoints and fixed leaf-query scratch storage. Both sweep endpoints share a rotation calculation, with no trigonometry at zero rotation and unchanged arithmetic order. Public mutable objects cannot authorize cache reuse. The canonical capacities, memory limits, and geometry semantics are in [Editor Tools](../editor-tools.md#eraser). The cache neither schedules work nor renews a deadline.

Store-created removals use a separate retained-history preparation entry point. Its opaque forward and reverse directions contain ordering and membership information, while canonical records remain private. Only the same Store's retained-history replay can consume those directions. Public mutation APIs continue to produce independent mutable element copies and validate external inputs. A public flag cannot establish private provenance. Ownership, byte limits, and replay remain governed by [History Replay Reuse](history-replay-reuse.md).

Freeze Store-owned band snapshots before sharing them with a removal transition. A changed removal band has one snapshot; unchanged snapshots are reused. Synchronous writers copy a frozen affected band before changing it. There is no lazy public getter that shifts a large sample copy into an uninterruptible read. The first snapshot freeze is an indivisible native operation. Let `K` be the number of shifted surviving ranks and `N` the total survivor count. When `2 * K > N`, prepare a complete successor rank map under the existing scheduler and atomically adopt its reference instead of writing those ranks again during commit. Reuse unchanged rank objects; do not clone the old complete map before patching it. Smaller changes and ties retain sparse patches, avoiding a complete-map rebuild for tail removals. Version and cancellation checks still guard adoption. The changed band and shifted ranks require linear preparation; this decision does not make the entire Store operation constant-time.

The uniform spatial index uses structurally shared search-tree nodes for keyed entries and cell membership. Stable numeric slots instead use 32-entry radix pages, avoiding keyed comparisons, ordinal nodes and tuple allocations on slot reads. Forking either structure revokes private ownership of shared nodes and nested values. Writers copy shared paths on first modification and can edit private paths directly; empty slot pages are released after deletion. Slot length remains a monotone high-water mark, and the radix root grows with the highest stored address rather than introducing another document limit. An ordinal tree preserves keyed insertion-order iteration. A single generator projects its values, keys, or fresh public entry tuples; set forks adopt prepared storage without constructing discarded empty maps. Large partial removals prepare affected lookup paths and adopt a fixed set of roots after the final generation and cancellation check. Existing extent heaps remain shared because deletion creates no new bottom value; bounded lazy cleanup owns stale entries. Insertions, complete clearing, and mixed changes retain their existing preparation paths. This avoids visiting every retained entry for a large partial removal, at the cost of logarithmic keyed lookups and bounded page/path copying. It adds no generic state framework, overlay chain, second authoritative index, or consumer-local scheduler.

The internal spatial-key contract rejects symbol IDs before mutation; production element IDs remain validated strings. Object identities use weak references, and identity and insertion-order counters use exact `bigint` values. This avoids a strongly retained registry of removed keys and lifetime counter overflow without changing the ES2021 worker baseline.

Pure removals may reuse a completely published visibility result only while its generation, camera envelope, complete candidate set, and finished reconciliation remain current, with no pending preview or ordering work. Filter the previously published IDs into private replacement arrays under the existing central deadline; never mutate published arrays or expose a partial target. Release removed candidate slots without reclassifying surviving records or rebuilding geometry. Mixed changes, incomplete evidence, and camera, page, layout, preview, or generation changes use normal reconciliation. Numeric ranks become dirty until an existing committed-visibility pass refreshes them; a later camera query must fully classify instead of merging entrants against stale ranks. Offscreen removals retain the proof when visible membership is unchanged. Cancellation and disposal release staged arrays and proofs.

Hidden preview descriptors retain the newest validated identity without eagerly constructing another SVG. Explicit lock readiness still prepares and validates the latest presentation before handoff. Visible locked siblings remain independently current. The lifecycle contract is canonical in [Obsidian Integration](../obsidian-integration.md).

Canonical unit-interval membership tests the existing decimal grid arithmetically, retaining type, finiteness, range, and negative-zero rejection. This changes the membership predicate only. Decimal canonicalization and its tie behavior remain unchanged, as do compact sample bytes, external validation, and independent Store-to-export integrity verification.

## Verification

Deterministic tests observe actual sample reads, section bounds and parent work, cache buffers, band descriptors, sample copying, spatial lookups and comparisons, bucket deletion, SVG allocation, and fixed-root adoption. Cases include maximum strokes, the complete 10,000-stroke fixture, repeated misses, public mutable aliases, replacement identities, cancellation, stale generations, Undo/Redo, and disposal. Decimal membership tests include the complete accepted grid and its adjacent IEEE-754 values.

CI measures bounded work and scheduling under [Performance CI](../performance-ci.md); it does not establish execution speed. Browser traces, before/after timing artifacts, native input behavior and physical-device latency remain separate acceptance evidence under [Quality and Testing](../quality-and-testing.md).
