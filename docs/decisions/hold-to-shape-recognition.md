# Hold-to-Shape Recognition

## Decision

Use a local geometric recognizer over the current uninterrupted Draw stroke. The pure domain recognizer returns native shape parameters or rejects the input; it never mutates a document. The editor owns the quiet interval, cancellation, and central-scheduler admission. The Obsidian adapter owns semantic timers and the normal creation/preview boundary. No model download, network service, or additional runtime dependency is needed.

Existing shape creation remains the owner of native style structure and validation. Recognition transfers the captured pen color, width, and opacity to the outline, initially removes closed-shape fill, and retains the native outline pattern. Native geometry, history, rendering, clipboard, and standalone SVG retain their existing contracts. The five-point star is a normal closed polygon, available through the shape tool as well as recognition. The interaction is canonical in [Editor Tools](../editor-tools.md#hold-to-shape); preferences are canonical in [Settings](../settings.md#hold-to-shape).

## Fitting and Rejection

Normalize positions by path distance while retaining significant corners. Keep 160 global segments, 32 detail positions within 48 CSS pixels of each endpoint, and at most 24 additional original corners within a 256-point bound. Retain the geometrically strongest corners using `(1 - cos(turn)) * min(adjacent segment lengths)`, reusing measured segment lengths; early small bends cannot consume the complete corner budget. Curve fitting weights samples by path distance so dense endpoint detail does not dominate the shaft. Fit arbitrary-direction lines and native quadratic curves, then closed-shape contours or a shaft with independently classified endpoint motifs. Prefer straight geometry for small drawing deviations, while checking significant endpoint retracing for actual arrowheads. Closed candidates include rotation and native aspect ratios; geometrically equivalent rectangle/diamond representations do not establish different user intent. A separate constrained five-tip fit accepts the familiar crossing pentagram gesture and creates the same native star as an outer-contour gesture. Nearby first/last samples belonging to the same tip retain the outermost observed endpoint in source order before the five-tip and fit checks, so reversing a small closing gap does not move the selected tip inward. Unsupported geometry, poor fits, substantial backtracking, and ambiguous candidates retain raw ink.

Pentagram tip extraction first uses the fine contour simplification and may retry once at four percent of the input diagonal when curved sides leave extra corners. Remove the weakest side bends below a 60-degree direction change while more than five candidates remain. Acceptance requires five convex outer tips, a consistent skip-two drawing order and five inner crossings. The complete input retains the existing 0.94-to-1.12 path/perimeter ratio and must remain within 2.6-percent RMS and 6.5-percent maximum distance of its five drawn sides. Fit the actual orthogonal native output rather than validating a freely sheared basis and discarding its shear during creation. With the pentagram topology established, native outer tips permit at most four-percent RMS and 6.5-percent maximum displacement relative to the input diagonal. These are pentagram-specific rules; other closed-shape and arrowhead limits remain unchanged.

Before fitting, check every original point against its corresponding normalized segment using retained path-distance positions. One advancing segment index keeps this fidelity check linear in original and normalized points. Reject a lost detail beyond `max(4 CSS pixels, 0.5% of the drawing diagonal)`: the absolute allowance accommodates two pixels of jitter in both the original point and sampled segment. This prevents repeated zigzags from aliasing into a line without using a raw-to-normalized length ratio that penalizes ordinary dense input jitter.

The $Q recognizer was investigated as an optional template classifier. Its nearest-template result does not provide native geometry or a calibrated acceptance probability; it also needs explicit rotation handling. This implementation uses geometric fitting first rather than adding an unproven template dependency. Any later template addition must demonstrate a concrete gain on separate evaluation examples while preserving rejection and work bounds.

The straight-line preference accepts a maximum chord deviation below `max(2 CSS pixels, 6% of chord length)` and a path-weighted RMS below `max(1 CSS pixel, 4% of chord length)`, while keeping path length below 1.12 times the chord. Check interior backward progress independently of lateral error, including on collinear paths and during final curve projection. The usual allowance is 2 CSS pixels. Only the very low-error lateral field permits earlier hold jitter up to `max(2 CSS pixels, min(14 CSS pixels, 6% of chord length))`; drawing may resume and make a previous quiet endpoint interior. The 14-pixel cap covers the default 12-pixel hold jitter plus a two-pixel geometric point allowance. Within the outer four percent of path distance, a point inside `max(3 CSS pixels, 2% of chord length)` of its endpoint is excluded from the shallow-path detail check. Pronounced interior corners remain protected.

After a curve passes the existing fit checks, a control point within 2 CSS pixels of the finite endpoint segment is canonicalized to a straight line. This removes negligible residual bends after tolerated endpoint jitter lengthens the sampled path, without bypassing curve validation or changing the path-length and corner limits.

Near-semicircular arches may use a separately validated approximation when the strict quadratic residual fails. Seventeen path-distance supports must establish one coherent turning direction, bounded local turns and a total turn near a half circle. The accepted native quadratic remains within `min(3.5% of path length, 6.5% of chord)` RMS and `min(6.5% of path length, 12% of chord)` maximum error. This preserves a visible arch rather than flattening it. The native model still owns a single quadratic; substantially overhanging curves that cannot fit it remain raw. A broad J-like trace can itself be a supported native quadratic, so a letter-like appearance alone is not a valid rejection rule.

Closed fitting retains its global 16-percent-of-diagonal endpoint-gap rule. A rectangle may additionally close a gap along one fitted side when that gap is no longer than half its shorter side; other shape kinds retain the original rule. Perimeter-like paths may discard one short initial or final seam excursion only when it is within both ten percent of the path length and 1.5 times the original endpoint gap, and brings the endpoints at least four times closer. Contour error, perimeter and backtracking limits still apply. An unresolved near-closed path longer than twice its diagonal with endpoints within twenty percent of that diagonal remains raw instead of being reinterpreted as an oversized arrowhead on a short closing seam.

Arrowhead fitting estimates the local shaft direction with bounded regressions over 10, 25, 50 and 100 CSS pixels rather than the last individual sample segment. Each window checks the four symmetric motifs and asymmetric polygon motifs for unequal arms and rear corners. A retraced open head additionally fits the observed return tip and two separately evidenced wings. If necessary, intersect each wing's distance-constrained angular intervals instead of widening its error tolerance. Bidirectional contour matching accommodates a slightly separated outward and return trace while preserving the 9.5-percent maximum residual. A complete residual below five percent stops the window search early only for a constrained native attachment; a translated side fit still checks the remaining windows for a native fit. At most six candidates per end reach the line/quadratic fitter, giving at most 48 nonempty shaft combinations. Rank candidates by native attachment before translated side fallback, then contour error, while reserving the earliest plausible attachment so later retracing cannot crowd out the real shaft boundary. Among combinations that pass shaft fitting, prefer more recognized heads, then fewer translated side attachments, then lower summed contour error. This extends the existing per-contour fallback order across cuts without replacing the shaft fitter's intentional straightening policy or adding another geometry-scoring pass. Each window and individual contour fit yields to the central scheduler.

Closed endpoint motifs admit outer-tip, near-boundary and side-boundary attachments. A complete loop may end with a short repeated rim: consider the nearest return to its initial seam after at least twice the marker depth only when the remaining path is at most one quarter of the total. Monotone path-distance cursors must also establish that the remainder repeats the earlier boundary within the existing closure tolerance; proximity alone cannot turn an unfinished triangle edge into a loop. The complete contour, including that repeated rim, still passes the existing bidirectional 9.5-percent residual and length checks. Side attachments require a closed contour straddling the actual shaft attachment; cached contour bounds translate the existing native templates. Circle attachment also accounts for the transverse center. Retraced tips and side attachments validate the original shaft before moving the result's native endpoints and pivot, avoiding an artificial corner in fabricated shaft samples. Both stroke orders use the same bounded head search; separate earlier strokes are not grouped. Rectangular endpoint boxes are not native arrow motifs and are not normalized to diamonds.

Closed-shape candidates at the same coarse angle share one preparation of rotated points and bounds. Refinement retains each kind's existing angle order and fit criteria. Polygon comparisons retain squared distances until the final metric instead of calculating a square root for every point-edge comparison. Arrowhead preparation collects contour bounds in one pass, and a template stops only when a fully measured point already exceeds the existing normalized maximum-error limit. Accepted templates still receive their complete score; rejected templates still allow the existing asymmetric alternative. Fixed circle template units are reused without retaining gesture data.

Rectangle fits use supported side interiors rather than allowing one outward wobble to place every edge. Selected native polygons can refine bounds through at most two projection/least-squares passes, yielding after each pass. Triangle, star and parallelogram refinement may be joined by either a four-corner diamond or a seven/eight-corner octagon when main-contour evidence supports it and an already valid rectangle or ellipse does not. The shared bounded corner extractor retains the original samples for final validation. RMS remains at most 2.6% of the contour diagonal, maximum error 6.5%, backtracking 9% of the native perimeter and absolute projected traversal mismatch 22%. Measure traversal along the fitted native boundary, including the short closing seam; perpendicular tremor must not inflate the perimeter measure. Full extra laps and insufficient boundary coverage remain rejected. Rank eligible fits by geometric residual; rounded corners and wavy sides are not penalized again through a perimeter score. Exclude invalid fits before comparing valid alternatives. For eligible competing diamond/parallelogram fits, recover four main side lines from the original side interiors and compare adjacent lengths against opposite-side coherence and fit uncertainty. Rounded corner samples alone must not establish unequal side lengths.

Collection rotation calculates one trigonometric basis per angle while sharing the scalar rotation arithmetic. Projected arrow contours carry their bounds into head fitting only for the identical point collection. A newly oriented contour calculates its own bounds; unrelated collections cannot reuse that preparation.

## Work and Ownership

The raw-input observer performs only bounded per-batch distance checks against a fixed screen-space anchor. It does not inspect document elements, build paths, or run recognition. The existing frame-coalesced live-stroke renderer continues to own ink feedback.

One quiet interval owns at most one recognition job and two semantic timers. Before calculation, one immutable copy is limited to the schema's 16,384 xyz samples, at most 49,152 numeric values. Source normalization yields bounded steps to the injected `WorkScheduler`; candidate searches operate on a bounded normalized path. Significant movement invalidates pending results and cancels recognition continuations. Release, cancellation, stale ownership, and disposal also release remaining timers. Failed preparation retains raw ink. Preview and final native geometry reuse the same accepted result rather than recognizing again at release.

Movement immediately invalidates recognition and updates the quiet deadlines. Existing semantic timers remain owned until their wakeup; an early wakeup schedules only the remaining quiet interval. Disposal still cancels every remaining timer. Stationary canonical tip replacements continue updating the raw input and pressure/time state while retaining unchanged live-stroke geometry. Actual canonical position or pressure changes rebuild the tail normally.

The existing scene live-path group sits behind the live-stroke group. Recognition uses it for a non-interactive translucent candidate, with no React work or document-store mutation. A successful release retains the full-opacity native path until normal scene publication completes. No whole-document lookup, extra worker, or viewport-driven decorative effect is added; existing spatial-index culling remains unchanged.

Recognized lines and arrows reuse `CreationSnapping` and `ScheduledSnapCandidate` at the normal creation boundary. The initial pointer can provide only a provisional start marker; recognized geometric endpoints replace that basis before acquiring connections. Endpoint editing applies native anchor references without rebuilding the curve, decorations or paint. Unchanged geometry, active connection features and store revision reuse existing results, including a matching initial start lookup. Pending release uses the existing refinable Create and prepared replacement pipeline; Undo, a new gesture, changed ownership or invalid targets cancel stale work. The interaction contract remains canonical in [Editor Tools](../editor-tools.md#hold-to-shape).

## Verification Boundaries

Unit tests cover geometry, natural endpoint attachment orders, conservative rejection, normalization aliasing, native star behavior, settings compatibility, and the portable hold lifecycle. Integration tests exercise actual recognition through preview, native snapping, target-movement propagation, renderer, history, release, and cancellation. Deterministic work tests observe input reads, snapshot creation, the single original-path fidelity pass, closed candidate fits, actual arrowhead and pentagram segment-distance calculations, indexed snap visits and timer/job cleanup; simulated time controls deadlines only and establishes no execution-speed claim.

Maintain at least ten distinct imperfect development gestures for each of the nine supported recognition kinds, with separately authored frozen evaluation gestures and negative inputs. Include start positions, direction changes, short gaps, overlaps, uneven sampling, asymmetric corners, rounded turns, side waves, curved shafts, independent arrowheads and retraced wings with small gaps. These are regression data for geometric fitting, not examples training an ML or $Q model. Captured, metadata-free pen positions supplement synthetic gestures. Adjudicate geometrically overlapping labels independently; an explicitly sheared diamond can also fit a native parallelogram. Once an evaluation failure informs a fix, retain it as a regression and freeze fresh examples before claiming another blind verification. Synthetic results do not establish accuracy across people or physical stylus devices.

Native acceptance uses the production plugin in the dedicated Obsidian QA vault on an isolated virtual display. Draw visibly irregular self-generated examples through the actual pointer surface, including broad waves, unequal corners and heads, overshoot, small gaps, nonuniform sample spacing and pauses. Freeze development and separate evaluation sets before tuning, retain intended labels and distinguish failed positive attempts from intentional negative inputs. Demonstrate rejected ink, continuing after a hold, repeated holding and actual target movement after connection acquisition across desktop, tablet, and phone modes. These examples are synthetic and do not establish multi-person accuracy. Physical low-end-device latency and stylus-driver behavior remain separate hardware evidence.
