# Snapshot-Authoritative Unlock and Output Reuse

Status: Accepted; supersedes full-document canonical geometry reconstruction and prepared-path transfer as part of unlock.

## Context

Unlock previously reconstructed every canonical path to prove that editable metadata and supplied static SVG agreed. Pressure-heavy documents paid for full-document contours before the visible scene could mount. A bounded cross-session path cache avoided this only for unchanged files and transferred additional geometry that the receiver validated again.

## Decision

Editable metadata is authoritative after bounded schema, root revision, original metadata-byte SHA-256, derived bounds, and input-limit validation. Unlock permits safe JSON formatting differences and does not reserialize the complete snapshot to compare canonical metadata spelling. Strict output verification retains canonical metadata comparison. Unlock validates the complete supplied SVG presentation against the safe envelope without reconstructing canonical geometry. The streaming suffix validator uses the same path grammar, paint, group, command, and aggregate limits as preview validation. It retains at most one incomplete tag, capped at the existing 16 MiB path-data maximum plus 4 KiB of attribute allowance, and checkpoints long path validation. It does not join or retain a complete SVG string.

Unlock does not build or transfer full-document prepared paths. After validated model hydration, the active scene may request canonical paths for currently visible stroke IDs from the document worker and adopt complete bounded batches under scene ownership. Pressure-enabled strokes receive filled contours; constant-width strokes receive stroked centerlines. Both use the same preparation, transport, version checks, and bounded cache. The worker and main-thread fallback share `CanonicalElementPathPreparation`; the central `WorkScheduler` controls cooperative handoffs, including the progressive local fallback for either stroke type. Shapes retain local preparation. This scene path derives only from the validated model, never from supplied SVG markup, and does not make model publication depend on offscreen export geometry. Input cancellation and terminal validation still prevent publication of an incomplete document. The owned worker handoff checks operation identity, element counts, ordering, and detached Store adoption; it does not serialize every point again on both sides to produce and compare a redundant unlock transport hash. Persisted export integrity manifests remain unchanged.

A safe external presentation may differ from the metadata. Locked preview shows that supplied presentation; unlocking shows the validated snapshot. A later edit and save replaces external presentation changes with canonical output. Unlock alone does not force a rewrite merely because the safe presentation might differ. Unsafe markup, invalid model data, incorrect hashes, and limits remain failures. This deliberately removes static/model equality as an editable-input acceptance condition; it does not relax canonical output verification.

Locked preview inspection may retain a private scalar proof of the safe-static scan, bound to the complete byte count and SHA-256. Unlock obtains a candidate only from the current lifecycle-owned recognition entry and reads the file bytes afresh. The host checks authentic ownership and byte capacity without hashing the complete file. The worker, or the bounded main-thread fallback when no worker is available, binds the candidate to the complete fresh input under the central scheduler before parsing. A candidate miss takes the normal safe-static scan; it does not invalidate an otherwise valid changed file or force executor recovery. The fallback consumes an authentic candidate directly; the real worker receives only its scalar fields through the internal protocol and reconstructs worker-owned evidence. Either executor may omit only the repeated safe-static scan after a complete hash match. The parser retains its own complete input hash and terminal proof check, so candidate reuse currently performs two hash passes inside the executor. A later mismatch fails closed. Metadata and root integrity, schema, migration, geometry, aggregate and size limits, stale identities, and cancellation remain required. Strict canonical output verification does not consume this proof. This proof is not a canonical-output proof and retains no SVG or DOM.

## Persisted-Output Verification

The executor separately retains two scalar proof slots for completely verified canonical input and its latest successful canonical export. Safe unlock does not populate either canonical proof slot. Complete strict output verification may seed or advance the input slot; the export slot is populated only after canonical serialization. Neither slot retains complete output or accepts proof supplied by a file. Autosave may separately supply its host-owned confirmed persisted base for the current preflight request; this does not seed either canonical proof slot.

Autosave preflight separately owns its confirmed persisted base. It passes that scalar base and the freshly read content to the existing executor. The executor enforces the exact expected UTF-8 byte count and complete hash, then compares the canonical revision and hash with the base. An exact match reuses the confirmed base, including a source accepted by safe unlock, without another safe-SVG scan or geometry reconstruction. Changed bytes retain strict verification; a hash mismatch adds one preliminary hash pass. No SVG or geometry is retained by this shortcut. The bundled worker channel binds the answer to the exact request operation; the bridge checks identity, root revision, and hash spelling without another complete main-thread hash or presentation scan.

Verification hashes newly read bytes under input limits and cancellation checkpoints. An exact canonical proof match returns the proven revision; a miss performs complete canonical validation. Initialization, clear, and executor replacement invalidate ownership, and epoch checks prevent suspended work from repopulating cleared slots. Host reads, operation identities, conflict checks, writes, and read-back confirmation remain required.

The bundled worker and fallback canonical serializer are internal producers, not external SVG inputs. Receiver adoption checks operation identity, exclusive transferable ownership, byte capacity, fatal UTF-8 decoding, and the bounded canonical root. Export revision and snapshot digest remain bound to the model integrity manifest. Adoption and the internal save entry points do not repeat full SVG allowlist scans or output hashing. The serializer enforces UTF-8 byte capacity for its string fallback; receiver string checks add a cheap length guard. This trusts serializer correctness and browser transport instead of attempting to detect arbitrary internal code defects with repeated production validation.

Actual Vault reads remain external boundaries. Verification-specific reads may defer exact UTF-8 size checking to the executor, while ordinary reads retain the strict adapter check. A candidate is not a verified-read proof. Exact read-back comparison covers every persisted character against the owned output and binds the stable host size to the serializer's actual UTF-8 byte count; differing content takes the strict verification path. Only successful verification with a still-current host identity can promote a candidate to a verified read. Preflight and the atomic write callback retain external-change conflict checks, and stale revisions cannot be written. A stale read is a file conflict, not an executor failure. No additional output cache or lifetime is introduced. Workspace own-write event suppression and recognition reuse the actual verified readback only while its host-owned file identity, stats, and modification epoch remain current. Missing or stale proofs require a bounded fresh read and complete hash; an unknown identity enters ordinary external-change handling. See the [host persistence contract](../obsidian-integration.md#vault-file-and-link-apis).

An own-export hit trusts the successful canonical serializer. It removes independent second production geometry reconstruction as a way to detect serializer defects. Canonical output parity and regression tests protect that boundary; exact hashing proves that persisted bytes equal the known output.

## Verification Boundaries

Regression coverage must distinguish model unlock from visible scene contour preparation, accept safe divergent presentation only for unlock, and reject unsafe suffixes, invalid metadata, exceeded limits, and cancellation. Strict verification must reject the same divergent presentation even after successful unlock. Work/resource coverage retains the full representative document and checks batching, visible scene preparation, retained resources, proof replacement, and strict fallback.

These contracts do not establish a latency guarantee or parity with another plugin. Schema and safe-presentation scans, full-file hashing, visible pressure geometry, DOM attachment, and browser painting still have real costs. Physical-device latency remains a separate acceptance requirement.
